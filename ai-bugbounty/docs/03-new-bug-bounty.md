# 03. New Bug Bounty — AI를 붙이면

> 정적 분석을 AI에게 넘기면.
> 목표 — 수작업을 AI 파이프라인으로 전환한다. '찾기'에서 '자동으로 찾게 하기'로 관점을 옮긴다.

이 파트에서 배우는 것: ① AI로 코드를 읽고 추적하는 법 ② 모델·에이전트·도구를 고른다 ③ 심각도·보상·임팩트를 판단한다.

---

## AI와 함께하는 버그 헌팅

Old와 같은 4단계(정찰 → 분석 → 검증 → 제출)에 AI를 투입한다.

| 단계 | AI가 하는 일 |
|---|---|
| 정찰 Recon | 스코프 문서 요약, 서브도메인 자동 수집, 엔드포인트 우선순위, 의심 지점 후보 제시 |
| 분석 Analysis | 디컴파일 코드 요약, 취약 함수 후보 지목, 인증·권한 로직 해석, 유사 CVE 패턴 매칭 |
| 검증 Validation | 퍼징 시나리오 생성, PoC 초안 자동 작성, 크래시 로그 분류, 오탐 1차 필터링 |
| 제출 Report | 재현 절차 정리, CVSS 초안 산정, 리포트 문장 다듬기, 중복 여부 사전 검색 |

**가장 크게 줄어드는 구간 — 정적 분석.** 수천 줄 디컴파일 결과를 AI가 먼저 요약해 주고, 취약 가능성 높은 함수부터 짚어 헛수고를 줄이며, 아낀 시간을 재현과 PoC 작성에 몰아준다.

### 수작업 vs AI 활용

| 구분 | AI 없이 (수작업) | AI 활용 | 체감 차이 |
|---|---|---|---|
| 정찰·범위 파악 | 도구 실행 후 수동 정리 | 수집·우선순위 자동화 | 착수 속도 향상 |
| 정적 분석 | 수천 줄 직접 독해 | AI 요약 후 집중 분석 | **시간 대폭 감소** |
| 검증·PoC | 오탐까지 전부 재현 | 초안 생성 + 오탐 필터 | 재현 부담 감소 |
| 리포트 제출 | 절차·영향도 직접 작성 | 초안 생성 후 검토 | 제출까지 단축 |

가장 큰 차이는 정적 분석에 쓰던 시간. 코드를 읽는 시간이 줄면, 그만큼 검증과 제출에 시간을 쓸 수 있다.

## AI는 코드를 어떻게 읽는가 — 이해가 아니라 확률적 패턴 매칭

모델은 토큰 단위로 다음에 올 가장 그럴듯한 것을 고른다. 그래서 흔한 취약 패턴은 잘 잡지만 드문 로직은 놓친다. **직접 실행하지 않으므로 도달 가능성은 판단하지 못한다.**

- 토큰화(코드도 텍스트로 잘림) · 패턴 매칭(학습된 취약 코드와의 유사도) · 추론(단계별 사고로 경로 연결) · 한계(실행 결과는 알지 못함)
- **잘하는 일**: 전형적인 CWE 패턴 식별과 대량 코드 요약
- **못하는 일**: 런타임 상태에 의존하는 도달 가능성 판단
- **보완 방법**: 정적 분석기와 퍼저의 실제 실행 결과를 함께 물려 줌

### 입력에서 위험 함수까지 AI로 추적 (Taint Flow)

신뢰할 수 없는 입력 지점을 먼저 목록화하고, 입력과 위험 함수 사이 경로를 AI가 정리하고, 검증이 빠진 구간만 사람이 확인한다.

```
입력 표면 목록화 → 위험 함수 지정 → 경로와 조건 요약 → 검증 누락 지점 확인
```

```c
char *name = recv_field(req);      // SOURCE — 외부 입력 진입점
char query[256];
sprintf(query,                     // PROPAGATION — 값이 가공·전달
        "SELECT * WHERE u='%s'", name);
db_exec(query);                    // SINK — 위험하게 쓰이는 함수
```

> 질의 — "name이 db_exec까지 검증 없이 도달하나?"
> SQLi·명령 인젝션·경로 조작 모두 같은 **source→sink** 문제.

손으로 따라가던 것과 달라지는 점: 경로 정리 자동화(수백 줄 흐름을 요약해 후보 경로부터), 검증 누락 탐지(길이·범위 검사가 빠진 구간 짚음), **도달 여부는 사람**(실제로 닿는지는 직접 재현해 확인).

## MCP — 에이전트에 도구를 물리는 규약

**Model Context Protocol**은 모델과 외부 도구를 잇는 표준 인터페이스. Ghidra·Burp·Semgrep 같은 도구를 같은 방식으로 붙일 수 있고, 모델은 도구 목록을 보고 필요한 순간에 스스로 호출한다. AI를 손발 달린 분석가로 만드는 층.

- 서버(도구 기능을 노출하는 쪽) · 클라이언트(에이전트가 붙는 쪽) · 도구 정의(이름·인자·설명) · 권한(실행 가능한 범위 제한)

붙이기 전에 반드시 정해 둘 것: **실행 권한**(파일 쓰기·셸 실행은 컨테이너 안으로만) · **도구 개수**(너무 많이 붙이면 모델이 엉뚱한 도구를 고름) · **로그 보존**(어떤 도구를 어떤 인자로 호출했는지 전부 기록).

### AI에게 도구를 이렇게 물린다

```python
from mcp import tool

@tool()
def decompile(addr: str) -> str:
    """주소의 함수를 디컴파일한다"""   # docstring이 AI의 사용 판단 근거
    fn = ghidra.get_function(addr)
    return fn.decompile()
```

도구를 잘 노출하는 법: ① 명확한 이름(`decompile`처럼 동사+대상) ② 타입 명시(인자·반환 타입 정확히) ③ 설명 필수(docstring) ④ 읽기·쓰기 분리(부작용 있는 도구는 따로 표시). **설명이 부실하면 AI가 엉뚱한 도구를 고른다.**

> 우리가 세팅한 IDA Pro MCP 연동은 [`setup/IDA-MCP-Kali-연동.md`](../setup/IDA-MCP-Kali-연동.md) 참고.

## 챗봇과 에이전트는 무엇이 다른가

| 구분 | 챗봇 방식 | 에이전트 방식 | 헌팅에서의 차이 |
|---|---|---|---|
| 입력 | 사람이 코드를 붙여 넣음 | 스스로 파일을 열어 읽음 | 다룰 수 있는 규모 |
| 도구 | 없음·답변만 생성 | MCP로 분석기를 직접 실행 | 실제 결과로 판단 |
| 반복 | 한 번 묻고 한 번 답함 | 계획·실행·관찰을 순환 | 실패를 스스로 교정 |
| 종료 | 사람이 판단해 멈춤 | 정지 조건까지 자동 진행 | 무인 운영이 가능 |

**차이는 모델이 아니라 구조에서 온다.** 같은 모델이라도 도구와 루프를 붙이는 순간 다룰 수 있는 코드의 양이 완전히 달라진다.

## 컨텍스트 한계를 다루는 네 가지 전략

| 전략 | 방법 |
|---|---|
| **Split 쪼개기** | 함수 단위로 분할, 호출 관계만 따로 전달, 헤더·주석 제거, 한 번에 한 모듈만 |
| **Rank 우선순위** | 입력 처리부 먼저, 외부 노출 함수 우선, 변경 이력 잦은 곳, 과거 CVE 인접 코드 |
| **Summary 요약 누적** | 분석 결과를 메모로 저장, 다음 턴엔 요약만 투입, 파일별 카드 유지, 중복 질문 차단 |
| **Retrieve 검색 결합** | 그래프 질의로 후보 추출, 필요한 조각만 조회, 임베딩 검색 병행, 전체 투입 금지 |

컨텍스트를 아낄수록 정확도가 올라간다: 노이즈 감소(관련 없는 코드가 섞일수록 환각도 늘어남), 비용 절감(절반 이하 토큰), 반복 가능(작게 나눠야 실패한 구간만 다시 돌림).

## AI가 틀리는 네 가지 방식 (Hallucination)

| 유형 | 증상 |
|---|---|
| **없는 것을 인용** | 존재하지 않는 함수명, 맞지 않는 파일:라인, 가짜 CVE 번호, 지어낸 API 시그니처 |
| **과잉 경고** | 안전한 코드도 취약 판정, 완화 기법 무시, 도달 불가 경로 보고, 심각도 과대 평가 |
| **조용한 누락** | 긴 파일 뒷부분 무시, 조건 분기 건너뜀, 간접 호출 추적 실패, 매크로 확장 미반영 |
| **그럴듯한 PoC** | 실행되지 않는 코드, 오프셋이 임의값, 환경 가정이 틀림, 재현 절차의 비약 |

**대응은 프롬프트가 아니라 절차로 한다**: 근거 강제(파일:라인 인용 없는 주장은 자동으로 버리는 규칙) · 교차 검증(정적 분석기 결과와 겹치는 후보만 남김) · 직접 재현(PoC는 반드시 내 환경에서 돌려 본 뒤에 인정).

### 오탐 갤러리 — AI가 '취약하다'고 한 것들, 왜 틀렸나

- "strcpy 발견 → 오버플로" — 길이가 상수로 검증된 안전한 호출
- "입력이 시스템 콜에 도달" — 실제로는 도달 불가능한 죽은 코드
- "경계 검사 없음" — 상위 호출자가 이미 검증한 경우

**오탐을 걸러내는 질문**: 이 경로가 실제로 호출되는가?(도달 가능성) / 입력 길이·값을 공격자가 제어하는가? / 상위·하위에서 이미 검증하지 않는가? / 재현되는 PoC가 실제로 나오는가?

> AI의 '취약' 판정은 가설일 뿐, 재현되기 전까지는 오탐으로 취급한다.

### AI를 붙였는데 실패하는 이유

1. 범위를 안 주고 전부 던진다 — 레포 전체를 넣으면 요약만 그럴듯하고 후보는 흐려짐.
2. 결과를 검증 없이 그대로 낸다 — 오탐 리포트 몇 건이면 플랫폼 신뢰도가 먼저 깎임.
3. 정지 조건 없이 루프를 돌린다 — 진척 없는 반복에 토큰만 소진.

**도구가 아니라 절차를 설계해야 한다.**

## 작업별 모델 선택 기준

| 작업 | 필요한 능력 | 적합한 모델 성격 | 비용 감각 |
|---|---|---|---|
| 대량 코드 선별 | 속도와 처리량 | 가볍고 빠른 모델 | 낮음·반복 호출 |
| 취약점 추론 | 긴 사고 사슬 | 추론 특화 상위 모델 | 높음·선별 후 투입 |
| PoC 작성 | 코드 생성 정확도 | 코딩에 강한 모델 | 중간·실패 시 재시도 |
| 리포트 초안 | 문장 구성력 | 범용 모델 | 낮음·1회 호출 |

**한 모델로 전부 하지 않는다.** 선별은 값싼 모델, 판단은 큰 모델로 나누면 같은 예산에서 탐색량이 몇 배로 늘어남.

## 심각도·보상·임팩트

### 심각도 등급과 보상 구조 (강의 시점 예시)

| 심각도 | 대표 사례 | CVSS 범위 | 일반적인 보상대 |
|---|---|---|---|
| Critical | RCE·인증 우회·계정 탈취 | 9.0–10.0 | $5,000–$50,000 |
| High | SQLi·SSRF·권한 상승 | 7.0–8.9 | $1,500–$8,000 |
| Medium | Stored XSS·IDOR | 4.0–6.9 | $300–$1,500 |
| Low | 정보 노출·CSRF | 0.1–3.9 | $50–$300 |

> **중복 제보는 0원이다.** 같은 결함이라도 먼저 접수된 한 건만 인정되므로, 탐색 속도가 곧 보상으로 이어짐.

### AI가 버그바운티에 끼친 영향 (실험 예시)

- **22** 확인된 0-day — GPT-5가 자율 탐색으로 찾아낸 신규 취약점 수
- **56** 유발한 크래시 — 같은 실험에서 트리거된 크래시 건수
- **3배** 추론을 켰을 때 — 성공률 7.7% → 22.0%로 상승
- 출처: CyberGym, OSS-Fuzz 431개 프로젝트 자율 탐색 실험

> 사람이 못 훑던 범위를 기계가 훑기 시작했다. 탐색량이 늘어난 만큼, 진짜인지 판단하는 몫이 사람에게 남음.

### 벤치마크 (2026년 7월 공개 스냅샷 예시)

| 순위 | 모델 | CyberGym 점수 | 한 줄 평 |
|---|---|---|---|
| 1 | Fugu Cyber | 86.9% | 공개 스냅샷 1위 |
| 2 | GPT-5.6 Sol | 84.5% | 범용 추론 강세 |
| 3 | Gemini 3.5 Flash Cyber | 83.2% | 속도·비용에 유리 |

### ExploitGym — 찾는 것과 뚫는 것은 다른 문제

- **898** 실제 취약점 태스크(실제 CVE·OSS-Fuzz 버그를 컨테이너로 재현) · **3** 대상 도메인(유저스페이스 프로그램, 크롬 V8 엔진, 리눅스 커널) · **PoV**에서 출발(크래시 입력 하나로 플래그를 읽는 익스플로잇까지 완성)
- 출처: ExploitGym, UC Berkeley RDI 외 (arXiv 2605.11086)
- 무엇을 어떤 조건에서 시키는가: 520 유저스페이스(FFmpeg·OpenSSL 등 C/C++), V8 브라우저 엔진(샌드박스 on/off로 난이도), KERNEL 리눅스 커널. 각 인스턴스는 ASLR·V8 샌드박스 등 완화 기법을 토글해 난이도 분리. **방어가 켜져 있어도 성공 사례는 남는다.**

**프론티어 모델은 어디까지 갔나 (2026년 8월 리더보드 예시)**: GPT-5.6 Sol 33.7%(전체 과제의 약 1/3에서 동작하는 익스플로잇 생성) · GPT-5.6 Terra 23.2% · Claude Mythos 5 17.5%. 리더보드는 몇 달 단위로 뒤집힘 — 숫자보다 '어디까지 자동화됐나'를 보는 게 중요. **3분의 1은 기계가, 나머지는 여전히 사람이.**

## 이 파트 (Day 1) 요약

1. 제도를 알아야 보상이 남는다 — Scope와 트리아지 흐름을 이해하면 헛수고가 줄어듦.
2. 계열을 알아야 찾을 곳이 보인다 — CWE 계열마다 의심 함수와 코드 패턴이 이미 정해져 있음.
3. **AI는 범위를 줄 때만 쓸모가 있다** — 범위·형식·근거·실패 허용을 넣은 프롬프트가 결과를 바꿈.
