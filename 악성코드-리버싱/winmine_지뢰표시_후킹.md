# 지뢰찾기(winmine) — "지뢰찾기 정보" 메뉴로 지뢰 전체 표시

교안 p109~116 (IAT & OEP, PlaySoundW). 실습자료 `Game/winmine.exe`. 목표: **폭탄 소리를 앵커로 지뢰 표시 로직을 찾고, "도움말 → 지뢰찾기 정보(About)" 메뉴를 눌렀을 때 보드의 지뢰가 전부 드러나게** 만들기. 오프라인 단일 게임이라 순수 리버싱 학습 대상이다.

## 대상 정보

| 항목 | 값 |
|---|---|
| ImageBase / EP | `0x1000000` / `0x1003E21` |
| 사운드 | `WINMM!PlaySoundW` (IAT `0x1001168`) |
| About 창 | `SHELL32!ShellAboutW` (IAT `0x10010A4`) |
| 보드 배열 | `0x1005340` (칸 1바이트, 행 stride `0x20`) |
| 보드 크기 | 폭 `[0x1005334]`, 높이 `[0x1005338]` (난이도별 런타임 설정) |
| 지뢰 그리기 | `0x1002EAB(x, y, tile)` — `ret 0xC`, 폭탄 타일 `0x4C` |
| 지뢰 비트 | 보드 셀의 `0x80` |

## 1. 분석 과정 — 함수·구조 찾아가기

주소는 처음부터 아는 게 아니라 아래 순서로 하나씩 파낸 것이다.

### (1) import로 두 진입점 잡기

우클릭 → **Search for → Intermodular calls**(또는 import 참조)로 관심 API 호출부를 찾는다.
- `WINMM!PlaySoundW` → `0x10038C8`, `0x10038E6`, `0x1003937` (사운드 재생부)
- `SHELL32!ShellAboutW` → `0x1003D6D` (단 1곳 = "지뢰찾기 정보" 핸들러)

### (2) 폭탄 소리를 앵커로 패배 경로 추적

지뢰 표시는 "졌을 때" 일어나고 그 순간 폭탄 소리도 난다. 그래서 **소리를 미끼로** 잡는다:
1. 사운드 함수(`0x10038D7`/`0x10038ED`)나 `PlaySoundW`에 BP
2. 지뢰 클릭 → 패배 순간 멈춤
3. **Call Stack**을 위로 타고 올라가며 "칸을 여는/게임을 끝내는" 함수들을 확인 → 여기서 보드 접근 코드가 보이기 시작한다.

### (3) 보드 구조 알아내기 (배열·stride·지뢰비트)

칸을 다루는 코드(예: 스텝 함수 `0x10035B7`)를 보면 셀 접근 패턴이 드러난다:

```asm
mov  eax, edi                       ; edi = y
shl  eax, 5                         ; y * 0x20  ← 행 stride = 0x20
mov  bl, byte ptr [eax+esi+0x1005340]  ; board[y][x],  esi = x
test bl, 0x40                       ; 0x40 = 덮인 칸(미개봉) 비트
```

- `shl eax,5` → 한 행이 `0x20`바이트 → **보드는 stride 0x20짜리 2D 배열, 베이스 `0x1005340`**.
- 칸 `(x,y)` 주소 = `y*0x20 + x + 0x1005340`.
- 지뢰 비트는 보드 초기화(지뢰 배치) 코드에서 `or byte ptr [...], 0x80` 으로 세팅되는 걸 보고 **`0x80` = 지뢰**임을 확인.

### (4) "지뢰 그리기" 원시동작 찾기 — 0x1002EAB & 폭탄타일 0x4C

폭탄소리에서 스택을 타고 올라가면 **StepXY 함수 `0x1003512`** 에 닿는다. 이건 클릭한 칸을 처리하는데, 그 칸이 지뢰(`0x80`)이면 이렇게 폭탄을 그린다:

```asm
0x1003529  test byte ptr [edx], 0x80    ; 이 칸이 지뢰?
...
0x1003588  push 0x4C                     ; 폭탄 타일 ID
0x100358A  push eax                      ; y
0x100358B  push esi                      ; x
0x100358C  call 0x1002EAB                ; 그 칸에 폭탄 그리기
```

`0x1002EAB(x, y, tile)`의 실제 동작(`ret 0xC`, 3인자 stdcall):

```asm
0x1002EAB  mov eax,[esp+8]              ; y
0x1002EAF  mov ecx,[esp+4]              ; x
0x1002EB7  shl eax,5                    ; y*0x20
0x1002EBA  lea eax,[eax+ecx+0x1005340]  ; &board[y][x]
0x1002EC1  mov dl,[eax]; and dl,0xE0; or dl,[esp+0x10]  ; 표시값 하위비트 = tile
0x1002ECB  mov [eax],dl
0x1002ECD  call 0x1002646               ; 화면 갱신
0x1002ED2  ret 0xC
```

→ **지뢰 하나 드러내기 = `0x1002EAB(x, y, 0x4C)`.** 덮임 여부와 무관하게 강제로 폭탄을 그린다.

> ⚠️ 주의: 클릭용 함수 `0x100374F`는 `test al,0x40; jne 끝`이라 **덮인 칸(미개봉 지뢰)을 건너뛴다.** 그래서 reveal에는 `0x100374F`가 아니라 위 `0x1002EAB`(강제 그리기)를 써야 한다.

### (5) 보드 크기 글로벌 찾기

같은 함수들이 루프/경계 검사에서 크기 글로벌과 비교한다:

```asm
cmp ebx, dword ptr [0x1005334]   ; ebx(x) <= 폭
cmp eax, dword ptr [0x1005338]   ; eax(y) <= 높이
```

→ **폭 `0x1005334`, 높이 `0x1005338`** (난이도에 따라 런타임에 채워짐).

### (6) 전용 reveal-all이 없음을 확인

게임의 패배 처리는 지뢰마다 `0x1002EAB(x,y,0x4C)`로 폭탄을 그리는 방식이다(무인자 "전체 표시" 단일 함수는 없음). 그래서 **게임과 똑같이** 보드를 스캔해 지뢰 칸마다 `0x1002EAB`로 그리는 루프를 케이브에 만든다(§3). 게임 자신의 스캔 로직(`0x1003545`~`0x100358C`: `test [..],0x80` → `push 0x4C; call 0x1002EAB`)을 그대로 베끼는 것이다.

### (7) About("지뢰찾기 정보") 핸들러 구조

`ShellAboutW` 유일 호출부(`0x1003D6D`)를 포함한 함수:

```asm
0x1003D52  call dword ptr [LoadIconW]
0x1003D58  push eax
0x1003D59  lea eax,[ebp-0x100] / push eax      ; 문자열 인자들
0x1003D60  lea eax,[ebp-0x200] / push eax
0x1003D67  push dword ptr [0x1005B24]
0x1003D6D  call dword ptr [ShellAboutW]        ; ★ 여기를 reveal 호출로 교체
0x1003D73  pop esi
0x1003D74  leave                               ; esp=ebp 로 스택 정리
0x1003D75  ret
```

`leave`가 `esp=ebp`로 되돌리므로, ShellAboutW 인자들이 남아도 자동 정리된다 → 이 자리 하나만 바꾸면 된다.

## 2. 요약 — 파낸 재료

| 항목 | 주소 | 어떻게 찾았나 |
|---|---|---|
| 보드 배열 | `0x1005340` | 셀 접근 `[y*0x20+x+0x1005340]` |
| 행 stride | `0x20` | `shl eax, 5` |
| 지뢰 비트 | `0x80` | 배치 코드 `or [..],0x80` |
| 폭 / 높이 | `0x1005334` / `0x1005338` | 경계 `cmp` |
| 지뢰 그리기 | `0x1002EAB(x,y,tile)` `ret 0xC` | StepXY(`0x1003512`)가 지뢰에 `tile=0x4C`로 호출 |
| 폭탄 타일 | `0x4C` | 지뢰 밟음 처리의 `push 0x4C` |
| About 핸들러 | `0x1003D6D` | ShellAboutW 유일 호출부 |

게임과 동일하게, 보드 전체(`1..폭`, `1..높이`)를 스캔해 **지뢰 비트(0x80) 칸마다 `0x1002EAB(x,y,0x4C)`로 폭탄을 그리는** 루프를 케이브에 만든다.

## 3. 코드 케이브에 reveal 루프 작성 (0x01004B00)

케이브는 `.text` 끝(코드가 `0x01004A56`에서 끝남) 뒤의 **0으로 채워진 실행가능 패딩**을 쓴다 — 교안 지정 `0x01004B00`. `Ctrl+G`로 `0x01004B00` 이동 후 스페이스바로 아래를 그대로 작성(주소·점프까지 계산 완료):

```asm
0x01004B00  pushad
0x01004B01  mov  esi, 1                          ; y = 1
0x01004B06  mov  edi, 1                          ; x = 1        (oy: 바깥루프 top)
0x01004B0B  mov  eax, esi                        ;              (ox: 안쪽루프 top)
0x01004B0D  shl  eax, 5                          ; y * 0x20
0x01004B10  mov  cl, byte ptr [eax+edi+0x1005340]; board[y][x]
0x01004B17  test cl, 0x80                        ; 지뢰 비트?
0x01004B1A  je   0x01004B25                      ; 지뢰 아니면 건너뜀
0x01004B1C  push 0x4C                            ; 폭탄 타일
0x01004B1E  push esi                             ; y
0x01004B1F  push edi                             ; x
0x01004B20  call 0x1002EAB                       ; 폭탄 그리기 (ret 0xC가 인자 정리)
0x01004B25  inc  edi                             ; (skip 지점)
0x01004B26  cmp  edi, dword ptr [0x1005334]      ; x <= 폭 ?
0x01004B2C  jle  0x01004B0B                       ; → ox
0x01004B2E  inc  esi
0x01004B2F  cmp  esi, dword ptr [0x1005338]      ; y <= 높이 ?
0x01004B35  jle  0x01004B06                       ; → oy
0x01004B37  popad
0x01004B38  ret                                  ; About 핸들러로 복귀
```

짧은 점프(`7E xx`, 2바이트)로 들어간다: `je 0x01004B25`, `jle 0x01004B0B`, `jle 0x01004B06` — 대상이 가까워 전부 rel8로 인코딩된다.

포인트:
- **지뢰 칸만** 그린다: `board[y][x] & 0x80`이면 `0x1002EAB(x,y,0x4C)`로 폭탄 그리기(게임의 패배 로직과 동일). 덮임 여부 무시하고 강제로 드러남.
- 좌표 **1부터** 시작. 0부터 하면 보드 테두리 침범.
- `0x1002EAB`가 `ret 0xC`라 push한 3개 인자를 스스로 정리 → 루프 내 스택 균형 OK.
- `pushad/popad`로 레지스터 보존.
- ImageBase `0x01000000` 기준: 보드 배열 `0x01005340`, 폭 `0x01005334`, 높이 `0x01005338`, 그리기 `0x01002EAB`.

## 4. "지뢰찾기 정보" 핸들러를 케이브 호출로 교체

`Ctrl+G` → `0x1003D6D` → 스페이스바:

```asm
0x01003D6D  call 0x01004B00      ; 기존 call dword ptr [ShellAboutW] 대체
```

바이트: `E8 8E 0D 00 00` + `90`(nop). 원래 `FF 15 ..`(6바이트) 자리를 `call rel`(5바이트)+nop로.

- **"Fill with NOP's" 체크** (원래 `call [ShellAboutW]` 6바이트 → `call rel` 5바이트 + nop 1).
- 앞서 push된 About 인자 4개는 남지만, 바로 뒤 `0x1003D74 leave`가 `esp=ebp`로 되돌려 **자동 정리**되므로 안전하다.
- 케이브가 `ret`으로 `0x1003D73`에 복귀 → `pop esi; leave; ret`로 정상 종료.

## 5. 검증

1. 게임 새로 시작(지뢰 배치됨).
2. **도움말 → 지뢰찾기 정보** 클릭.
3. About 창 대신 **보드가 전부 열리며 지뢰가 다 보이면 성공.**

## 6. 트러블슈팅 (실제로 겪은 것)

### ① 도움말 누르면 바로 튕김 — 간접호출 vs 직접호출

케이브의 `call 0x1002EAB`이 `FF 15 AB2E0001`(= `call dword ptr [0x1002EAB]`, **간접**)로 조립되면 크래시. `0x1002EAB`는 **IAT 슬롯이 아니라 함수 코드 자체**라, 그 자리 바이트를 주소로 잘못 읽어 쓰레기로 점프한다.

| 대상 | 문법 | 바이트 |
|---|---|---|
| IAT 슬롯 (예: IsDebuggerPresent) | `call dword ptr [슬롯]` (대괄호) | `FF 15 ..` |
| 내부 함수 (예: `0x1002EAB`) | `call 0x1002EAB` (대괄호 X) | `E8 ..` |

→ 케이브의 call은 **대괄호 없이** 입력해 `E8`(직접)로. 위치 판별: 그 call에 BP → `F7`로 들어가서 `0x1002EAB`의 `mov eax,[esp+8]`에 도달하면 정상.

> `F8`(Step Over)로 그 call을 밟으면 케이브 전체가 한 번에 돌아 거기서 죽는다. 케이브 내부를 보려면 About 호출부(`0x1003D6D`)에서 `F7`(Step Into)로 들어갈 것.

### ② 실행 중엔 되는데 "Patch file" 사본은 안 됨 — VirtualSize

케이브 `0x1004B00`은 `.text` 섹션의 **VirtualSize(`0x3A56`, VA `0x1004A56`) 밖**이다. 메모리엔 페이지 정렬로 매핑돼 디버깅 중엔 동작하지만, x32dbg가 파일로 저장할 때 그 자리를 섹션 밖으로 보고 **케이브 바이트를 파일에 안 쓴다** → 사본은 About이 빈(0) 케이브를 호출해 실패("케이브가 밀림").

**해결**: `.text`의 VirtualSize를 RawSize와 같게 키워 케이브를 섹션 안에 포함.
- 헥스에디터(HxD)로 파일 오프셋 **`0x1D8`** 의 4바이트 `56 3A 00 00`(0x3A56) → **`00 3C 00 00`(0x3C00)** 으로 수정
- **패치 전에** 파일 헤더를 먼저 고쳐야 patch-file이 케이브를 "섹션 안"으로 인식
- 순서: 원본 복사 → 오프셋 `0x1D8` 수정 → 그 파일을 x32dbg로 열어 케이브+About 패치 → Patch file → 사본 실행

> ⚠️ 참고: 이 winmine은 **ASLR 꺼짐(DYNAMIC_BASE off) + 재배치 테이블 없음**이라 항상 `0x1000000`에 로드된다. 그래서 절대주소(`0x1005340`, `0x1002EAB` 등)는 사본에서도 안 밀린다 — 문제는 오직 위 VirtualSize 매핑뿐. (ASLR이 켜진 대상이라면 절대주소가 다 어긋나므로 그땐 ASLR부터 꺼야 한다.)

## 배운 것

- **소리를 앵커로 로직 찾기**: 이벤트(폭탄 소리)에 BP → Call Stack 역추적으로 관련 코드 위치 특정. 정적으로 헤매지 않는 동적 분석의 정석.
- **없는 기능은 조합해서 만든다**: 전용 reveal-all이 없어도, 게임 자신의 지뢰 그리기(`0x1002EAB(x,y,0x4C)`)를 보드 전체 루프로 감싸 새 기능을 구성. (덮인 칸을 건너뛰는 `0x100374F`가 아니라 강제로 그리는 `0x1002EAB`를 써야 함.)
- **메뉴 핸들러 하이재킹**: 기존 메뉴(About)의 호출 하나를 내 코드로 바꿔 트리거로 사용. 스택 정리(`leave`)를 이용하면 인자 불균형도 흡수된다.
- 보드 내부 구조(배열 `0x1005340`, stride `0x20`, 크기 글로벌, 좌표 1-기반)를 파악하는 것이 조작의 전제.
- **직접호출 vs 간접호출**: 함수는 `call addr`(E8), IAT 슬롯은 `call [slot]`(FF15). 헷갈리면 크래시.
- **코드 케이브는 VirtualSize 안에 둬야 파일로 저장된다**: 섹션 VirtualSize 밖 패딩은 실행 중엔 되지만 patch-file에 안 실린다.
