## 계정 관리

### U-01 root 계정 원격 접속 제한 `상` 🔴 취약

**[현황]**
- 대상 서버에서는 Telnet이 비활성화 되어 있고, SSH 관련 "PermitRootLogin" 설정이 주석 처리되어 root 계정으로 직접 로그인이 가능한 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 "/etc/ssh/sshd_config" 설정 파일 내 "PermitRootLogin" 관련 주석 제거 및 값을 "no"로 설정하여 주시기 바랍니다.

### U-02 비밀번호 관리정책 설정 `상` 🔴 취약

**[현황]**
- "/etc/login.defs" 설정 파일 내 패스워드 최대사용기간(99999), 최소사용기간(0), 최소자릿수(5) 및 "/etc/pam.d/system-auth" 파일 내 "password" 설정 구문에 복잡도 값이 설정되어 있지 않은 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 최대사용기간(90), 최소사용기간(1), 최소자릿수(8 이상), "password" 설정 구문에 대/소문자, 숫자, 특수문자가 각각 1자리수씩 포함될 수 있도록 설정하여 주시기 바랍니다.

### U-03 계정 잠금 임계값 설정 `상` 🔴 취약

**[현황]**
- "/etc/pam.d/system-auth" 설정 파일 내 "auth" 및 "account" required 구문에 "pam_tally.so" 관련 모듈이 적용되어 있지 않은 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 "pam_tally.so" 모듈을 적용하는 경우 "auth" required 구문에 deny "10", unlocktime "1800" 이상으로 설정하시거나  "pam_tally2.so" 모듈을 적용하는 경우 "account" required 구문에 deny "10", unlocktime "1800" 이상으로 설정하여 주시기 바랍니다.
(*) 1. pam_tally.so 모듈 사용시
 auth required /lib/security/pam_tally.so deny=5 unlock_time=120 no_magic_root
 account required /lib/security/pam_tally.so no_magic_root reset
2. pam_tally2.so 모듈 사용시
 auth required /lib/security/pam_tally2.so no_magic_root reset
 account required /lib/security/pam_tally2.so deny=5 unlock_time=120 no_magic_root

### U-04 비밀번호 파일 보호 `상` 🟢 양호

**[현황]**
- "/etc/passwd" 설정 파일 내 shell 로그인이 가능한 모든 사용자(root, adiosl, mysql, cubrid) 계정 패스워드가 암호화로 설정되어 있는 상태입니다.

### U-05 root 이외의 UID가 '0' 금지 `상` 🟢 양호

**[현황]**
- "/etc/passwd" 설정 파일 내 shell 로그인이 가능한 사용자 계정 중 UID가 "0"인 계정이 "root"만 존재하는 상태입니다.,

### U-06 사용자 계정 su 기능 제한 `상` 🔴 취약

**[현황]**
- "/etc/pam.d/su" 파일 내 "su" 관련 구문이 주석으로 설정되어 있고 "/etc/group" 파일 내 "wheel" 그룹에 사용자가 추가되어 있지 않으며, "/bin/su" 파일 권한이 4755(-rwsr-xr-x), 소유그룹이 "root"로 설정되어 있는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 "su" 관련 구문의 주석 제거 후 "root" 권한이 필요한 사용자만 "/etc/gorup" 파일 내 "wheel" 그룹에 사용자 추가, "/bin/su" 파일 권한을 4750(-rwsr-x---), 소유 그룹을 "wheel"로 설정하여 주시기 바랍니다.

### U-07 불필요한 계정 제거 `하` 🟡 인터뷰

**[현황]**
- Default 계정(lp, uucp)이 "/sbin/nologin"으로 shell이 제한되어 있지만 로그인이 가능한 사용자 계정 중 "adiosl" 계정이 2017년 3월 23일에 생성 후 shell을 사용한 기록이 없는 상태입니다.
**[인터뷰]**
로그인이 가능한 일반 사용자 계정(cubrid)을 어떤 목적으로 사용하고 있는지 담당자 확인이 필요합니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 일반 사용자 계정 중 사용하고 있지 않거나 불필요하게 생성되어 있는 계정을 제거하여 주시기 바랍니다.

### U-08 관리자 그룹에 최소한의 계정 포함 `중` 🟢 양호

**[현황]**
- "/etc/group" 파일 내 "root" 그룹에 사용자가 설정되어 있지 않은 상태입니다.

### U-09 계정이 존재하지 않는 GID 금지 `하` 🟢 양호

**[현황]**
- "/etc/passwd" 파일에 shell을 사용하는 계정(root, adiosl, mysql, cubrid)에 대한 사용자 그룹이 모두 존재하는 상태입니다.

### U-10 동일한 UID 금지 `중` 🟢 양호

**[현황]**
- 전체 사용자 계정의 UID가 서로 다르게 설정되어 있는 상태입니다.

### U-11 사용자 Shell 점검 `하` 🔴 취약

**[현황]**
- 로그인이 불필요한 시스템 계정의 shell 상태가 "/sbin/nologin"으로 되어 있지만 로그인이 가능한 일반 사용자 계정 중 shell 명령어를 한번도 입력하지 않은 계정(adiosl)이 존재하는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 shell 명령어를 사용하지 않은 계정에 대해 추가 사용 또는 계정 유지를 하지 않으실 경우 제거하여 주시기 바랍니다.

### U-12 세션 종료 시간 설정 `하` 🔴 취약

**[현황]**
- "/etc/profile" 파일 내 "TMOUT" 값이 존재하지 않는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 "TMOUT" 값을 "600"으로 설정하여 주시기 바랍니다.

### U-13 안전한 비밀번호 암호화 알고리즘 사용 `중` 🟢 양호

**[현황]**
- 암호화 알고리즘이 "SHA512"로 설정되어 있는 상태입니다.

## 파일 및 디렉토리 관리

### U-14 root 홈, 패스 디렉터리 권한 및 패스 설정 `상` 🟢 양호

**[현황]**
- "/etc/profile" 파일 내 시스템 환경변수 경로 맨 앞 및 중간에 "."이 포함되어 있지 않은 상태입니다.

### U-15 파일 및 디렉터리 소유자 설정 `상` 🔴 취약

**[현황]**
- 로그인이 가능한 사용자 계정 중 "root" 홈 디렉터리(/root/commons-daemon/commons-daemon-1.1.0-src/) 하단에 소유자 및 그룹 소유자가 존재하지 않는 다수의 파일이 존재하는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 소유자 및 그룹 소유자가 존재하지 않는 다수의 파일을 제거하시거나 소유자 및 그룹을 지정하여 주시기 바랍니다.

### U-16 /etc/passwd 파일 소유자 및 권한 설정 `상` 🟢 양호

**[현황]**
- "/etc/passwd" 파일 소유자가 "root", 권한이 644(-rw-r--r--)로 설정되어 있는 상태입니다.

### U-17 시스템 시작 스크립트 권한 설정 `상` 🟢 양호

**[현황]**
- "/etc/rc.d/init.d" 디렉터리 내 모든 부팅 스크립트 파일의 소유자가 "root", 타사용자 쓰기 권한이 제거된 상태입니다.

### U-18 /etc/shadow 파일 소유자 및 권한 설정 `상` 🟢 양호

**[현황]**
- "/etc/shadow" 파일 소유자가 "root", 권한이 0(----------)으로 설정되어 있는 상태입니다.

### U-19 /etc/hosts 파일 소유자 및 권한 설정 `상` 🟢 양호

**[현황]**
- "/etc/hosts" 파일 소유자가 "root", 권한이 644(-rw-r--r--)로 설정되어 있는 상태입니다.

### U-20 /etc/(x)inetd.conf 파일 소유자 및 권한 설정 `상` 🟢 양호

**[현황]**
- "xinetd" 데몬이 구동중이지 않고 "/etc/xinetd.d" 디렉터리 내 "xinetd.conf" 파일이 존재하지 않는 상태입니다.

### U-21 /etc/(r)syslog.conf 파일 소유자 및 권한 설정 `상` 🔴 취약

**[현황]**
- "/etc/rsyslog.conf" 파일의 소유자가 "root" 지만, 권한이 644(-rw-r--r--)로 설정되어 있는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 파일 권한을 640(-rw-r-----)으로 설정하여 주시기 바랍니다.

### U-22 /etc/services 파일 소유자 및 권한 설정 `상` 🟢 양호

**[현황]**
- "/etc/services" 파일 소유자가 "root", 권한이 644(-rw-r--r--)로 설정되어 있는 상태입니다.

### U-23 SUID, SGID, Sticky bit 설정 파일 점검 `상` 🔴 취약

**[현황]**
- 시스템 설정 파일 중 일부 파일(unix_chkpwd, at, newgrp)에 SUID가 설정되어 있는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 일부 파일(unix_chkpwd, at, newgrp)에 부여된 SUID를 제거하시거나 영향도가 발생할 경우 타사용자가 권한을 제거하여 주시기 바랍니다.

### U-24 사용자, 시스템 환경변수 파일 소유자 및 권한 설정 `상` 🟢 양호

**[현황]**
- 로그인이 가능한 모든 사용자 계정(root, adiosl, mysql, cubrid)의 환경변수 파일의 소유자 및 그룹 소유자가 자기 자신으로 되어 있고 소유자만 쓰기권한이 부여되어 있는 상태입니다.

### U-25 world writable 파일 점검 `상` 🟡 인터뷰

**[현황]**
- 전체 디렉터리 및 파일을 확인한 결과 타사용자 쓰기 권한이 부여된 Kernel 관련 파일만 존재하는 상태입니다.
(*) 해당 Kernel 관련 파일은 실제 데이터가 아닌 데이터 자체를 규격화하는 것에 목적이 있어 서버를 재부팅할 경우 권한이 다시 원상복구됨
**[인터뷰]**
기본 설정된 파일 외 타사용자 쓰기 권한이 부여된 파일이 존재하여 어떤 목적으로 사용하고 있는지 담당자 확인이 필요합니다.

### U-26 /dev에 존재하지 않는 device 파일 점검 `상` 🟡 인터뷰

**[현황]**
- "/dev/.udev/db" 디렉터리 내 디바이스 정보가 보관된 다수의 파일 중 서버 운영상의 목적이 아닌 미사용 디바이스 파일이 존재하는 상태입니다.
**[인터뷰]**
- "/dev/.udev/db" 디렉터리 내 미사용 디바이스 파일이 존재하는지 담당자 확인이 필요합니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 서버 운영상의 목적이 아닌 미사용 디바이스 파일을 제거하여 주시기 바랍니다.

### U-27 $HOME/.rhosts, hosts.equiv 사용 금지 `상` 🟢 양호

**[현황]**
- "xinetd" 데몬이 구동중이지 않고 "/etx/xinetd.d" 디렉터리 내 "r-command(rlogin, rsh, rbash, rexec)" 파일이 존재하지 않으며, "/etc/hosts.equiv" 파일과 로그인이 가능한 사용자 계정 홈 디렉터리 내 ".rhosts" 파일이 존재하지 않는 상태입니다.

### U-28 접속 IP 및 포트 제한 `상` 🟡 인터뷰

**[현황]**
- "/etc/hosts.deny" 및 "/etc/hosts.allow" 파일에 접근을 차단하는 구문과 허용이 필요한 사용자가 설정되어 있지 않은 상태입니다.
**[인터뷰]**
- 서버 접근 통제가 접근제어 솔루션을 통해 구현되어 있거나 내부 방화벽으로 서버의 직접적인 접근을 차단하고 있는지 담당자 확인이 필요합니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 "/etc/hosts.deny" 파일 내 "ALL:ALL" 설정 후 "/etc/hosts.allow" 파일 내 접근이 필요한 사용자의 hostname 및 IP address를 추가하여 주시기 바랍니다.

### U-29 hosts.lpd 파일 소유자 및 권한 설정 `하` 🟢 양호

**[현황]**
- "/etc/hosts.lpd" 파일이 존재하지 않는 상태입니다.

### U-30 UMASK 설정 관리 `중` 🔴 취약

**[현황]**
- "/etc/profile" 파일 내 "UID"가 "199"를 초과하는 계정에 대해 UMASK 값이 "002"로 설정되어 있는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어  "/etc/profile" 파일 내 UMASK 구문 바로 하단에 "umask 022" 값을 추가하여 주시기 바랍니다.

### U-31 홈 디렉토리 소유자 및 권한 설정 `중` 🔴 취약

**[현황]**
- 로그인이 가능한 계정 중 "mysql" 홈 디렉터리(/var/lib/mysql)에 755(drwxr-xr-x)로 권한이 부여되어 있어 "/var/lib/mysql/mysql.sock" 파일이 손상될 가능성이 존재하는 상태입니다.
**[대응방안]**
주요정보통신기반시설 가이드를 참고하시어 "mysql" 홈 디렉터리(/var/lib/mysql) 권한을 750(drwxr-x---)으로 설정하여 주시기 바랍니다.

### U-32 홈 디렉토리로 지정한 디렉토리의 존재 관리 `중` 🟢 양호

**[현황]**
- 로그인이 가능한 모든 사용자 계정의 홈 디렉터리가 존재하는 상태입니다.

### U-33 숨겨진 파일 및 디렉토리 검색 및 제거 `하` 🟡 인터뷰

**[현황]**
