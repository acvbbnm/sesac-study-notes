## 3. 취약 항목 상세 (현황 / 대응방안)

### U-01 (상) root 계정 원격 접속 제한 — 🔴 취약
- **[현황]** Telnet은 비활성화되어 있으나, SSH의 `PermitRootLogin` 설정이 **주석 처리**되어 root 계정 직접 로그인이 가능한 상태
- **[대응방안]** `/etc/ssh/sshd_config` 내 `PermitRootLogin` 주석 제거 후 값을 `no`로 설정

> 💡 주석 처리 = 기본값 적용. OpenSSH 구버전 기본값이 `yes`이므로 **"설정이 없다 = 양호"가 아니라 "취약"**으로 판정한다.

### U-02 (상) 비밀번호 관리정책 설정 — 🔴 취약
- **[현황]** `/etc/login.defs` 최대사용기간 **99999**, 최소사용기간 **0**, 최소자릿수 **5** / `/etc/pam.d/system-auth` 의 `password` 구문에 복잡도 값 미설정
- **[대응방안]** 최대사용기간 **90**, 최소사용기간 **1**, 최소자릿수 **8 이상**, `password` 구문에 대문자·소문자·숫자·특수문자 각 1자리 이상 포함하도록 설정

### U-03 (상) 계정 잠금 임계값 설정 — 🔴 취약
- **[현황]** `/etc/pam.d/system-auth` 의 `auth`·`account` required 구문에 `pam_tally.so` 모듈 미적용
- **[대응방안]**
  - `pam_tally.so` 적용 시 → `auth` required 구문에 `deny=10`, `unlock_time=1800` 이상
  - `pam_tally2.so` 적용 시 → `account` required 구문에 `deny=10`, `unlock_time=1800` 이상

### U-06 (상) 사용자 계정 su 기능 제한 — 🔴 취약
- **[현황]** `/etc/pam.d/su` 내 su 관련 구문이 **주석 처리**, `/etc/group` 의 `wheel` 그룹에 사용자 미등록, `/bin/su` 권한 **4755(-rwsr-xr-x)** / 소유 그룹 `root`
- **[대응방안]** su 구문 주석 제거 → root 권한이 필요한 사용자만 `wheel` 그룹에 추가 → `/bin/su` 권한 **4750(-rwsr-x---)**, 소유 그룹 **wheel** 로 변경

> 💡 3가지(PAM 설정 + wheel 그룹 + 파일 권한/그룹)가 **모두** 충족돼야 양호. 하나라도 빠지면 일반 사용자가 su 시도 가능.

### U-11 (하) 사용자 Shell 점검 — 🔴 취약
- **[현황]** 시스템 계정은 `/sbin/nologin` 처리되어 있으나, 로그인 가능한 일반 사용자 중 **shell 명령어를 한 번도 사용하지 않은 계정(adiosl)** 존재
- **[대응방안]** 미사용 계정은 추가 사용 계획이 없으면 삭제

### U-12 (하) 세션 종료 시간 설정 — 🔴 취약
- **[현황]** `/etc/profile` 내 `TMOUT` 값 없음
- **[대응방안]** `TMOUT=600` 설정 (10분 무입력 시 자동 로그아웃)

### U-15 (상) 파일 및 디렉터리 소유자 설정 — 🔴 취약
- **[현황]** root 홈 디렉터리 하위(`/root/commons-daemon/commons-daemon-1.1.0-src`)에 **소유자·그룹 소유자가 존재하지 않는 파일 다수**
- **[대응방안]** 해당 파일 제거 또는 소유자·그룹 지정

> 💡 소스 압축 해제 시 원본 시스템의 UID/GID가 그대로 남아 발생하는 전형적 케이스. `find / -nouser -o -nogroup` 으로 탐지.

### U-21 (상) /etc/(r)syslog.conf 파일 소유자 및 권한 설정 — 🔴 취약
- **[현황]** 소유자는 `root` 로 정상이나 권한이 **644(-rw-r--r--)**
- **[대응방안]** 권한을 **640(-rw-r-----)** 으로 설정

> 💡 소유자·권한 **둘 다** 기준을 만족해야 양호. 한쪽만 맞으면 취약.

### U-23 (상) SUID, SGID, Sticky bit 설정 파일 점검 — 🔴 취약
- **[현황]** 시스템 설정 파일 중 일부(`unix_chkpwd`, `at`, `newgrp`)에 SUID 설정
- **[대응방안]** 해당 파일의 SUID 제거 또는 타사용자 실행 권한 제거

## 4. 인터뷰 항목

### U-07 (하) 불필요한 계정 제거 — 🟡 인터뷰
- **[현황]** Default 계정(`lp`, `uucp`)은 `/sbin/nologin` 으로 shell 제한되어 있으나, **목적이 확인되지 않는 로그인 가능 일반 계정(adiosl, cubrid)** 존재
- **[인터뷰]** 해당 계정의 사용 목적을 담당자에게 확인 필요
- **[대응방안]** 미사용·불필요하게 생성된 계정 제거

> 💡 계정의 "필요 여부"는 스캐너로 판단 불가 → **인터뷰 판정의 대표 사례**. 현황(사실) / 인터뷰(질문) / 대응방안(조치)을 분리해서 기재한다.

## 5. 양호 항목 판정 근거 (U-01~U-25 중 15개)

| 코드 | 항목 | 판정 근거 |
|------|------|----------|
| U-04 | 비밀번호 파일 보호 | shell 로그인 가능 계정(root, adiosl, mysql, cubrid) 비밀번호 모두 암호화(`x`, shadow 분리) |
| U-05 | root 이외의 UID 0 금지 | UID `0` 계정이 `root` 뿐 |
| U-08 | 관리자 그룹 최소 계정 | `/etc/group` 의 `root` 그룹에 추가 사용자 없음 |
| U-09 | 계정 없는 GID 금지 | shell 사용 계정의 그룹이 모두 존재 |
| U-10 | 동일 UID 금지 | 전체 계정 UID 중복 없음 |
| U-13 | 안전한 비밀번호 암호화 알고리즘 | 알고리즘 `SHA-512` |
| U-14 | root 홈·PATH 디렉터리 설정 | `/etc/profile` PATH 맨 앞·중간에 `.` 미포함 |
| U-16 | /etc/passwd 소유자·권한 | root / 644 |
| U-17 | 시스템 시작 스크립트 권한 | `/etc/rc.d/init.d` 전체 root 소유, 타사용자 쓰기 권한 없음 |
| U-18 | /etc/shadow 소유자·권한 | root / **000(---------)** |
| U-19 | /etc/hosts 소유자·권한 | root / 644 |
| U-20 | /etc/(x)inetd.conf 소유자·권한 | `xinetd` 미구동, `xinetd.conf` 파일 부재 |
| U-22 | /etc/services 소유자·권한 | root / 644 |
| U-24 | 환경변수 파일 소유자·권한 | 각 계정 환경변수 파일 소유자·그룹이 자기 자신, 소유자만 쓰기 |
| U-25 | world writable 파일 | 타사용자 쓰기 권한 파일은 Kernel(`/proc`, `/sys`) 관련 파일뿐 |

> 💡 **U-25 예외 처리**: `/proc`, `/sys` 등 커널 가상 파일시스템은 실제 데이터가 아닌 규격화된 인터페이스이며 재부팅 시 권한이 원복되므로 **양호로 판정하고 각주(\*)로 사유를 명시**한다.  
> 💡 **권한 기준 차이 주의**: `/etc/passwd`·`/etc/hosts`·`/etc/services` 는 644 허용(양호)이지만, `/etc/rsyslog.conf` 는 640 이하여야 양호(U-21). 항목마다 기준이 다르므로 가이드 확인 필수.

## 7. 작성하면서 정리한 문구 패턴

결과보고서는 문체가 정형화되어 있어 아래 패턴을 그대로 재사용하면 빠르게 작성 가능.

```
[현황]
- "<설정 파일 경로>" 파일 내 "<설정 항목>" 값이 <실제값>으로 설정되어 있는 상태입니다.
  → 양호: "~로 설정되어 있는 상태입니다."
  → 취약: "~ 설정되어 있지 않은 상태입니다." / "~ 주석으로 설정되어 있는 상태입니다."

[인터뷰]
- <확인이 필요한 사항>에 대해 담당자 확인이 필요합니다.

[대응방안]
주요정보통신기반시설 가이드를 참고하시어 "<파일 경로>" 내 <설정 항목>을 <권고값>으로
설정하여 주시기 바랍니다.
```

### 작성 체크포인트
- **현황은 사실만, 판단은 결과 컬럼에** — 현황에 "취약합니다" 같은 판단 문구를 쓰지 않는다
- **경로·설정값·계정명은 실제 값 그대로** 인용 (오탈자 시 재현·검증 불가)
- **취약 판정 = 대응방안 필수 작성**, 양호 판정은 대응방안 생략
- **복합 조건 항목 주의** — U-06(su)처럼 조건 3개가 AND인 항목은 하나만 미충족이어도 취약
- **인터뷰는 3단 구성** — [현황](확인된 사실) / [인터뷰](담당자 질문) / [대응방안](조치)

### 제출 전 교정 확인 (이번 작성분 오탈자)
| 위치 | 오기 | 정정 |
|------|------|------|
| U-06 | `whell` 그룹 | **`wheel`** 그룹 |
| U-06 | "사용자마나" | "사용자만" |
| U-07 | `curbrid` | **`cubrid`** |
| U-03 | `acoount` required | **`account`** required |
| U-21 | `644(-rw-r-r--)` | `644(-rw-r--r--)` |

> 계정명·그룹명·권한 표기는 고객사에 그대로 전달되는 내용이므로 제출 전 반드시 교정한다.
