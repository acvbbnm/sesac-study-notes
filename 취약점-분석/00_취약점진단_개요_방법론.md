# 00. 취약점 진단 개요 & 방법론

> 교안: 시스템 취약점 분석 실무 과정 교안 (2026)  
> 참조: 주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드 (KISA, 2026)

---

## 1. 취약점 진단 vs 모의해킹

| 구분 | 취약점 진단 | 모의해킹 |
|------|------------|----------|
| **정의** | IT 운영환경 취약점 진단 및 보호대책 수립으로 정보보호 수준 향상 | 실제 해킹과 동일한 공격으로 실제적 보안 취약점 확인·제거 방안 제시 |
| **범위** | 웹·소스코드 진단, 서버 OS·DBMS·WEB·WAS·NETWORK·보안장비 진단 | 내/외부 시스템 모의해킹, APT 진단(내부 정보 유출) |
| **산출물** | 보호대책 및 개선과제 제시 | 진단 대상 및 개선과제 제시 |

---

## 2. 취약점 진단 방법론 (4단계)

```
① 사전협의 단계
   ├─ 프로젝트 요청 / 담당자 미팅 (유선·오프라인)
   ├─ 진단 기준 선정 (기반시설 / 금융취약점분석평가)
   ├─ 진단 대상 선정 (OS, Middleware 등)
   └─ 진단 기간 선정 (진단 수 대비 인력)

② 정보수집 단계
   ├─ 진단 정보 요청
   ├─ 보안 담당자 인터뷰
   └─ 시스템 담당자 인터뷰

③ 취약점 진단 단계
   ├─ 진단 수행
   ├─ 오픈 포트 분석
   ├─ 데몬 분석
   ├─ 계정 분석
   └─ 진단 대상 최종 FIX

④ 보고서 작성 및 프로젝트 종료 단계
   ├─ 결과 보고서 작성
   ├─ 결과 보고서 리뷰
   ├─ 산출물 제출
   ├─ 데이터 클렌징
   └─ 프로젝트 종료
```

## 3. 진단 대상별 항목 체계 (KISA 상세가이드 기준)

주요정보통신기반시설 기술적 취약점 분석·평가는 12개 대상으로 분류:

| 대상 | 주요 분류 |
|------|----------|
| **Unix 서버** | 계정 / 파일·디렉터리 / 서비스 / 패치 / 로그 관리 (U-01~U-67) |
| **Windows 서버** | 계정 / 서비스 / 패치 / 로그 / 보안 관리 (W-01~W-64) |
| **보안 장비** | 계정 / 접근 / 패치 / 로그 / 기능 관리 |
| **네트워크 장비** | - |
| **제어 시스템** | - |
| **PC** | 계정 / 접근 / 패치 / 보안 관리 |
| **DBMS** | 계정 관리 등 |
| **WEB (Apache 등)** | 계정 / 서비스 / 보안 설정 / 패치·로그 (WEB-01~WEB-26) |
| **클라우드** | 계정 / 권한 / 가상 리소스 / 운영 관리 |

**항목 중요도**: 상 / 중 / 하 3단계

> ※ 판단 기준은 권고 사항이며, 각 기반시설의 정책·운용 상황을 고려하여 진단 수행자가 최종 결정.  
> ※ 취약 판단을 받아도 합당한 보안 조치·근거가 있으면 양호로 판단 가능.
