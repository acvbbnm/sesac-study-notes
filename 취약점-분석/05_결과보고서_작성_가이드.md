# 05. 결과보고서 작성 가이드 (양식 기반)

> 양식: `SYSTEM진단 역량강화 - 환경분석_양식.docx`, `Linux,Apache,Windows 결과보고서_양식.xlsx`

---

## 1. 환경분석 보고서 양식 (docx)

진단 착수 전 대상 시스템 환경을 정리하는 문서.

### 구성
```
1. 대상 기본정보
   - OS       : Platform 명 & 버전
   - DBMS     : Platform 명 & 버전
   - Web server: Platform 명 & 버전
   - WAS      : Platform 명 & 버전

2. 포트 분석 (netstat -tlnp 결과 정리)
   Proto | Local Address | Well Known 여부 | Foreign Address | Program name | 비고

3. 데몬 분석 (ps -ef 결과 정리)
   RUSER | Daemon Name | 목적 | 비고

4. 계정 분석 (/etc/passwd 정리)
   Username | Info | Home directory | Command/shell | 비고
```

## 2. 취약점 결과보고서 양식 (xlsx)

3개 시트로 구성: **LINUX(67) / WEB 서비스(Apache)(26) / Windows(64)**

### 컬럼 구조

| 컬럼 | 내용 |
|------|------|
| 항목분류 | 계정 관리 / 파일·디렉터리 관리 / 서비스 관리 / ... |
| 코드 | U-01, W-01, WEB-01 등 |
| 항목명 | 점검항목 이름 |
| 중요도 | 상 / 중 / 하 |
| 결과 | 양호 / 취약 / 인터뷰 |
| 결과(상세) | [현황] + [대응방안] |

### 결과 판정 기준

| 판정 | 의미 |
|------|------|
| **양호** | 판단 기준 충족, 보안 설정 적용됨 |
| **취약** | 판단 기준 미충족, 조치 필요 |
| **인터뷰** | 자동 점검 불가, 담당자 인터뷰로 확인 |

### 상세 작성 예시 (U-01 취약 케이스)

```
[현황]
- 대상 서버에서 Telnet은 비활성화되어 있으나,
  SSH 설정의 "PermitRootLogin"이 주석 처리되어
  root 계정으로 직접 로그인이 가능한 상태임

[대응방안]
- 주요정보통신기반시설 가이드를 참고하여
  /etc/ssh/sshd_config 파일의 PermitRootLogin 값을 No로 설정
```

## 3. 보고서 작성 시 유의사항

- **현황은 근거 중심**: 실제 설정값·명령어 결과를 캡처/인용하여 판정 근거 명시
- **대응방안은 구체적으로**: KISA 상세가이드 조치 방법(파일 경로·설정값)을 인용
- **중요도 우선순위**: '상' 항목의 취약점부터 조치 계획 수립
- **인터뷰 항목 관리**: 자동 점검 불가 항목은 담당자 확인 후 근거 기록
- **정책 고려**: 취약 판정이어도 합당한 보완 통제·근거가 있으면 양호로 조정 가능 (수행자 최종 판단)

## 4. 진단 → 보고 연계 흐름

```
[환경분석]
 포트/데몬/계정 분석 → 환경분석 보고서(docx)
        │
        ▼
[항목별 진단]
 U/W/WEB 항목 점검 → 양호/취약/인터뷰 판정
        │
        ▼
[결과보고서(xlsx)]
 항목별 [현황] + [대응방안] 작성
        │
        ▼
[최종 보고]
 결과 리뷰 → 산출물 제출 → 데이터 클렌징 → 종료
```

## 6. 판정별 작성 예시 (3케이스)

**취약 케이스 (U-01 root 원격 접속)**
```
[결과] 취약
[현황]
- /etc/ssh/sshd_config 파일에서 PermitRootLogin 값이 "yes"로 설정되어 있어
  root 계정으로 SSH 직접 로그인이 가능한 상태임
  (근거: # grep PermitRootLogin /etc/ssh/sshd_config → PermitRootLogin yes)
[대응방안]
- /etc/ssh/sshd_config 파일의 PermitRootLogin 값을 No로 변경 후 sshd 재시작
  (systemctl restart sshd)
```

**양호 케이스 (U-02 비밀번호 정책)**
```
[결과] 양호
[현황]
- /etc/security/pwquality.conf에 minlen=8, 복잡도(dcredit/ucredit/lcredit/ocredit=-1)가
  설정되어 있어 비밀번호 관리 정책이 적용됨
[대응방안]
- 해당 없음 (현 설정 유지 권고)
```

**인터뷰 케이스 (U-64 보안 패치)**
```
[결과] 인터뷰
[현황]
- 폐쇄망 운영으로 자동 업데이트 미적용. 분기별 수동 패치 절차를 운영 중이라는
  시스템 담당자 인터뷰 확인 (최근 패치: 2026-06)
[대응방안]
- 정기 패치 주기 문서화 및 벤더 보안 권고 모니터링 체계 유지 권고
```

## 7. 작성 실무 팁

- **근거(evidence) 필수**: 현황에는 반드시 점검 명령어와 그 결과를 함께 기재 → 재현·검증 가능해야 함
- **취약 → 대응방안 1:1**: 취약 판정 항목은 반드시 대응방안을 작성. KISA 가이드의 조치 방법(파일 경로·설정값)을 그대로 인용하면 정확
- **조치 시 영향 명시**: 비밀번호 정책 변경이 Web/WAS/DB 연동에 영향을 줄 수 있는 것처럼, 조치가 운영에 미치는 영향을 함께 안내
- **중요도 순 정렬**: 보고서 요약에는 '상' 취약 항목을 상단 배치하여 우선 조치 유도
- **오탐 검증**: 벤더 룰·자동 스캐너 결과를 그대로 옮기지 말고 실제 설정을 확인하여 오탐 제거
- **일관된 용어**: 계정명·경로·설정값 등은 실제 시스템 값과 정확히 일치시킬 것
