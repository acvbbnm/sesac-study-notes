# 07. 계층별 로그 정리 (OS / DBMS / WebServer / WAS)

> 진단·침해분석·로그 관리 항목(U-65~67, W-40~43)의 실무 참조용.  
> 각 계층에서 어떤 로그가 어디에 쌓이는지, 무엇을 봐야 하는지 정리. (교안 보충)

---

## 0. 로그를 왜 보는가

| 목적 | 설명 |
|------|------|
| **침해 흔적 탐지** | 비정상 로그인, 권한 상승, 파일 변조 흔적 확인 |
| **진단 근거** | 로그 설정(U-66)·권한(U-67) 점검 및 정탐/오탐 판단 근거 |
| **사고 대응** | 침해사고 발생 시 공격 시점·경로·범위 추적(포렌식) |
| **책임 추적성** | "누가 언제 무엇을" 했는지 감사(Accountability) |

> 로그가 없거나 변조 가능하면 위 목적을 달성 못 함 → 로그 **설정(U-66)** 과 **접근 권한(U-67)** 이 진단 항목인 이유.

## 1. OS — Linux 로그

리눅스 로그는 대부분 `/var/log/` 아래에 위치. 텍스트 로그는 `cat/tail/grep`, 바이너리 로그는 전용 명령어로 확인.

| 로그 파일 | 내용 | 확인 명령어 | 보안 관점 |
|-----------|------|-------------|----------|
| `/var/log/messages` | 시스템 전반 메시지(커널·서비스) | `tail -f`, `grep` | 서비스 오류·비정상 이벤트 |
| `/var/log/secure` | 인증·권한 관련(로그인, su, sudo, sshd) | `grep sshd`, `grep sudo` | ⚠️ **로그인 실패·무차별 대입 탐지** |
| `/var/log/auth.log` | 인증 로그 (데비안·우분투 계열) | `grep` | secure와 동일 역할 |
| `/var/log/cron` | crontab 예약 작업 실행 이력 | `tail` | 비인가 예약 작업 탐지(U-37) |
| `/var/log/boot.log` | 부팅 시 서비스 시작 메시지 | `cat` | 서비스 정상 기동 여부 |
| `/var/log/dmesg` | 커널 링 버퍼(하드웨어·드라이버) | `dmesg` | 하드웨어 오류 |
| `/var/log/maillog` | 메일(Postfix/Sendmail) | `tail` | 스팸 릴레이 악용 탐지(U-47) |
| `/var/log/httpd/` | Apache 로그 (아래 3장 참조) | - | 웹 공격 분석 |

### 바이너리 로그 (전용 명령어 필요)

| 로그 파일 | 내용 | 확인 명령어 |
|-----------|------|-------------|
| `/var/log/wtmp` | 로그인·로그아웃·부팅 성공 기록 | `last` |
| `/var/log/btmp` | **로그인 실패** 기록 | `lastb` |
| `/var/run/utmp` | 현재 로그인 중인 사용자 | `who`, `w` |
| `/var/log/lastlog` | 계정별 마지막 로그인 시각 | `lastlog` |
| `/var/log/audit/audit.log` | auditd 감사 로그(상세 시스템콜) | `ausearch`, `aureport` |

### 침해분석 자주 쓰는 조회

```bash
# SSH 로그인 성공/실패
grep "Accepted"  /var/log/secure     # 성공
grep "Failed"    /var/log/secure     # 실패 (무차별 대입 흔적)
lastb | head                          # 로그인 실패 요약

# 특정 계정 로그인 이력
last <username>

# sudo/su 사용 이력
grep "sudo:"  /var/log/secure
grep "su:"    /var/log/secure

# 시각 순 이벤트 추적
grep "Jan 15" /var/log/messages
```

### 로그 관리 진단 연계
- **U-66 시스템 로깅 설정**: `/etc/rsyslog.conf`(또는 syslog.conf)에 로그 정책이 설정되어 있는지
- **U-67 로그 디렉터리 권한**: `/var/log` 및 하위 파일이 비인가자에게 노출·변조되지 않도록 소유자/권한 설정
- **U-65 시각 동기화**: NTP로 시간이 맞아야 로그 시각의 신뢰성 확보

## 2. OS — Windows 로그

Windows는 **이벤트 로그(Event Log)** 로 관리. `eventvwr.msc`(이벤트 뷰어) 또는 PowerShell로 확인.

| 로그 | 내용 | 보안 관점 |
|------|------|----------|
| **Security(보안)** | 로그온/로그오프, 권한 사용, 정책 변경, 개체 접근 | ⚠️ 침해분석 핵심. 로그온 성공/실패 |
| **System(시스템)** | 시스템 구성요소·드라이버·서비스 이벤트 | 서비스 시작/중지, 시스템 오류 |
| **Application(응용)** | 응용 프로그램 이벤트 | 앱 오류·크래시 |
| **Setup** | 설치/업데이트 이벤트 | 패치 적용 이력 |
| **Forwarded Events** | 다른 시스템에서 전달된 이벤트 | 중앙 수집 |

### 주요 보안 이벤트 ID

| Event ID | 의미 | 침해 관점 |
|:---:|------|----------|
| **4624** | 로그온 성공 | 로그온 유형·시각 확인 |
| **4625** | **로그온 실패** | ⚠️ 무차별 대입 공격 탐지 |
| 4634 / 4647 | 로그오프 | 세션 추적 |
| **4672** | 관리자 권한 로그온 | 권한 상승 감시 |
| 4720 / 4726 | 계정 생성 / 삭제 | ⚠️ 비인가 계정 생성 |
| 4732 | 보안 그룹에 멤버 추가 | ⚠️ 관리자 그룹 편입 |
| 1102 | **감사 로그 지워짐** | ⚠️ 흔적 삭제 시도 |
| 7045 | 새 서비스 설치 | ⚠️ 악성 서비스·백도어 |

### 조회 방법

```powershell
# 로그온 실패(4625) 최근 20건
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4625} -MaxEvents 20

# 이벤트 뷰어 GUI
eventvwr.msc

# wevtutil (CMD)
wevtutil qe Security /c:10 /rd:true /f:text
```

### 로그 관리 진단 연계
- **W-40 시스템 로깅 설정**: 감사 정책(Audit Policy) 구성 여부 (`secpol.msc`)
- **W-42 이벤트 로그 크기**: 로그가 덮어써져 손실되지 않도록 충분한 크기 설정
- **W-43 로그 접근 통제**: 이벤트 로그 파일 접근 권한 제한
- **W-41 시각 동기화**: NTP 설정

## 3. DBMS 로그

### MySQL / MariaDB

`my.cnf`(`/etc/my.cnf`)에서 각 로그를 활성화·경로 지정. 기본 데이터 디렉터리는 `/var/lib/mysql/`.

| 로그 | 내용 | 설정 | 보안 관점 |
|------|------|------|----------|
| **Error Log** | 기동/종료·오류·비정상 종료 | `log_error` | 서비스 오류, 크래시 |
| **General Query Log** | **모든 접속·쿼리** 기록 | `general_log=ON` | ⚠️ 전체 쿼리 감사(성능 부담 커서 상시 X) |
| **Slow Query Log** | 임계시간 초과 쿼리 | `slow_query_log=ON` | 비정상 대량 쿼리 탐지 |
| **Binary Log(binlog)** | 데이터 **변경**(INSERT/UPDATE/DELETE) | `log_bin` | ⚠️ 데이터 변조 추적·복구, 복제 |

```sql
-- 로그 설정 확인
SHOW VARIABLES LIKE 'log_error';
SHOW VARIABLES LIKE 'general_log%';
SHOW VARIABLES LIKE 'slow_query%';
SHOW VARIABLES LIKE 'log_bin';
```
```bash
# binlog 내용 조회 (바이너리 → 텍스트)
mysqlbinlog /var/lib/mysql/mysql-bin.000001
```

> ⚠️ 접속 계정·쿼리에 **평문 인증정보·개인정보**가 로그로 남을 수 있어 로그 파일 권한 관리 중요.

### Oracle

| 로그 | 내용 | 위치(예) |
|------|------|---------|
| **Alert Log** | 인스턴스 기동/종료·오류(ORA-)·구조 변경 | `$ORACLE_BASE/diag/rdbms/.../trace/alert_<SID>.log` |
| **Listener Log** | 리스너 접속 시도(클라이언트 IP·서비스) | `$ORACLE_BASE/diag/tnslsnr/.../listener/` |
| **Audit Trail** | 감사(로그인·권한·객체 접근) | `AUD$` 테이블 또는 `audit_file_dest` |

- **Listener Log**: 비인가 IP의 접속 시도·무차별 대입 탐지
- **Audit**: `AUDIT` 설정으로 로그인 성공/실패, 권한 사용 감사

### 기타 DBMS

| DBMS | 주요 로그 |
|------|----------|
| **PostgreSQL** | `pg_log/` (접속·쿼리·오류). `log_connections`, `log_statement` |
| **MS-SQL** | SQL Server Error Log, 감사(Audit), 프로파일러 |

### 로그 관리 관점
- **감사 로그 활성화**: 로그인 실패·권한 사용을 남기도록 감사 설정 (침해 추적 필수)
- **DB 로그 권한**: 로그 파일에 비인가 접근·변조 방지 권한 설정
- **민감정보 주의**: general log 등에 평문 데이터가 남을 수 있으므로 상시 활성화 지양·접근 통제

## 4. WebServer 로그


### Apache

기본 경로: `/var/log/httpd/`(RHEL) 또는 `/var/log/apache2/`(Debian). `httpd.conf`에서 경로·포맷 지정.

| 로그 | 내용 | 보안 관점 |
|------|------|----------|
| `access_log` | 모든 HTTP 요청(IP·시각·URL·상태코드·UA) | ⚠️ **웹 공격 분석 핵심** (SQLi, XSS, 스캔) |
| `error_log` | 서버 오류·경고 | 설정 오류·모듈 오류·공격 시도 흔적 |

**access_log 포맷(Combined)**
```
192.168.0.10 - - [15/Jan/2026:14:30:22 +0900] "GET /login.php?id=1' HTTP/1.1" 200 512 "-" "Mozilla/5.0"
   ①IP          ②시각                        ③요청(메서드/URL)          ④상태 ⑤크기      ⑥User-Agent
```

| 필드 | 침해분석 활용 |
|------|--------------|
| IP | 공격자 출발지 식별·차단 |
| 요청 URL | `'`, `<script>`, `../`, `union select` 등 공격 패턴 탐지 |
| 상태코드 | 200(성공)·403(차단)·404(스캔)·500(오류) 분포로 공격 판단 |
| User-Agent | sqlmap, nikto 등 공격 도구 시그니처 |

**공격 흔적 조회 예시**
```bash
# SQL Injection 시도 흔적
grep -iE "union|select|' or |0x" /var/log/httpd/access_log

# 디렉터리 트래버설
grep "\.\./" /var/log/httpd/access_log

# 404 다발 IP(스캐닝 의심)
awk '$9==404 {print $1}' access_log | sort | uniq -c | sort -rn | head

# 웹쉘 업로드 의심 (POST + 확장자)
grep "POST" access_log | grep -iE "\.php|\.jsp|\.asp"
```

### Nginx
경로: `/var/log/nginx/access.log`, `error.log`. 포맷·활용은 Apache와 동일.

### IIS (Windows)
경로: `C:\inetpub\logs\LogFiles\W3SVC1\`. W3C 포맷(`u_exYYMMDD.log`). `cs-uri-stem`(요청 URI), `sc-status`(상태코드), `c-ip`(클라이언트 IP) 필드로 분석.

### 로그 관리 진단 연계
- **WEB-26 로그 디렉터리·파일 권한**: 웹 로그가 비인가 접근·변조되지 않도록 권한 설정
- 로그에 **개인정보·인증정보**가 평문 기록되지 않도록 주의

## 5. WAS 로그

### Tomcat

경로: `<TOMCAT_HOME>/logs/`

| 로그 | 내용 | 보안 관점 |
|------|------|----------|
| `catalina.out` | 표준출력·에러 통합(앱 예외·스택트레이스) | ⚠️ 앱 오류로 경로·쿼리 노출 위험 |
| `catalina.<date>.log` | Tomcat 엔진 이벤트(기동/종료) | 서비스 상태 |
| `localhost_access_log.<date>.txt` | HTTP 접근 로그(Apache access_log와 유사) | 웹 공격 분석 |
| `manager.<date>.log` | Manager 앱(배포·관리) 접근 | ⚠️ 관리 콘솔 비인가 접근 |
| `host-manager.<date>.log` | Host Manager 접근 | 관리 콘솔 감시 |

```bash
# 앱 예외 실시간 확인
tail -f <TOMCAT_HOME>/logs/catalina.out

# 접근 로그에서 관리 콘솔 접근 시도
grep "/manager" localhost_access_log.*.txt
```

### 기타 WAS

| WAS | 주요 로그 | 경로(예) |
|-----|----------|---------|
| **JEUS** | JEUSMain.log, servlet 로그 | `<JEUS_HOME>/logs/` |
| **WebLogic** | AdminServer.log, access.log | `<DOMAIN>/servers/<name>/logs/` |
| **JBoss/WildFly** | server.log, boot.log | `<JBOSS>/standalone/log/` |

### 로그 관리 관점
- **관리 콘솔 로그 감시**: Manager·Admin 콘솔 접근 로그에서 비인가 IP·실패 시도 확인
- **스택트레이스 노출 주의**: `catalina.out`의 예외 메시지가 에러 페이지로 사용자에게 노출되면 정보 유출(WEB-22 에러 페이지 관리)
- **로그 권한**: WAS 로그도 비인가 접근·변조 방지 권한 설정 필요

## 6. 계층별 로그 한눈에 보기

| 계층 | 대표 로그 | 위치 | 핵심 용도 |
|------|----------|------|----------|
| **OS(Linux)** | secure, messages, wtmp/btmp | `/var/log/` | 로그인·인증·시스템 |
| **OS(Windows)** | Security 이벤트 로그 | 이벤트 뷰어 | 로그온·권한·감사 |
| **DBMS(MySQL)** | error/general/slow/binlog | `/var/lib/mysql/` 등 | 접속·쿼리·변경 |
| **DBMS(Oracle)** | alert log, listener.log, audit | `$ORACLE_BASE/diag/` | 인스턴스·리스너·감사 |
| **WebServer** | access_log, error_log | `/var/log/httpd/` 등 | HTTP 요청·웹 공격 |
| **WAS(Tomcat)** | catalina.out, access_log | `<TOMCAT>/logs/` | 앱 오류·관리 콘솔 |

> **침해분석 흐름**: WebServer access_log(공격 URL 확인) → WAS/DBMS 로그(실제 실행·쿼리 확인) → OS secure/Security(권한 상승·로그인 확인)로 **계층을 따라 내려가며** 공격 경로를 추적한다.
