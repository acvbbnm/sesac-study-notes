## 1. 패스워드 관련 문제

### 핵심 확인 명령
```bash
# 패스워드 사용기간·자릿수 정책
cat /etc/login.defs | grep -E "PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_MIN_LEN"
# 복잡도 정책 (RHEL 6~7)
cat /etc/pam.d/system-auth | grep -E "pam_cracklib|pam_pwquality"
cat /etc/security/pwquality.conf
# 암호화 알고리즘
cat /etc/login.defs | grep ENCRYPT_METHOD      # SHA512 여야 양호
authconfig --test | grep hashing
# shadow 사용 여부 (두 번째 필드가 x)
cat /etc/passwd
```

### 판단 기준 & 정답값

| 항목 | 확인 위치 | 🟢 양호 값 | 🔴 취약 값 |
|------|----------|-----------|-----------|
| **U-02** 관리정책 | /etc/login.defs | 최대 **90**, 최소 **1**, 최소자릿수 **8** | 99999 / 0 / 5 |
| **U-02** 복잡도 | pwquality.conf / system-auth | 대·소문자·숫자·특수문자 각 1자 이상 | 미설정 |
| **U-04** 파일 보호 | /etc/passwd, shadow | 비밀번호 암호화(shadow 사용, `x`) | 평문 저장 |
| **U-13** 알고리즘 | login.defs / system-auth | **SHA512** | MD5, DES |

### 조치 예시
```bash
# /etc/login.defs
PASS_MAX_DAYS 90
PASS_MIN_DAYS 1
PASS_MIN_LEN  8
# /etc/security/pwquality.conf (복잡도, 각 -1 = 최소 1자 요구)
minlen = 8
dcredit = -1   # 숫자
ucredit = -1   # 대문자
lcredit = -1   # 소문자
ocredit = -1   # 특수문자
```

### 💡 실전 (CentOS 6.9)
- **U-02 🔴 취약**: login.defs 최대사용기간 **99999**, 최소 **0**, 최소자릿수 **5**, system-auth 복잡도 미설정 → 90/1/8 + 복잡도 설정
- **U-04 🟢 양호**: root·adiosl·mysql·cubrid 모두 암호화 저장
- **U-13 🟢 양호**: SHA512 설정됨

> (상세 → [02. U-02/U-04/U-13](./02_Unix_진단항목_U01-U67.md))

## 2. 타사용자 쓰기 권한 문제

"others(타사용자)에 쓰기 권한이 있으면 취약"이 핵심. 파일 종류별 적정 권한을 외운다.

### 핵심 확인 명령
```bash
# world writable 파일 탐색 (others 쓰기 = 취약)
find / -type f -perm -2 -exec ls -al {} \;      # -2 = o+w
find / -type d -perm -2 2>/dev/null             # world writable 디렉터리
# SUID/SGID 파일 탐색
find / -perm -4000 -type f -exec ls -al {} \;   # SUID
find / -perm -2000 -type f -exec ls -al {} \;   # SGID
# UMASK 확인
cat /etc/profile | grep -i umask
umask
```

### 파일별 적정 권한 (암기)

| 파일 | 적정 권한 | 소유자 | 항목 |
|------|:--------:|:------:|:----:|
| /etc/passwd | 644 | root | U-16 |
| /etc/shadow | **400 (또는 000)** | root | U-18 |
| /etc/hosts | 644 | root | U-19 |
| /etc/(r)syslog.conf | **640** | root | U-21 |
| /etc/services | 644 | root | U-22 |
| /var/log/wtmp, lastlog, utmp | **640** | root | U-67 |
| UMASK | **022** | - | U-30 |

### 개념
- **권한 읽기**: `-rw-r--r--` = (소유자 rw)(그룹 r)(others r). **others에 w(쓰기)** 가 있으면 위험
- **world writable(o+w)**: 누구나 파일을 덮어쓰기/삭제 가능 → 시스템 파일이면 장애·악성코드 삽입
- **UMASK 022**: 신규 파일에서 그룹·others 쓰기 권한을 제거하는 마스크값

### 💡 실전 (CentOS 6.9)
- **U-21 🔴 취약**: rsyslog.conf 권한 **644 → 640** 조치
- **U-23 🔴 취약**: SUID 설정 파일(**unix_chkpwd, at, newgrp**) → SUID 제거
- **U-25 🟡 인터뷰**: world writable가 커널 관련 파일뿐(재부팅 시 원복) → 담당자 확인
- **U-30 🔴 취약**: UMASK **002 → 022** 추가
- **U-66/U-67 🔴 취약**: /var/log/lastlog(644), wtmp·utmp(664) → **640** + others 권한 제거

> (상세 → [02. 파일·디렉터리 관리 U-16~U-25](./02_Unix_진단항목_U01-U67.md))

## 3. 아파치 필수 확인

httpd.conf에서 **반드시 확인**하는 설정들. 지문에 설정값을 주고 양호/취약 판정 요구.

### 핵심 확인 명령
```bash
cat /etc/httpd/conf/httpd.conf | grep "DocumentRoot\|ServerRoot" | grep -v "#"
cat /etc/httpd/conf/httpd.conf | grep -C10 Directory | grep -v "#"   # Options/AllowOverride
cat /etc/httpd/conf/httpd.conf | grep Listen | grep -v "#"           # 80/443
cat /etc/httpd/conf/httpd.conf | grep "CustomLog\|ErrorLog" | grep -v "#"
cat /etc/httpd/conf/httpd.conf | grep -E "ServerTokens|ServerSignature"
```

### 필수 설정 정답표

| 항목 | 설정 | 🟢 양호 | 🔴 취약 |
|------|------|--------|--------|
| **WEB-04** 디렉터리 리스팅 | Options | `-Indexes` | `Indexes` |
| **WEB-06** 상위 경로 접근 | AllowOverride | `AuthConfig` | `None` |
| **WEB-09/14** 소유자·권한 | 파일 소유자 | **apache** 계정, conf 640·디렉터리 750 | root, 644/755 |
| **WEB-12** 심볼릭 링크 | Options | `-FollowSymLinks` | `FollowSymLinks` |
| **WEB-16** 헤더 정보 | ServerTokens / Signature | `Prod` / `Off` | `OS` / `On` |
| **WEB-20** SSL/TLS | Listen | 443 + TLS1.2/1.3 | 80만 허용 |
| **WEB-26** 로그 | 권한/포맷 | 640, apache, **combined** | 644, root |

### 핵심 개념
- **Indexes**: 디렉터리에 index 파일 없으면 파일 목록을 그대로 노출 → `-Indexes`로 차단
- **ServerTokens Prod**: 응답 헤더에서 Apache 버전·OS 숨김 (정보 노출 방지)
- **combined 로그**: `%h %l %u %t "%r" %>s %b "Referer" "User-Agent"` — IP·요청·유입경로·브라우저 모두 기록

### 💡 실전 (CentOS 6.9 — 대부분 취약)
- 소유자가 전부 **root** + 권한 과다(755/644) → 공통 조치: **전용 계정(apache) + 750/640**
- ServerTokens=**OS**, ServerSignature=**On** → Prod/Off
- HTTP(80)만 허용 → HTTPS(443) 추가 + Redirect

> (상세 → [11. WEB 진단 결과](./11_진단결과_WEB_Apache_CentOS6.9.md), [04. WEB 항목](./04_WEB_Apache_진단항목_WEB01-WEB26.md))

## 4. 메일 서버 문제

postfix/sendmail 설정 파일에서 릴레이·명령어 제한을 확인.

### 핵심 확인 명령
```bash
postconf mail_version                            # 버전 (U-45)
ls -al /usr/sbin/postsuper                        # 큐 DROP 권한 (U-46)
cat /etc/postfix/main.cf | grep mynetworks        # 릴레이 제한 (U-47)
cat /etc/postfix/main.cf | grep disable_vrfy_command  # expn/vrfy (U-48)
cat /etc/postfix/main.cf | grep smtpd_banner       # 배너 (U-62)
```

### 판단 기준 & 정답

| 항목 | 확인 | 🟢 양호 | 🔴 취약 |
|------|------|--------|--------|
| **U-45** 버전 | postconf mail_version | 최신 패치 | 구버전(EOS) |
| **U-46** 큐 DROP | /usr/sbin/postsuper 권한 | **750** | 755 |
| **U-47** 릴레이 | main.cf `mynetworks` | 관리자 IP만 등록 | 주석(오픈 릴레이) |
| **U-48** expn/vrfy | main.cf `disable_vrfy_command` | **yes** | 미설정 |

### 핵심 개념
- **릴레이(mynetworks)**: 오픈 릴레이면 서버가 **스팸 발송지로 악용**됨 → 신뢰 네트워크·관리자 IP만 허용
- **VRFY/EXPN**: 계정 존재 확인·메일링리스트 확장 명령 → **계정 정보 수집(정찰)** 에 악용 → `disable_vrfy_command = yes`
- **메일 QUEUE**: 일반 사용자가 DROP(삭제) 못 하도록 postsuper 권한 제한(U-46)

### 💡 실전 (CentOS 6.9 — 전부 취약)
- **U-45 🔴**: postfix **2.6.6**, CentOS 6.9 EOS로 패치 불가 → 신규 구축
- **U-46 🔴**: postsuper **755 → 750**
- **U-47 🔴**: mynetworks 주석 → 관리자 IP 등록
- **U-48 🔴**: disable_vrfy_command **yes** 설정

> (상세 → [02. U-45~U-48](./02_Unix_진단항목_U01-U67.md), U-47 강사 보충)

## 5. 계정 분석 (지문형)

`/etc/passwd` 한 줄을 주고 **필드 해석·취약 여부·계정 종류**를 묻는 형태.

### /etc/passwd 7필드 (암기)
```
  root : x : 0 : 0 : root : /root : /bin/bash
   ①    ②   ③   ④    ⑤      ⑥        ⑦
① Username  ② Password(x=shadow)  ③ UID  ④ GID
⑤ Comment   ⑥ Home directory      ⑦ Login Shell
```

### UID 체계
| UID | 분류 | 예 |
|-----|------|-----|
| **0** | 최고관리자(root 전용) | root |
| 1~999 | 시스템/서비스 계정 | mysql(27), apache |
| **1000+**(구버전 500+) | 일반 사용자 | adiosl(500), cubrid |

### 지문 해석 포인트

| 지문 패턴 | 판정 | 근거·항목 |
|----------|------|----------|
| root 외 계정에 **UID 0** | 🔴 취약 | root 권한 탈취 위험 (U-05) |
| **동일 UID** 계정 2개 | 🔴 취약 | 감사 추적 불가 (U-10) |
| 서비스 계정(mysql)에 **/bin/bash** | 🔴 취약 | 로그인 셸 부여 (U-11) |
| 미사용 계정 존재(로그인 기록 없음) | 🟡 인터뷰/취약 | 불필요 계정 (U-07) |
| SSH `PermitRootLogin yes` | 🔴 취약 | root 원격 접속 (U-01) |
| wheel 그룹 미설정 + su 주석 | 🔴 취약 | su 제한 안 됨 (U-06) |

### 예시 문제 & 답
```
지문: mysql:x:27:27:MySQL Server:/var/lib/mysql:/bin/bash
Q. 이 계정의 취약점은?
A. 서비스 계정(mysql)에 로그인 셸(/bin/bash)이 부여됨 → U-11 취약.
   조치: usermod -s /sbin/nologin mysql
```
```
지문: backup:x:0:0::/home/backup:/bin/bash
Q. 판정은?
A. root(UID 0)가 아닌 backup 계정이 UID 0 → U-05 취약.
   조치: 0 이외 UID로 변경(usermod -u) 또는 불필요 시 제거.
```

### 💡 실전 (CentOS 6.9)
- 로그인 가능 계정: root(0), adiosl(500), mysql(27), cubrid(501)
- **U-05 🟢**: UID 0은 root뿐 / **U-11 🔴**: mysql·cubrid에 /bin/bash / **U-07 🟡**: adiosl 미사용(2017 생성 후 셸 기록 없음)

## 📌 시험 직전 체크 (한 줄 암기)

1. **패스워드**: 90/1/8 + 복잡도 4종, SHA512, shadow 암호화
2. **쓰기권한**: others w 있으면 취약 / shadow 400·syslog 640·log 640 / UMASK 022 / SUID 제거
3. **아파치**: -Indexes, ServerTokens Prod, 소유자 apache·640/750, HTTPS 443, combined 로그
4. **메일**: mynetworks(릴레이 제한), disable_vrfy_command=yes, postsuper 750
5. **계정**: passwd 7필드, UID 0=root만, 서비스계정 nologin
