# Part 1. 인공지능 · 머신러닝 · 딥러닝

## 1.1 AI, 머신러닝, 딥러닝의 관계

**인공지능(AI)** 은 인간의 지능(학습·추론·지각 등)을 컴퓨터로 모사하는 모든 기술을 통칭합니다. 그 안에 머신러닝이, 머신러닝 안에 딥러닝이 들어가는 **포함 관계** 입니다.

| **구분** | **정의** | **대표 예시** |
|----|----|----|
| **인공지능 (AI)** | 지능을 모사하는 모든 기술. 규칙 기반 시스템부터 스스로 사고하는 시스템까지 포함 | 검색 엔진, 자율주행, 챗봇 |
| **머신러닝 (ML)** | 사람이 규칙을 짜는 대신 데이터로 학습시켜 스스로 성능을 높이는 기술 | 스팸 분류, 넷플릭스 추천, 주가 예측 |
| **딥러닝 (DL)** | 인공신경망을 여러 층(Deep)으로 쌓아 복잡한 비정형 데이터를 처리하는 ML의 한 종류 | ChatGPT(LLM), 이미지 생성(Stable Diffusion) |

> **💡 포함 관계로 외우기**
> AI ⊃ 머신러닝 ⊃ 딥러닝. 즉 **모든 딥러닝은 머신러닝이고, 모든 머신러닝은 AI** 이지만 그 역은 성립하지 않습니다. 예전 체스 프로그램처럼 사람이 짠 규칙으로만 도는 AI도 있는데, 이는 머신러닝이 아닙니다.
> **정형 데이터 vs 비정형 데이터:** 표·숫자처럼 행과 열로 정리되는 것이 정형 데이터, 이미지·음성·텍스트처럼 그렇지 않은 것이 비정형 데이터입니다. 딥러닝은 특히 비정형 데이터에서 압도적입니다.

## 1.2 머신러닝 핵심 용어

### 독립변수와 종속변수

- **독립변수 (X / feature / 특징):** 원인이 되는 변수. 모델이 예측에 사용하는 입력 힌트들. 예) 나이·BMI·혈압, 아파트 평수·방 개수·역과의 거리

- **종속변수 (y / target / label / 정답):** 결과가 되는 변수. 우리가 최종적으로 맞히고 싶은 정답. 예) 1년 뒤 질병 진행도, 아파트 실거래가

### 모델, 학습, 추론

- **모델(Model):** 데이터의 패턴을 담는 수학적 뼈대이자 예측 시스템 (선형 회귀, 결정 트리, 인공신경망 등)

- **학습(Training):** X와 y를 반복해 보며 둘 사이의 규칙·패턴을 스스로 찾아내는 과정

- **추론(Inference):** 학습을 마친 모델에 정답 없는 새 데이터를 주고 결과를 예측하게 하는 과정

> **💡 헷갈리지 않기 — 파라미터 vs 하이퍼파라미터**
> 핵심 구분은 **'누가 정하느냐'** 입니다. 기계가 학습으로 알아내면 파라미터, 사람이 학습 시작 전에 손으로 정하면 하이퍼파라미터입니다. 요리에 비유하면 오븐 온도·굽는 시간(하이퍼파라미터)은 내가 미리 정하고, 그 결과로 빵이 부푸는 정도(파라미터)는 자동으로 결정됩니다.
> **에포크 1회 =** 전체 학습 데이터를 처음부터 끝까지 한 번 훑는 것. 학습률이 너무 크면 정답을 지나쳐 발산하고, 너무 작으면 학습이 매우 느려집니다.

> **💡 유형 구분 한 줄 정리**
> 
> **정답표가 있다 →** 지도 학습 (회귀 = 숫자 맞히기 / 분류 = 종류 맞히기)
> **정답표가 없다 →** 비지도 학습 (비슷한 것끼리 묶기 = 군집)
> **정답 대신 점수(보상)가 있다 →** 강화 학습 (게임 점수를 올리듯)

## 1.4 규칙 기반 프로그래밍 vs 머신러닝

**규칙 기반:** 데이터 + 규칙(사람이 입력) → 결과 \| **머신러닝:** 데이터 + 결과(정답) → 규칙(컴퓨터가 학습)

| **구분** | **규칙 기반 프로그래밍** | **머신러닝** |
|----|----|----|
| **규칙의 주체** | 인간 개발자가 직접 정의 | 데이터로부터 기계가 자동 학습 |
| **메커니즘** | IF-THEN 조건문의 조합 | 통계적 모델링·패턴 인식 |
| **결과 성격** | 결정론적 (항상 일정) | 확률론적 (불확실성 존재) |
| **설명 가능성** | 과정 추적이 명확 | 복잡한 모델은 추적이 어려움 |
| **새 상황 대응** | 사람이 코드를 고쳐야 반영 | 새 데이터 학습으로 자동 업데이트 |

**적합한 영역 —** 규칙 기반: 세금 계산·회계·경기 판정처럼 예외 없이 규칙이 명확하고 투명한 설명이 필요한 일. 머신러닝: 이미지·음성 인식, 자율주행, 자연어 처리처럼 규칙을 말로 일일이 정의하기 어려운 일.

> **💡 왜 굳이 머신러닝인가**
> 스팸 필터를 예로 들면, 규칙 기반은 '무료'가 들어가면 스팸 처리하도록 짭니다. 그런데 발송자가 '무.료', '광/고'로 바꾸면 규칙을 또 추가해야 하는 **끝없는 술래잡기** 가 됩니다. 머신러닝은 수백만 건의 메일에서 미세한 패턴을 스스로 찾아내 변형에도 대응합니다. 단, 그 대가로 **왜 그렇게 판단했는지 설명하기 어렵다** 는 약점(블랙박스 문제)이 생깁니다.

## 1.5 AI 윤리

AI를 개발·사용하는 과정에서 **인간의 존엄성·안전·보편적 가치를 지키기 위한 도덕적 기준** 입니다. AI의 사회적 영향력이 커질수록 오남용과 부작용을 막는 필수 안전장치가 됩니다.

### AI 윤리가 중요한 이유

- **차별과 편향:** 과거 남성 중심 데이터를 학습한 채용 AI가 여성 지원자를 탈락시키는 문제

- **프라이버시 침해:** 동의 없이 방대한 개인정보를 무단 수집·학습

- **책임 소재의 모호성:** 자율주행차 사고 시 제조사·운전자·개발자 중 책임 주체가 불명확

- **딥페이크·가짜뉴스:** 얼굴·목소리를 도용해 범죄에 악용하거나 여론 조작

### 핵심 5대 원칙 (UNESCO·EU 등 공통)

1.  인간 중심(Human Centric): AI는 인간의 자유·권리를 침해하지 않고 복지 증진에 쓰여야 함

2.  투명성·설명 가능성(Transparency): 왜 그런 결론을 냈는지 인간이 이해할 수 있어야 함

3.  공정성(Fairness): 인종·성별·종교·지역에 따른 차별·편향을 배제

4.  안전성·보안(Safety & Security): 해킹·악용에 안전하고 신체·정신적 해를 끼치지 않아야 함

5.  책임성(Accountability): 오작동·결과에 책임질 주체(인간)가 명확해야 함

> **💡 시사 연결 — 편향은 어디서 오나**
> AI의 편향은 대개 알고리즘 자체가 아니라 **학습 데이터** 에서 옵니다('Garbage In, Garbage Out'). 과거의 차별이 담긴 데이터를 그대로 학습하면 AI가 그 차별을 자동화·증폭합니다. 그래서 '설명 가능한 AI(XAI)'와 공정성 평가가 점점 중요해지고 있습니다.

> **💡 GPU가 왜 딥러닝에 중요한가**
> CPU는 복잡한 계산을 순차적으로 잘 처리하고, GPU는 단순한 계산을 **동시에 대량으로** 처리합니다. 딥러닝은 거대한 행렬 곱셈의 반복이라 병렬 처리에 강한 GPU에서 수십 배 빨라집니다.

\# 결합 방식: 숫자는 str()로 변환해야 함

print("나는 " + name + ", 나이는 " + str(age) + "살")

\# f-string: 문자열 앞 f, 변수는 {} 안에 ← 권장

print(f"나는 {name}, 나이는 {age}살")

> **💡 f-string을 쓰는 이유**
> 문자열 결합(+)은 숫자를 일일이 **str()** 로 바꿔야 하고 따옴표·공백 실수가 잦습니다. f-string은 **{변수}** 로 바로 끼워 넣어 가독성이 좋고 오류가 적습니다. **f"{3*4}"** 처럼 중괄호 안에서 식 계산도 됩니다.

## 2.4 연산자

### 산술 연산자

| **연산자** | **의미**                       | **예시**      |
|------------|--------------------------------|---------------|
| + - *    | 더하기·빼기·곱하기             | 5 + 2 → 7     |
| /          | 나누기 (결과는 항상 실수)      | 5 / 2 → 2.5   |
| //         | 몫 (소수점 버림)               | 5 // 2 → 2    |
| %          | 나머지 (홀짝 판별에 자주 사용) | 5 % 2 → 1     |
|            | 거듭제곱                       | 5 ** 2 → 25 |

### 비교 · 대입 연산자

- **비교:** == (같다), != (다르다), > < >= <= → 결과는 True/False

- **대입:** = (기본 대입), += (x += 3 은 x = x + 3 과 동일), -= 등

### 문자열 결합/반복

print("Hello" + ", " + "Python" + "!") \# 결합 → Hello, Python!

print("-" * 14) \# 반복 → --------------

> **💡 = 와 == 는 완전히 다르다**
> **=** 는 '값을 넣어라'(대입), **==** 는 '같은지 비교해라'(비교)입니다. 조건문에서 **if x = 5** 처럼 쓰면 오류가 나며 **if x == 5** 가 맞습니다. 가장 흔한 초보 실수입니다.
> **/ 와 // 주의:** 5 / 2 는 2.5(실수), 5 // 2 는 2(몫)입니다. %(나머지)가 0이면 짝수라는 점도 자주 활용됩니다.

## 2.5 조건문 (if / elif / else)

| **키워드** | **의미** | **설명** |
|----|----|----|
| **If** | 만약 ~라면 | 조건이 참(True)일 때만 아래 코드 실행 |
| **Elif** | 그렇지 않고 ~라면 | 앞 조건이 거짓일 때 새 조건 검사 (개수 제한 없음) |
| **Else** | 그것도 아니라면 | 앞의 모든 조건이 거짓일 때 실행 (조건식 없음) |

score = 85

if score >= 90:

print("A 학점")

elif score >= 80:

print("B 학점") \# ← 실행됨

else:

print("C 학점 이하")

\# in : 멤버십 연산자

if "포션" in inventory:

print("회복 가능")

\# 조건부 표현식 (한 줄 if)

result = "합격" if score >= 70 else "불합격"

> **💡 들여쓰기(indent)가 곧 문법이다**
> 파이썬은 중괄호 {} 대신 **들여쓰기(보통 공백 4칸)** 로 코드 묶음(블록)을 구분합니다. 콜론(:) 다음 줄은 반드시 들여써야 하며, 들여쓰기가 어긋나면 **IndentationError** 가 납니다. elif는 여러 번, else는 맨 끝에 한 번만 옵니다.

## 2.6 반복문 (for / while)

| **종류** | **중심 개념** | **주로 쓰는 경우** |
|----|----|----|
| **for** | 횟수·대상 중심 | 반복 횟수가 정해졌거나 리스트·문자열 요소를 하나씩 꺼낼 때 |
| **While** | 조건 중심 | 조건이 참인 동안 계속 (횟수가 정해지지 않았을 때) |

for fruit in ["사과", "바나나", "체리"]:

print(fruit)

for i in range(1, 6): \# 1,2,3,4,5 (끝 6은 미포함)

print(i)

count = 1

while count <= 3:

print(count)

count += 1 \# 이게 없으면 무한 루프!

\# 흐름 제어

break \# 반복을 즉시 종료

continue \# 이번 회차만 건너뛰고 다음으로

\# 리스트 컴프리헨션

squares = [x ** 2 for x in range(1, 5)] \# [1, 4, 9, 16]

> **💡 range와 무한 루프 주의**
> **range(1, 6)** 은 1부터 **6 직전(5)** 까지입니다. 끝 숫자는 포함하지 않는다는 점을 꼭 기억하세요.
> **while** 문에서는 조건을 거짓으로 만드는 코드(예: count += 1)를 빼먹으면 영원히 도는 **무한 루프** 에 빠집니다. 리스트 컴프리헨션은 for문 4줄을 한 줄로 압축하는 파이썬다운 표현입니다.

## 2.7 리스트 (List)

여러 데이터를 **대괄호 [ ]** 로 묶어 **순서대로** 관리하는 자료형. 정수·실수·문자열·리스트까지 섞어 담을 수 있고, 생성 후 자유롭게 수정됩니다.

items = [10, 3.15, True, "Hello", [1, 2, 3]]

items[0] \# 인덱싱: 첫 번째 → 10

items[-1] \# 마지막 → [1, 2, 3]

items[0:2] \# 슬라이싱: 0~1번 → [10, 3.15]

nums = [10, 20, 30]

nums[0] = 99 \# 수정

nums.append(40) \# 맨 뒤 추가

nums.remove(20) \# 값으로 삭제

del nums[0] \# 위치로 삭제

sum(nums); max(nums); min(nums); len(nums) \# 자주 쓰는 함수

> **💡 인덱스는 0부터, 음수는 뒤에서부터**
> 첫 요소는 **0번** 입니다(1번 아님). **-1** 은 맨 뒤, **-2** 는 뒤에서 두 번째를 가리킵니다. 슬라이싱 **[a:b]** 는 a번부터 b **직전** 까지 — 조건문·반복문과 더불어 시험·실습에서 가장 많이 나오는 개념입니다.

## 2.8 딕셔너리 (Dictionary)

키(key)–값(value) 쌍으로 저장하는 자료형. **중괄호 { }** 로 만들며, 키로 값을 빠르게 찾습니다. 키는 중복 불가, 값은 중복 가능, 키는 변경 불가능한 타입(문자열·숫자·튜플)만 가능합니다.

person = {"name": "Alice", "age": 30, "city": "Seoul"}

person["name"] \# 키로 접근 → Alice

person.get("email", "none") \# 키 없으면 기본값 반환 (안전)

person["age"] = 35 \# 수정

person["email"] = "a@b.com" \# 새 항목 추가

del person["city"] \# 삭제

person.keys(); person.values(); person.items() \# 키/값/쌍

for key, value in person.items():

print(key, value)

squares = {n: n**2 for n in range(1, 6)} \# 딕셔너리 컴프리헨션

> **💡 리스트 vs 딕셔너리, 그리고 .get()**
> **리스트** 는 **순서(번호)** 로 값을 찾고, **딕셔너리** 는 **이름(키)** 으로 값을 찾습니다. 의미 있는 이름으로 데이터를 관리할 때 딕셔너리가 편합니다.
> **person["x"]** 는 키가 없으면 오류(KeyError)가 나지만, **person.get("x", 기본값)** 은 오류 없이 기본값을 돌려줘 더 안전합니다. 파이썬 3.7+ 부터 딕셔너리는 입력한 순서를 유지합니다.
