불균형·SMOTE · 의사결정 트리 · 랜덤포레스트

목차

1\. 데이터 불균형 (Data Imbalance)

분류 데이터셋에서 특정 클래스의 샘플 수가 다른 클래스보다 현저히 적거나 많은 상황. 현실에서는 흔합니다 (사기 거래, 암 환자, 희귀질환 등).

1.1 모델에 미치는 영향

- **정확도의 함정(Accuracy Paradox):** 전체 정확도는 높아 보여도, 정작 중요한 소수 클래스(사기·암)의 재현율·정밀도는 매우 낮음

- **편향된 모델:** 빈도 높은 다수 클래스만 예측하는 게 '안전'하다고 학습 → 소수 클래스를 무시

1.2 해결 전략

| **전략** | **방법** | **설명** |
|----|----|----|
| **오버샘플링** | 소수 클래스 늘리기 | 복제 또는 유사 샘플 생성 (예: SMOTE) |
| **언더샘플링** | 다수 클래스 줄이기 | 다수 클래스 일부를 제거 |
| **알고리즘 변경** | 특화 모델·가중치 | Random Forest·LightGBM, 손실함수에 소수 클래스 가중치 부여 |

2\. SMOTE (합성 소수 오버샘플링)

단순 복제가 아니라, 기존 소수 클래스 샘플들 **사이의 공간에 새로운 데이터를 생성**하는 대표적 오버샘플링 기법. **KNN** 기반으로 동작합니다.

2.1 작동 원리 (KNN 기반 보간)

> **1. 소수 클래스 샘플 하나를**무작위 선택
>
> **2. 그 샘플의 최근접 이웃 K개**(보통 5개)를 찾음
>
> **3. 샘플과 이웃 하나를**잇는 선분을 그림
>
> **4. 그 선분 위 임의의 지점에**새 데이터 생성(보간, Interpolation)

- **복제보다 나은 이유:** 새 데이터를 만들어 과적합 위험↓, 소수 클래스의 결정 경계를 넓게 확장

- **한계·변형:** 다수 클래스 근처에 잘못 생성하면 노이즈가 됨 → Borderline-SMOTE(경계에만), ADASYN(밀도 낮은 곳에 더 많이)

from imblearn.over_sampling import SMOTE

\# \[중요\] 학습 데이터에만 적용! (테스트에 적용하면 가짜 데이터를 평가하는 꼴)

smote = SMOTE(random_state=42)

X_train_res, y_train_res = smote.fit_resample(X_train, y_train)

y_train.value_counts() \# 적용 전 (불균형)

y_train_res.value_counts() \# 적용 후 (균형)

3\. 의사결정 트리 (Decision Tree)

데이터를 **스무고개처럼 질문**으로 나눠 분류·회귀하는 나무 구조 알고리즘.

3.1 구조

| **구성**                | **설명**                            |
|-------------------------|-------------------------------------|
| **뿌리 노드(Root)**     | 전체 데이터가 시작되는 최상위 노드  |
| **중간 노드(Internal)** | 데이터를 나누는 기준(질문) 노드     |
| **가지(Branch)**        | 답(Yes/No)에 따라 갈라지는 경로     |
| **잎 노드(Leaf)**       | 더 안 나뉘는 최종 결과(클래스·수치) |

3.2 분할 기준 — 얼마나 '깨끗하게' 나눴나

- **엔트로피 / 정보 이득(Information Gain):** 질문 후 불확실성이 얼마나 줄었는지 → 정보 이득 최대 방향으로 분할

- **지니 계수(Gini Index):** 불순도(서로 다른 클래스가 섞인 정도). 0에 가까울수록 순수

3.3 장단점 & 가지치기

| **장점** | **단점** |
|----|----|
| 해석 쉬움 (White Box, 시각화 가능) | **과적합 위험** (너무 깊으면 훈련에만 맞춰짐) |
| 전처리 간단 (스케일링 불필요) | 불안정 (데이터 조금 바뀌면 구조 확 변함) |
| 수치형·범주형 모두 처리 | 단일 트리는 성능 한계 |

**가지치기(Pruning):** 사전(Pre) — max_depth·min_samples_leaf로 미리 제한 / 사후(Post) — 만든 뒤 기여도 낮은 가지 제거.

from sklearn.tree import DecisionTreeClassifier, plot_tree

dt = DecisionTreeClassifier(

max_depth=4, \# 사전 가지치기: 최대 깊이

min_samples_leaf=10, \# 잎이 되기 위한 최소 샘플 수

random_state=42)

dt.fit(X_train, y_train)

plot_tree(dt) \# 트리 시각화

dt.feature_importances\_ \# 어떤 특성이 중요했나

4\. 랜덤포레스트 (Random Forest)

의사결정 트리의 과적합 약점을 해결하기 위해 **여러 트리를 결합**하는 앙상블(Ensemble) 모델. 분류·회귀 모두 사용합니다.

4.1 작동 원리

> **1. 배깅(Bagging):**부트스트랩(중복 허용 복원추출)으로 여러 데이터셋 생성. 안 뽑힌 약 36.8%는 OOB로 검증에 활용
>
> **2. 무작위 피처 선택:**전체 M개 중 무작위 m개(보통 √M)에서만 분할 → 나무들이 서로 달라짐(다양성 확보)
>
> **3. 독립적 트리 생성:**가지치기 없이 깊게 키운 트리 수십~수백 개
>
> **4. 집단지성:**분류=다수결, 회귀=평균으로 최종 예측

| **장점**                       | **단점**                           |
|--------------------------------|------------------------------------|
| 단일 트리보다 과적합↓, 안정적  | 트리가 많아 학습 느림              |
| 스케일링 등 전처리 거의 불필요 | 블랙박스 (개별 판단 역추적 어려움) |
| 특성 중요도 파악 쉬움          | —                                  |

from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(

n_estimators=100, \# 만들 트리 개수

max_depth=5, \# 각 트리 최대 깊이

random_state=42)

rf.fit(X_train, y_train)

y_pred = rf.predict(X_test)

from sklearn.metrics import accuracy_score, classification_report

print(accuracy_score(y_test, y_pred))

print(classification_report(y_test, y_pred))

rf.feature_importances\_ \# 특성 중요도
