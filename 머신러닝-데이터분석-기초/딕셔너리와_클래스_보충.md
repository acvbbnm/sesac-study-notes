1. 딕셔너리(Dictionary) 정리

**키(key)–값(value)** 쌍으로 데이터를 저장하는 자료 구조. **이름표(키)** 로 값을 빠르게 찾습니다.

주요 특징

- **순서 있음** (Python 3.7+): 삽입한 순서대로 항목 유지

- **키는 중복 불가, 값은 중복 가능**

- **키는 변경 불가능한 타입만** 가능 (문자열·숫자·튜플). 리스트는 키가 될 수 없음

- 중괄호 { } 또는 dict() 로 생성

주요 연산·메서드 한눈에

| **동작** | **문법** | **설명** |
|----|----|----|
| 접근 | person["name"] | 키로 값 꺼내기 (없으면 KeyError) |
| 안전한 접근 | person.get("age", 0) | 키 없으면 기본값 반환 (오류 X) |
| 수정 / 추가 | person["age"] = 35 | 있으면 수정, 없으면 새로 추가 |
| 삭제 | del person["city"] | 특정 키 삭제 |
| 꺼내며 삭제 | person.pop("name") | 값을 반환하면서 삭제 |
| 전체 삭제 | person.clear() | 빈 딕셔너리로 |
| 키 / 값 / 쌍 | keys() / values() / items() | 반복문에 자주 사용 |
| 여러 항목 갱신 | person.update({...}) | 여러 키를 한 번에 수정·추가 |

person = {"name": "Alice", "age": 30}

print(person["name"]) \# Alice

print(person.get("email","none"))# none (키 없음 → 기본값)

person["age"] = 35 \# 수정

person["city"] = "Seoul" \# 추가

for key, value in person.items():

print(f"{key} : {value}")

\# 딕셔너리 컴프리헨션

squares = {n: n**2 for n in range(1, 6)} \# {1:1, 2:4, ... 5:25}

\# 키 기준 정렬

for key in sorted(person.keys()):

print(key, person[key])

> **💡 [ ] 기호와 .get(), 그리고 정렬**
> 교안의 빈 [ ] 는 Colab에서 **실행 결과가 없는 코드 셀** 표시일 뿐 문법이 아닙니다.
> **person["x"]** 는 키가 없으면 오류(KeyError), **person.get("x", 기본값)** 은 오류 없이 기본값을 돌려줘 안전합니다.
> **sorted(딕셔너리.keys())** 는 원본을 바꾸지 않고 **정렬된 키 리스트** 를 새로 만들어 돌려줍니다.

2. 딕셔너리에서 클래스로 — 왜 클래스가 필요한가

딕셔너리로도 '한 사람'을 표현할 수 있습니다. 하지만 사람이 많아지고 **'행동(기능)'** 까지 담아야 하면 한계가 옵니다.

\# 딕셔너리 방식 — 데이터만 담긴다

alice = {"name": "Alice", "age": 30}

bob = {"name": "Bob", "age": 25}

\# 문제점:

\# - 오타로 "naem" 이라고 써도 오류를 안 알려줌

\# - "인사하기" 같은 기능(동작)을 넣기 어렵다

\# - 사람마다 매번 같은 구조를 손으로 다시 만들어야 함

> **💡 핵심 다리(bridge)**
> **딕셔너리** = 이름표로 **데이터** 를 묶는 도구. **클래스** = **데이터(속성) + 기능(메소드)** 을 하나의 '설계도'로 묶는 도구입니다. 즉 클래스는 딕셔너리에 **'행동'** 을 더하고, **'설계도'로 찍어내기** 를 가능하게 한 발전형이라고 보면 됩니다.

3. 클래스 · 객체 · 인스턴스

| **용어** | **비유** | **의미** |
|----|----|----|
| **클래스(Class)** | 붕어빵 **틀** / 설계도 | 객체를 만들기 위한 틀. 속성·메소드를 정의 |
| **객체(Object)** | 틀로 찍어낸 **붕어빵** | 클래스로 만들어진 실체 (데이터+기능을 가짐) |
| **인스턴스(Instance)** | '이 붕어빵은 그 틀의 것' | 특정 클래스로부터 만들어진 객체를 부르는 말 |

객체와 인스턴스는 거의 같은 뜻입니다. **객체** 는 그 자체를 가리키는 일반적 표현이고, **인스턴스** 는 **'어느 클래스로부터 나왔는지'** 관계를 강조할 때 씁니다. (예: alice 는 Person 클래스의 인스턴스다.)

4. 속성(Attribute)과 메소드(Method)

- **속성(Attribute):** 객체가 가진 **데이터·상태**. 딕셔너리의 '값'에 해당 (예: 이름, 나이)

- **메소드(Method):** 객체가 할 수 있는 **동작·기능**. 클래스 안에 정의된 함수 (예: 인사하기)

기본 문법

class Person: \# 클래스 정의 (관례상 첫 글자 대문자)

def __init__(self, name, age): \# 생성자: 객체가 만들어질 때 자동 실행

self.name = name \# 속성 저장

self.age = age

def greet(self): \# 메소드 (동작)

print(f"안녕, 나는 {self.name}, {self.age}살이야.")

\# 인스턴스 생성 (틀로 붕어빵 찍기)

alice = Person("Alice", 30) \# __init__ 자동 호출

bob = Person("Bob", 25)

print(alice.name) \# 속성 접근 → Alice

alice.greet() \# 메소드 호출 → 안녕, 나는 Alice, 30살이야.

bob.greet() \# 안녕, 나는 Bob, 25살이야.

> **💡 self 와 __init__ 이 헷갈릴 때**
> **__init__ (생성자):** 객체를 만들 때 **딱 한 번 자동으로** 실행되어 속성을 초기화합니다. Person("Alice", 30) 을 부르면 파이썬이 알아서 __init__ 을 호출합니다.
> **self:** **'만들어지는 그 객체 자신'** 을 가리킵니다. self.name = name 은 '이 객체의 name 칸에 값을 저장하라'는 뜻입니다. 메소드의 첫 번째 매개변수는 항상 self 로 쓰며, 호출할 때는 **직접 넣지 않습니다** (alice.greet() 라고만 쓰면 alice 가 self 로 자동 전달).

점(.) 표기법 — 딕셔너리와 비교

| **구분**     | **데이터 접근** | **딕셔너리 대응**        |
|--------------|-----------------|--------------------------|
| 딕셔너리     | alice["name"] | 대괄호 [키]            |
| 객체(클래스) | alice.name      | 점(.) + 속성이름         |
| 객체의 기능  | alice.greet()   | 딕셔너리엔 없음 (메소드) |

5. 딕셔너리 vs 클래스 정리

| **구분**      | **딕셔너리**              | **클래스(객체)**                 |
|---------------|---------------------------|----------------------------------|
| **담는 것**   | 데이터(값)만              | 데이터(속성) + 기능(메소드)      |
| **접근 방식** | alice["name"]           | alice.name                       |
| **구조 강제** | 자유로움 (오타 키도 허용) | 설계도가 구조를 고정 → 실수 감소 |
| **재사용**    | 매번 직접 구성            | 틀로 여러 인스턴스를 찍어냄      |
| **적합한 때** | 가볍게 데이터만 묶을 때   | 데이터+동작을 반복해 다룰 때     |

> **💡 한 줄 요약**
> **딕셔너리** 는 '이름표 붙인 데이터 묶음', **클래스** 는 '데이터 + 기능을 찍어내는 설계도'. 속성은 객체의 데이터, 메소드는 객체의 동작, 인스턴스는 설계도로 만든 실체입니다.
