1. 데이터베이스와 데이터베이스 시스템

데이터 · 정보 · 지식

- **데이터** : 관찰의 결과로 나타난 정량적·정성적인 실제 값

- **정보** : 데이터에 의미(사용 목적·용도)를 부여한 것

- **지식** : 사물·현상에 대한 이해 (데이터+정보→이해→지식)

**데이터베이스** : 조직에 필요한 정보를 얻기 위해 **논리적으로 연관된 데이터를 모아 구조적으로 통합**해 놓은 것.

데이터베이스의 4가지 개념

| **개념**                  | **의미**                                       |
|---------------------------|------------------------------------------------|
| 통합된 데이터(Integrated) | 중복을 최소화해 **데이터 불일치를 제거**       |
| 저장된 데이터(Stored)     | 디스크·테이프 등 **컴퓨터 저장장치**에 저장    |
| 운영 데이터(Operational)  | 조직의 업무·목적을 위해 검색·사용되는 데이터   |
| 공용 데이터(Shared)       | 한 사람이 아니라 **여러 업무가 공동으로 사용** |

> **💡 검색·변경 빈도로 DB 유형을 나눈다**
> 데이터베이스는 주로 **검색과 변경(삽입·삭제·수정)**을 수행합니다. 검색·변경 빈도에 따라 유형1(공룡 DB, 둘 다 적음)~유형4(증권 DB, 둘 다 많음)로 나뉘며, 둘 다 많은 실시간 시스템일수록 구축이 어렵습니다.

2. 파일 시스템 vs DBMS

데이터를 저장하는 방법은 3가지 — **① 프로그램 내부 저장, ② 파일 시스템, ③ DBMS** 순으로 발전했습니다.

| **방법** | **핵심 문제점** |
|----|----|
| ① 프로그램 내부 저장 | 데이터가 생길 때마다 **프로그램 수정 후 재컴파일** 필요 |
| ② 파일 시스템 | 데이터 구조 변경 시 재컴파일·서비스 중단 / **동시 공유 불가** |
| ③ DBMS | 데이터 정의·값을 DBMS가 관리 → **구조가 바뀌어도 재컴파일 불필요** |

> **💡 DBMS의 핵심 가치: 데이터와 프로그램의 분리**
> 파일 시스템은 데이터 구조가 프로그램에 박혀 있어(예: '저자' 컬럼 추가 시 재컴파일) 유지보수가 어렵고 동시 접근도 안 됩니다. **DBMS는 데이터 정의·값을 프로그램 밖(DBMS)에서 관리**하므로, 프로그램은 EXEC SQL 같은 명령으로 호출만 하고 구조 변경에 영향받지 않습니다. 이것이 데이터 독립성의 출발점입니다.

3. DB 시스템의 구성 (3단계 스키마)

**스키마(Schema)** : 데이터베이스의 구조 정의(릴레이션이 어떻게 구성되고 어떤 정보를 담는지). 테이블의 첫 행(헤더=속성)에 해당합니다. ANSI는 데이터베이스를 보는 관점을 **3단계**로 분리했습니다.

| **단계** | **보는 주체** | **설명** | **개수** |
|----|----|----|----|
| 외부 스키마 | 일반 사용자·응용 프로그래머 | 전체 DB 중 하나의 논리적 부분. **뷰(View)**·서브스키마 | **여러 개** |
| 개념 스키마 | DBA(DB 관리자) | 전체 DB의 정의. 관계·제약·무결성 포함 | **하나** |
| 내부 스키마 | DBMS | 물리적 저장 방법(인덱스·레코드 배치·압축) | **하나** |

**매핑(Mapping, 사상)** : 단계 간 대응 관계. **외부/개념 매핑**(외부↔개념)과 **개념/내부 매핑**(개념↔내부 물리 저장)의 두 종류가 있습니다.

데이터 독립성

| **종류** | **사이** | **의미** |
|----|----|----|
| 논리적 데이터 독립성 | 외부 ↔ 개념 | **개념 스키마가 변경돼도 외부 스키마(응용 프로그램)에 영향 없음** |
| 물리적 데이터 독립성 | 개념 ↔ 내부 | **저장장치 구조가 바뀌어도 개념 스키마에 영향 없음** (구현이 더 쉬움) |

> **💡 데이터 독립성 = 하위 세부사항을 상위에서 숨김**
> 3단계 구조의 핵심은 **데이터 독립성**입니다. 하위(물리) 단계의 세부사항을 상위(논리) 단계에 추상화해 숨김으로써 한 단계의 변경이 다른 단계에 간섭하지 않게 합니다. 참고로 **내부 스키마는 1개, 외부 스키마는 여러 개**입니다(자주 나오는 함정 문제).

> **💡 Day 1 핵심**
> DBMS는 **데이터와 프로그램을 분리**하고, **3단계 스키마**가 그 위에서 **데이터 독립성**을 보장한다. 이 토대 위에 Day 2의 관계 모델이 올라간다.
