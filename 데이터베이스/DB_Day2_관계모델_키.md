목차

4. 관계 데이터 모델 (릴레이션)

**릴레이션(Relation)** : 행과 열로 구성된 테이블. 관계 데이터 모델은 데이터를 2차원 테이블(릴레이션)로 표현하고, **제약조건**과 **관계대수** 연산을 정의한 것입니다.

릴레이션은 **스키마(구조)**와 **인스턴스(실제 데이터)**로 이루어집니다.

| **릴레이션 용어**  | **같은 의미**   | **파일 시스템 용어** |
|--------------------|-----------------|----------------------|
| 릴레이션(Relation) | 테이블(Table)   | 파일(File)           |
| 스키마(Schema)     | 내포(Intension) | 헤더(Header)         |
| 인스턴스(Instance) | 외연(Extension) | 데이터(Data)         |
| 튜플(Tuple)        | 행(Row)         | 레코드(Record)       |
| 속성(Attribute)    | 열(Column)      | 필드(Field)          |

핵심 용어

- **속성(Attribute)** : 릴레이션의 열 / **도메인(Domain)** : 속성이 가질 수 있는 값의 집합(예: {남, 여})

- **차수(Degree)** : 속성(열)의 개수 / **카디널리티(Cardinality)** : 튜플(행)의 개수

- **튜플(Tuple)** : 릴레이션 인스턴스의 행. 모든 튜플은 서로 중복되지 않아야 함

릴레이션의 6가지 특징

1.  한 속성의 값은 모두 같은 도메인 값을 가짐

2.  속성은 단일 값을 가짐 (여러 값 불가 → 튜플을 나눠야 함)

3.  속성은 서로 다른 이름을 가짐

4.  속성의 순서는 상관없음

5.  튜플의 순서는 상관없음

6.  릴레이션 내 중복된 튜플은 허용하지 않음 (속성 값이 하나라도 다르면 중복 아님)

> **💡 도메인·차수·카디널리티를 헷갈리지 말 것**
> **차수(Degree)=열 개수(스키마 고정), 카디널리티(Cardinality)=행 개수(수시로 변함)**입니다. **도메인은 '속성이 가질 수 있는 값의 범위'**로, 실제 저장된 값(인스턴스)과 구분해야 합니다. 도메인은 튜플 개수와 무관합니다(자주 나오는 O/X 함정).

5. 키와 무결성 제약조건

**키(Key)** : 특정 튜플을 식별하는 속성(집합). 키 값은 반드시 서로 달라야 하고, 릴레이션 간 관계를 맺는 데도 쓰입니다.

| **키** | **정의** |
|----|----|
| 슈퍼키(Super Key) | 튜플을 **유일하게 식별**하는 속성 집합 (불필요한 속성 포함 가능) |
| 후보키(Candidate Key) | 튜플을 유일하게 식별하는 **속성의 최소 집합** |
| 기본키(Primary Key) | 후보키 중 **대표로 선정한 키** (밑줄 표기, NULL·중복 불가) |
| 대체키(Alternate Key) | 기본키로 선정되지 **않은** 후보키 |
| 대리키(Surrogate Key) | 일련번호 같은 **가상 속성**을 만들어 기본키로 삼은 것(=인조키) |
| 외래키(Foreign Key) | **다른 릴레이션의 기본키를 참조**하는 속성 (관계 연결용) |

**기본키 선정 시** : ① 고유값, ② 값 변동 없음, ③ 최소 속성, ④ 문제 소지 없음, ⑤ **NULL 불가**. (주민번호는 개인정보라 부담 → 고객번호 같은 대리키 권장)

**외래키 특징** : 참조되는 기본키와 **도메인이 같아야** 하고, **NULL·중복 허용**. 참조되는 값이 변하면 외래키도 연동. 자기 자신의 기본키 참조도 가능(멘토 릴레이션).

3가지 무결성 제약조건

| **구분** | **도메인 무결성** | **개체 무결성** | **참조 무결성** |
|----|----|----|----|
| 별칭 | 도메인 제약 | 기본키 제약 | 외래키 제약 |
| 대상 | 속성 | 튜플 | 속성과 튜플 |
| 핵심 | 속성은 **지정 도메인 값**만 | **기본키는 NULL 불가·유일** | 외래키=참조 기본키와 **도메인 동일** |
| NULL | 허용 | **불가** | 허용 |

> **💡 키의 포함 관계: 슈퍼키 ⊇ 후보키 ⊇ 기본키**
> **슈퍼키(식별 가능한 모든 집합) ⊃ 후보키(최소 집합) ⊃ 기본키(대표 1개)**. 기본키로 안 뽑힌 후보키가 대체키입니다. 무결성은 데이터의 **일관성·정확성**을 지키는 것으로, **개체 무결성(기본키 NULL 금지)**과 **참조 무결성(외래키는 부모 기본키를 벗어난 값 금지)**이 핵심입니다.

> **💡 Day 2 핵심**
> 데이터를 **릴레이션(2차원 테이블)**로 표현하고, **키(식별)**와 **무결성(정확성)**으로 신뢰성을 보장한다. Day 3에서는 이 릴레이션을 연산하는 관계대수와 SQL을 배운다.
