# 증거 데이터 사전

## 형식과 공통 규칙

이 묶음은 **합성 조사 내보내기 형식**이다. CloudTrail은 기본 중첩 구조를 참고했고, 나머지는 분석을 위해 JSON Lines로 정규화했다. 원래 AWS·Linux의 모든 필드를 구현한 형식이나 재생 가능한 로그 수집 에이전트 출력은 아니다.

IP는 문서용 대역 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24와 사설 대역을 사용한다. 평판·국가·실제 AWS 주소를 조회해 판단하지 않는다. `192.0.2.80`은 이 시뮬레이션의 정상 외부 서비스 목적지다. 식별자가 실제 키처럼 보이더라도 인증에 사용할 수 없으며 SecretAccessKey·세션 토큰은 없다.

- 이벤트 원래 시각은 UTC다. 노트북은 `event_time`을 timezone-aware UTC로, `time_kst`를 KST로 만든다.
- 호스트·웹 시계 편차는 최대 1초라고 가정한다. 실제 조사에서는 별도 검증이 필요하다.
- `_collected_at`은 교육용 수집기 메타데이터이며 AWS 표준 이벤트 필드가 아니다. 이벤트보다 늦게 도착할 수 있다.
- 이벤트 ID·요청 ID는 근거 위치다. 공격/정상 라벨이나 단계 정답은 학생 데이터에 없다.
- 동일 식별자의 수집 중복은 제거하되 같은 객체의 새 요청은 남긴다.
- `manifest.json`은 개별 증거 파일의 SHA-256과 크기다. 자기 자신은 해시 목록에서 제외한다. 이 목록은 진실성을 보장하는 전자서명이 아니다.

## CloudTrail: initial/cloudtrail.jsonl 및 followup/cloudtrail.jsonl

주체·API·대상·오류·시간을 확인한다. `GetObject`는 Data, 나머지 제공 API는 Management 범주다. 데이터 이벤트는 별도로 수집을 설정해야 한다. 이 가상 사건은 대상 버킷 전체 prefix의 GetObject 수집이 사건 전에 활성화된 설정이다. [CloudTrail 데이터 이벤트](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/logging-data-events-with-cloudtrail.html)

| 원래 경로 | 노트북 열 | 해석 |
|---|---|---|
| eventID | record_id | 같은 이벤트의 재전송 구분 |
| requestID | request_id | S3 서버 요청과 연결 |
| eventTime | event_time, time_kst | 호출 발생 시각 |
| eventName / eventSource | event_name / event_source | 요청 API와 서비스 |
| sourceIPAddress | source_ip | 서비스가 관찰한 호출 출발지 |
| userIdentity.type | identity_type | AssumedRole 등 인증 유형 |
| userIdentity.arn | principal, session_name | 세션 ARN과 마지막 경로 성분 |
| userIdentity.accessKeyId | access_key_id | 임시 자격증명의 식별자; 비밀 값 아님 |
| userIdentity.sessionContext.sessionIssuer.userName | role | 세션을 발급한 역할 |
| userIdentity.sessionContext.attributes.creationDate | session_created_at | 세션 발급 시각 |
| requestParameters.bucketName / key | bucket / object_key | 요청한 버킷과 객체 |
| errorCode | error_code | 없는 필드는 분석 표에서 빈 문자열 |

여기서 `session_name`은 EC2 인스턴스 ID지만 모든 AWS 역할 세션이 이런 이름을 갖는 것은 아니다. 역할이 같아도 세션·키가 같지는 않다. EC2 세션의 `mfaAuthenticated=false`를 사람의 콘솔 MFA 미사용으로 해석하지 않는다. [주체 필드](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-event-reference-user-identity.html)

`responseElements`가 null일 수 있다. 실패 여부는 errorCode 및 서비스 측 증거와 함께 해석한다. 오류 없는 GetObject도 HTTP 상태·전송량은 S3 로그에서 교차 확인한다. [CloudTrail 이벤트 필드](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-event-reference-record-contents.html)

## 웹: web.jsonl

ALB 뒤 애플리케이션의 구조화된 접근 기록을 모델링했다. ALB 원본 액세스 로그 형식은 아니다.

| 열 | 의미 |
|---|---|
| instance_id | 실제 처리한 인스턴스 |
| request_id | 요청 및 실행 맥락을 연결하는 애플리케이션 추적 ID |
| client_ip | 신뢰하는 ALB에서 전달받은 원래 클라이언트 주소 |
| method, path | HTTP 동작과 경로; 요청 본문은 수집하지 않음 |
| status | HTTP 응답 상태; 500은 서버 오류이며 침해 성공 판정이 아님 |
| response_bytes, duration_ms | 응답 크기와 처리 시간 |

대량 오류는 승인된 부하 시험에서도 발생한다. request_id를 확인하기 전 서로 가까운 시각의 모든 웹·호스트 사건을 같은 요청으로 묶지 않는다.

## 호스트: host.jsonl

엔드포인트 관찰과 애플리케이션 추적 연계를 정규화한 교육용 스키마다. Linux auditd 원문 그대로가 아니며, 실제 환경에서는 EDR/eBPF·앱 추적 연동이 있어야 request_id가 붙을 수 있다.

| 열 | 의미 |
|---|---|
| event | process_start, metadata_access, network_connect, user_schedule_registered, service_heartbeat 등 |
| process / parent_process | 관찰 프로세스와 부모 이름 |
| pid / ppid | 해당 인스턴스·시각의 PID 관계; PID는 재사용될 수 있음 |
| user | 실행 계정; 프로세스 이름과 별개 |
| request_id | 연계 가능한 앱 요청. 로컬 점검은 빈 값 |
| detail | 관찰 설명. 실행 가능한 전체 명령·공격 입력은 제외 |
| metadata_category, http_status | 수집기가 분류한 메타데이터 접근과 응답 상태. 내용·토큰·구체 URL 없음 |
| destination_ip, destination_port | 호스트가 관찰한 연결 목적지 |
| task_name, scope | 예약 작업 등록 대상과 범위. 실행 내용·실행 성공 여부는 제공하지 않음 |

메타데이터 접근은 정상 에이전트에서도 발생한다. 작업 등록 기록은 등록의 증거이며 실제 작업 실행·root 권한 획득의 증거와 구분한다.

## 네트워크: vpc_flow.jsonl

VPC Flow Logs 필드를 참고한 JSON 정규화본이다. `record_id`, `time`은 교육용 내보내기에 추가했다.

| 열 | 의미 |
|---|---|
| interface-id | 관찰 ENI; assets의 eni로 인스턴스와 연결 |
| srcaddr, dstaddr, srcport, dstport, protocol | 관찰된 연결 식별 정보 |
| start, end | 흐름 집계의 시작·종료 Unix 초 |
| flow-direction | ENI 기준 ingress / egress |
| action | ACCEPT / REJECT. 애플리케이션 성공 여부가 아님 |
| bytes, packets | 관찰 네트워크 전송량. S3 객체 크기와 같은 지표가 아님 |
| log-status | 제공 기록은 OK |

초기/추가 자료 분리는 이벤트 시작 시각 기준이므로 흐름의 end가 경계를 조금 넘을 수 있다. `srcaddr`의 사설 주소와 CloudTrail의 NAT 주소가 다른 것은 정상이다. 메타데이터 서비스 접속은 이 묶음에서 호스트 텔레메트리로만 관찰한다. 외부 장치가 AWS API에 직접 요청한 트래픽은 피해 인스턴스 ENI에 나타나지 않는다. [AWS Flow Logs 필드](https://docs.aws.amazon.com/vpc/latest/userguide/flow-log-records.html)

## S3: s3_access.jsonl

S3 서버 접근 로그의 관련 필드를 정규화했다. 원래 공백 구분 원문을 그대로 내보낸 것은 아니다.

| 열 | 의미 |
|---|---|
| request_id | 개별 S3 요청 ID; CloudTrail requestID와 연결 |
| requester | 요청 주체의 역할 세션 ARN |
| bucket, key | 요청 대상 |
| remote_ip | 서비스가 관찰한 출발지 |
| operation | 이 자료는 REST.GET.OBJECT |
| http_status, error_code | 성공·실패 결과 |
| bytes_sent | 서버가 해당 응답으로 반환한 바이트. 오류 응답 본문도 있을 수 있음 |
| object_size | 객체 전체 크기; 실패해도 모형에 메타데이터가 남을 수 있음 |

실습의 확인된 전체 객체 응답은 HTTP 200으로 한정한다. 실패 응답의 bytes_sent를 피해 데이터로 더하지 않는다. 같은 객체를 새 request_id로 다시 반환하면 전송량에는 다시 더하고 고유 객체 수에는 한 번만 센다. S3 접근 로그의 실제 전달은 best effort이며, 운영 환경에서는 누락·지연을 점검해야 한다. [S3 로그 형식](https://docs.aws.amazon.com/AmazonS3/latest/userguide/LogFormat.html)

## 인증·상태·맥락

- `auth.jsonl`: 정규화한 SSH 인증 기록. 네트워크에서 REJECT된 스캔은 sshd까지 도착하지 않으므로 인증 실패 행을 임의로 만들어 연결하지 않는다.
- `logging_status.jsonl`: 조사팀의 독립적인 로깅 설정·수집기 상태 스냅샷. CloudTrail API 이벤트는 아니다.
- `assets.json`: 조사 시작 시점 자산·역할·ENI·승인 NAT 주소.
- `change_calendar.json`: 승인된 업무 변경. 승인이 없는 행위가 자동으로 공격이 되는 것은 아니다.
- `expected_sources.json`: 역할별 승인 출발지. 짧은 기준선에서 처음 본 주소와 같은 개념이 아니다.
- `permission_review.json`: 조사팀의 가상 유효 권한 검토 요약. 업무상 필요한 prefix와 실제 허용 prefix, 출발지 제한 여부를 비교한다. AWS 정책 원문이나 모든 계정 권한의 분석 결과는 아니다. 승인 IP 목록과 실제 IAM 조건은 구분한다.
- `object_catalog.json`: 객체 분류·크기·소유 부서. 실제 파일 내용·고객 행은 없다.
- `collection_scope.json`: 관찰 시각, 출처, 가정, 한계.
- `followup/response_actions.json`: 대응팀 작업 기록. 실제 AWS 변경을 실행하지 않는다.
- `followup/recovery_validation.json`: 교체 서비스의 기능·권한 확인 결과. 모든 영속화 수단을 검사했다는 보증은 아니다.

## 결론의 한계

반환된 객체·바이트와 관찰된 주체는 집계할 수 있다. 실제 사람이 누구인지, 특정 취약 입력이 무엇인지, 압축 파일 안의 피해 인원 수, 수신자의 저장·재배포 여부, 관찰 기간 밖의 추가 행위는 이 자료만으로 확정할 수 없다. 로그가 더 이상 없다는 사실을 전 세계 어디에도 침해가 없다는 의미로 확대하지 않는다.
