# HC-2026-0715 — 새벽항로

## 당신의 역할

가상의 전자상거래 서비스 HarborCart의 보안 담당자다. 문서 미리보기 서비스의 야간 이상 징후를 접수했다. 경보만 전달하는 대신, 서비스 담당자와 경영진이 조치할 수 있는 사건 결론을 만들어야 한다.

2026-07-15 01:32 KST, 문서 미리보기 오류와 인스턴스 역할의 낯선 네트워크 사용 경보가 접수되었다. 먼저 살펴볼 인스턴스는 `render-01`이다. 범인·침해 방법·피해 규모는 아직 확정하지 않았다.

## 업무 환경

- AWS의 한 가상 계정과 싱가포르 리전으로 범위를 제한한다.
- ALB 뒤의 `render-01`, `render-02`가 문서를 미리보기 이미지로 처리한다.
- 두 인스턴스는 `HarborRenderRole`을 공유하지만 인스턴스 세션과 임시 키는 다르다.
- `backup-01`, `build-01`, `bastion-01`은 정상 배치·빌드·운영을 수행한다.
- 외부로 나가는 인스턴스 API 요청은 NAT 공인 주소로 관찰된다. 승인 주소는 자산·역할별 목록에 있다.
- CloudTrail 관리 이벤트와 지정 S3 버킷의 객체 읽기 데이터 이벤트를 수집하고 있다. S3 서버 접근 로그와 호스트 실행 기록도 제공한다.

CloudTrail·S3·호스트·웹·네트워크 기록은 각각 다른 사실을 설명한다. 한 종류의 로그만으로 전체 침해를 설명하려고 하지 않는다.

## 첫 자료와 추가 자료

초기 로그는 2026-07-12 00:00 UTC부터 2026-07-14 16:40 UTC까지의 이벤트를 제공한다. 비교 기준선은 2026-07-14 00:00 UTC 이전이다. 이후 18:00 UTC까지의 추가 이벤트와 대응 기록은 초기 가설·피해·대응 제안을 작성한 뒤 연다. 전체 자료는 수집 지연을 기다린 후 내보낸 사후 조사 묶음이다.

## 해결해야 할 질문

1. 웹 오류·네트워크 스캔·프로세스 실행 중 무엇이 사건의 근거인가?
2. 인스턴스에서 어떤 행위가 이어졌고, 어디까지 직접 관찰되는가?
3. 같은 역할을 쓰는 인스턴스들을 어떤 식별자로 구분할 것인가?
4. 어떤 객체가 실제로 반환되었으며 재시도·수집 중복을 어떻게 셀 것인가?
5. 시도만 있었던 행위와 성공한 행위를 구별할 수 있는가?
6. 초기 대응 이후에도 영향 범위가 늘었는가?
7. 어떤 범위에서 대응 효과를 확인했고 무엇이 아직 불확실한가?

## 실제 사례와의 관계

Sysdig가 2023년 공개한 SCARLETEEL 조사에서는 워크로드 침해가 클라우드 권한 악용과 데이터 탈취로 이어졌다. 여기서는 그 연결 관점을 참고해 새 사건을 만들었다. 실제 보고서의 로그·피해 수량·고객 정보·공격 입력을 복제하지 않았다. [공개 조사](https://www.sysdig.com/blog/cloud-breach-terraform-data-theft)

이 자료의 회사·주소·식별자·시간·객체는 가상이다. 승인 변경과 수집 범위도 교육용으로 설정했다. 공격을 실행하거나 외부 서비스에 접속하는 단계는 없다.
