# 04. 저장장치 수집과 분석

출처: 로컬 `LECTURE NOTES/(PLB#4) 저장장치 수집과 분석.pdf`, 26쪽.

## 1. 복제와 이미징 (p.4-12)

| 구분 | 출력 | 특징 |
|---|---|---|
| 복제 | 다른 저장장치 | 원본 섹터를 대상 장치에 복사, 대상 크기·초기화 고려 |
| 이미징 | 이미지 파일 | 공유·분할·압축·검증과 분석 사본 관리에 유리 |

물리 이미징은 장치 전체, 볼륨 이미징은 선택한 볼륨을 대상으로 한다. 논리 수집은 선택한 파일·디렉터리를 대상으로 한다. 삭제 데이터가 항상 복구되는 것은 아니며 덮어쓰기·TRIM·암호화·수집 범위에 영향을 받는다.

연결 방식은 로컬과 원격으로, 수집 환경은 라이브·부팅 매체·오프라인으로 구분해 생각한다. RAID·LVM·동적 디스크는 구조를 기록하고 재구성 가능한 수집 단위를 선택한다. 원격 이미징은 네트워크와 서비스 부하를 고려해야 한다.

## 2. 증거 형식 (p.14-21)

| 형식 | 대상·특징 | 확인할 점 |
|---|---|---|
| RAW/dd | 섹터 데이터의 단순 파일 | 별도 해시·수집 기록, 분할 여부 |
| E01/Ex01 | EWF 증거 컨테이너 | 사용 형식의 압축·암호화·검증 및 도구 호환성 |
| AFF4 | 블록·스트림 기반 증거 형식 | 수집·분석 도구가 지원하는 기능 |
| ZIP/RAR/TAR | 선택 파일의 아카이브 | 실제로 보존되는 시간·권한·메타데이터 |
| AFF4-L, AD1, L01/Lx01 | 논리 증거 형식 | 생성 도구와 분석 도구의 호환성 |

교안은 RAW의 자체 압축·보호 기능 부재, FAT32의 파일 크기 제약, EWF의 블록 검증, AFF4의 유연한 수집을 설명한다. 교안에 적힌 특정 제품의 지원 여부를 모든 버전에 동일하게 적용하지 않는다. 일반 압축 파일을 만들었다고 모든 원본 메타데이터가 보존됐다고 가정하지 않는다.

## 3. 무결성 검증과 관리연속성 (p.23-25)

검증은 수집 과정의 기준 해시와 저장된 증거 데이터를 다시 읽어 계산한 해시를 비교하는 작업이다. 쓰기 오류나 매체 손상 때문에 수집 완료 후에도 재검증이 필요하다. 사본을 추가 생성한 경우에도 확인한다.

논리 수집에서는 컨테이너 전체 해시와 개별 파일 해시의 용도가 다르다. 증거 형식 내부의 데이터 검증값과 컨테이너 파일 자체의 해시를 혼동하지 않는다.

CoC(Chain of Custody)는 증거의 수집·이동·보관·접근·분석 과정에 대한 기록이다. 최소 기록 항목은 증거 식별자, 대상·범위, 담당자, 시각·시간대, 도구·버전, 해시 알고리즘·값, 검증 결과, 전달·보관 이력이다.

## 4. 실습: FTK Imager로 USB 이미지 생성·검증 (p.26)

교안 과제는 USB의 물리이미지를 만들고 검증하는 것이다. 아래 절차는 과제를 수행할 때의 정리이며 이 저장소에서 완료 확인된 결과는 아니다.

1. 실습 USB의 장치 식별 정보·용량을 확인한다.
2. 원본과 다른 저장 위치를 준비하고 원본에 쓰지 않도록 구성한다.
3. FTK Imager의 이미지 생성 기능에서 물리 드라이브와 해당 USB를 선택한다.
4. 증거 정보, 출력 형식·경로·분할 크기를 기록한다.
5. 이미지를 생성하고 도구의 검증 기능으로 저장된 데이터를 재검증한다.
6. 로그의 오류·해시·검증 결과를 기록한다.
7. 분석 사본을 열어 파티션과 파일 목록을 확인한다.

성공 판단은 이미지 파일 존재, 도구의 검증 성공, 읽기 오류 확인, 이미지 열기 확인을 함께 사용한다. 현재 FTK 이미징·검증 완료 로그는 확인되지 않았다.

## 5. 현재 파일과의 관계

`ARTIFACT/METADATA/$MFT`, `$LogFile`, `$J`는 선별된 파일시스템 메타데이터다. 이 세 파일만으로 USB 전체 이미지 생성 과제를 완료했다고 볼 수 없다. `DATA/MFT.csv`는 메타데이터 분석 결과 형식이며 저장장치 원본 이미지와 구별된다.
