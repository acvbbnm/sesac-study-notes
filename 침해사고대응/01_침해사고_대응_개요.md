# 01. 침해사고 대응 개요

출처: 로컬 `LECTURE NOTES/(PLB#1) 침해사고 대응 개요.pdf`, 70쪽.

## 1. 사이버 위협 모델 (p.3-13)

공격을 개별 악성 파일이 아니라 일련의 행위로 이해해야 최초 침투, 실행, 지속성, 전파와 피해를 연결할 수 있다.

| 모델 | 핵심 | 분석에 활용하는 방법 |
|---|---|---|
| Cyber Kill Chain | 정찰 → 무기화 → 전달 → 취약점 악용 → 설치 → C2 → 목적 수행 | 공격 흐름 중 발견한 흔적의 위치 파악 |
| Mandiant Targeted Attack Lifecycle | 최초 침투와 거점 확보 이후 권한 상승·내부 정찰·지속성·내부 이동이 반복 | 침입 이후 공격자가 여러 호스트에서 활동했는지 조사 |
| MITRE ATT&CK | 실제 관찰된 공격 행위를 전술·기법·하위 기법으로 분류 | 증거와 행위 연결, 탐지 규칙과 보고서의 공통 용어 |

전술은 공격의 목적, 기법은 그 목적을 달성하는 방법, 절차는 실제 사건에서 사용한 구체적 구현이다. 단계 모델만으로는 세부 탐지 설계를 설명하기 어렵고, IOC만으로는 변경되는 공격 인프라를 따라가기 어렵다는 것이 교안의 요점이다.

### 호스트 분석에서 던질 질문

| 관점 | 조사 질문 | 연결할 자료 예시 |
|---|---|---|
| Initial Access | 최초 진입 경로가 무엇인가? | 브라우저 다운로드, 원격 접속·로그온 기록 |
| Execution | 무엇을 언제 실행했는가? | 프로세스, Prefetch, 실행 관련 이벤트 |
| Persistence | 재부팅 후 접근을 어떻게 유지했는가? | Run 키, 서비스, 예약 작업, WMI |
| Credential Access | 인증정보 접근 흔적이 있는가? | 프로세스·메모리·보안 이벤트 |
| Lateral Movement | 어떤 다른 호스트까지 접근했는가? | RDP·SMB·원격 서비스 기록 |
| Collection / Exfiltration | 무엇을 모았고 실제 반출했는가? | 파일 생성, 압축 흔적, 전송·네트워크 자료 |
| Impact | 암호화·삭제·서비스 장애 등 피해가 무엇인가? | 변경된 파일, 서비스·장애 로그 |

교안 p.10의 전술 목록은 15개이며 Stealth와 Defense Impairment를 포함한다. 이 수치는 교안의 분류로 읽고, 버전이 다른 ATT&CK 자료와 섞어 고정된 개수로 암기하지 않는다.

## 2. 위협 동향을 읽는 방법 (p.14-52)

교안은 M-TRENDS 2026의 조사 사례를 이용해 산업별 피해, 초기 침투 경로, 탐지 주체, 잠복 기간, 악성코드, 랜섬웨어, 클라우드, ATT&CK 행위를 설명한다. 통계는 조사된 사건 집단의 특성이며 모든 조직의 발생 확률을 뜻하지 않는다.

교안 도표에서 확인한 대표 수치:

| 항목 | 교안 표시 | 학습 포인트 |
|---|---|---|
| 전체 초기 침투 경로(p.17) | Exploit 32%, Voice Phishing 11%, Prior Compromise 10%, Stolen Credentials 9% | 취약점뿐 아니라 기존 침해·계정·사회공학도 조사 |
| 전체 잠복 기간 중앙값(p.21) | 2025년 14일 | 최초 침투 시점과 탐지 시점을 구분 |
| 랜섬웨어 초기 경로(p.31) | 기존 침해 30%, Exploit 27%, Brute Force 20% | 암호화 직전만 보지 말고 이전 침입 이력 추적 |
| 클라우드 초기 경로(p.34) | Voice Phishing 23%, Third-Party Compromise 17%, Stolen Credentials 16% | 계정·외부 연결 관계까지 범위 확대 |

Dwell Time은 최초 침투부터 인지까지의 기간이다. 파일 생성 시각 하나를 최초 침투 시각으로 대체하면 안 된다.

악성코드는 기능에 따라 Backdoor, Credential Stealer, Data Miner, Downloader, Dropper, Launcher, Ransomware, Tunneler, Utility 등으로 구분한다(p.27-29). 한 사건에 여러 기능이 연쇄적으로 등장할 수 있으므로 파일명보다 실행·통신·지속 행위를 함께 본다.

## 3. IOC와 IOA (p.53-59)

| 구분 | IOC: 침해지표 | IOA: 공격지표 |
|---|---|---|
| 초점 | 특정 침해와 연결되는 관찰값 | 공격 의도와 행위 패턴 |
| 예 | 파일 해시, 도메인, IP, 서비스명 | 인증 시도 패턴, 지속성 생성, 내부 이동, C2 행위 |
| 장점 | 검색·비교·차단이 빠름 | 인프라 변경 후에도 행위 중심 탐지 가능 |
| 한계 | 공격자가 쉽게 변경 가능 | 정상 관리 행위와 구별할 맥락 필요 |

예를 들어 의심 파일 해시로 다른 호스트를 검색하고, 해당 파일이 예약 작업을 등록한 사실을 확인했다면 예약 작업 생성이라는 행위까지 탐지 대상으로 확장한다. IP나 프로세스 이름 하나만으로 악성 여부를 확정하지 않는다.

## 4. 대응 절차 (p.60-70)

교안은 여러 기관의 대응 모델을 비교한 후 준비 → 사고 처리 → 사후 대응의 큰 흐름으로 정리한다.

| 단계 | 해야 할 일 | 남길 기록 |
|---|---|---|
| 준비 | 인력·도구·체크리스트·역할 확보 | 연락망, 도구 검증, 수집 절차 |
| 등록 | 사고 여부 판단과 공식 접수 | 최초 신고, 영향 자산, 인지 시각 |
| 트리아지 | 범위·영향을 추정하고 증거 확보 | 대상 목록, 수집 목록, 대응 전략 |
| 완화 | 확산 위험 축소, 필요 시스템 격리 | 조치 대상·시각·영향 |
| 분석 | 원인, 구체적 피해, 잔존 위협 조사 | 증거 연결과 공격 타임라인 |
| 재발 방지 | 원인 보완과 TTP 감시 | 설정 개선, 탐지 규칙, 점검 항목 |
| 복구 | 데이터·시스템·업무 정상화 | 복구 범위, 검증 결과 |
| 사후 활동 | 사고 후 분석, 모니터링, 이행 점검, 증거 보존 | 개선 담당자·기한·보존 기록 |
| 사고 학습 | 팀 전체 경험 공유와 대응 과정 평가 | 강평과 절차 개선 |

트리아지는 초기 범위 추정, 피해 분석은 구체적 피해 규명이다. 복구 이후에도 대체 접근 경로가 남아 있는지 확인해야 한다.

## 5. 실습 보고서에 적용

1. 인지 시점과 관찰 증상을 먼저 적는다.
2. 수집한 파일, 수집 시각, 대상 환경과 분석 도구를 기록한다.
3. 의심 행위를 실행 → 지속성 → 유입·전파 순으로 연결한다.
4. 관찰 사실, 해석, 추가 확인이 필요한 항목을 구분한다.
5. 원인·피해·잔존 위협·복구·재발 방지를 각각 적는다.
