# 02. 라이브 데이터 수집과 분석

출처: 로컬 `LECTURE NOTES/(PLB#2) 라이브 데이터 수집과 분석.pdf`, 44쪽.

## 1. 현장 대응 결정 (p.4-10)

라이브 대응은 동작 중인 시스템에서 현재 상태를 수집하는 작업이다. 전원을 끄기 어려운 서버, 활성 연결·프로세스·메모리가 중요한 상황에서 사용한다. 오프라인 대응은 종료·격리가 가능하거나 전체 저장장치와 삭제 데이터 분석이 필요한 상황에 대응한다.

수집 전에는 재부팅 이력, 전원 종료 가능 여부, 서비스 영향, 메모리의 의미, 선별 수집과 전체 이미징 중 필요한 범위를 판단한다. 시스템 시간과 기준 시간의 차이, 디스크·볼륨 구성, 현장 인터뷰도 함께 기록한다. 수집 자체가 시스템 상태를 바꾸므로 준비된 도구를 사용하고 실행 과정을 남긴다.

## 2. 활성·비활성 데이터와 수집 순서 (p.11-21, 25-30)

| 종류 | 수집 항목 | 분석 목적 |
|---|---|---|
| 활성 | 네트워크 연결, ARP, 라우팅, 프로세스, 세션, 열린 파일 | 현재 동작과 연결 관계 |
| 메모리 | 물리메모리 또는 필요 시 프로세스 메모리 | 디스크에 남지 않는 실행 흔적 등 |
| 비활성 | MFT, 파일시스템 저널, 이벤트, 레지스트리, Prefetch, 브라우저 | 과거 실행·접근·지속성 재구성 |

OOV(Order of Volatility)는 빨리 사라지는 증거를 우선 확보하려는 원칙이다. 교안 p.21도 여러 수집 순서를 비교한다. 네트워크·메모리·프로세스·로그온 정보를 우선 검토하되 사고 상태와 수집 영향에 따라 계획한다.

## 3. 실습 A: Windows 기본 명령 수집 (p.22)

교안 과제는 다음 명령의 출력을 배치 파일로 저장하는 것이다.

| 명령 | 확보 정보 | 분석 시 연결할 대상 |
|---|---|---|
| `arp -a` | ARP 캐시 | 최근 로컬 네트워크 통신 후보 |
| `netstat -nao` | 연결·포트·PID | 프로세스 목록의 PID |
| `route PRINT` | 라우팅 테이블 | 통신 경로·게이트웨이 |
| `net file` | 서버 측 열린 공유 파일 | 원격 파일 접근 |
| `net share` | 공유 리소스 | 전파·공유 범위 |
| `net user` | 로컬 사용자 목록 | 로그온·실행 계정 |
| `tasklist /V` | 상세 프로세스 목록 | PID·계정·실행 이름 |
| `ipconfig /all` | 인터페이스 구성 | IP·DNS·DHCP 설정 |

아래는 교안 과제를 정리한 **재현용 예시**이며 실제 수행 결과가 아니다. 실습 VM에서 실행하며, 결과 디렉터리가 기존 파일과 겹치지 않도록 정한다.

```bat
@echo off
set "TARGET_DIR=%~dp0IR_LIVE_NEW"
if exist "%TARGET_DIR%" exit /b 1
mkdir "%TARGET_DIR%"
arp -a > "%TARGET_DIR%\arp.txt" 2>&1
netstat -nao > "%TARGET_DIR%\netstat.txt" 2>&1
route PRINT > "%TARGET_DIR%\route.txt" 2>&1
net file > "%TARGET_DIR%\net_file.txt" 2>&1
net share > "%TARGET_DIR%\net_share.txt" 2>&1
net user > "%TARGET_DIR%\net_user.txt" 2>&1
tasklist /V > "%TARGET_DIR%\tasklist.txt" 2>&1
ipconfig /all > "%TARGET_DIR%\ipconfig.txt" 2>&1
```

교안은 사전에 준비한 명령 도구 사용을 강조한다. 위 예시는 시스템 명령 호출 형태이므로 현장 키트로 사용하려면 검증한 도구 경로를 별도로 지정한다. 빈 파일·접근 거부·명령 실패도 확인하며 파일 생성만으로 수집 성공이라 판단하지 않는다.

## 4. 실습 B: 써드파티 도구와 메모리 (p.23-24)

| 도구 | 교안의 수집 목적 |
|---|---|
| cprocess, pslist | 프로세스 상세 정보 |
| cports | 열린 포트와 프로세스 연결 |
| wifihistoryview, winlogonview | 무선 연결·로그온 이력 |
| lastactivityview, executedprogramslist | 시스템 활동·실행 흔적 |
| opensavefilesview | 열기·저장 대화상자 흔적 |
| browsinghistoryview | 브라우저 방문 기록 |
| WinPmem | 물리메모리 이미지 |

교안에는 `/stext`, `/scomma` 형식의 내보내기와 `winpmem_mini_x64_rc2.exe memory.raw` 예시가 있다. 도구별 출력 파일 인자와 지원 옵션은 배포 버전에서 확인한다. 메모리는 일반 파일 목록이나 프로세스 목록으로 대체되지 않는다.

## 5. 실습 C: BITLive 수집 (p.31-39)

1. 대상 OS에 맞게 준비한 키트의 명령 프롬프트를 관리자 권한으로 연다.
2. 교안의 `BITLive_win.bat`을 실행하고 메모리·비활성 수집 범위를 선택한다.
3. 네트워크, 프로세스, 로그온 사용자, 인터페이스, 시스템, 기타 항목의 출력과 로그를 확인한다.
4. 비활성 자료의 Prefetch, Amcache, MFT, 레지스트리, 이벤트, LNK·Jumplist, 브라우저, WER 등을 점검한다.
5. 수집 시작·종료 시각, 실패 항목과 수집 옵션을 기록한다.

교안 p.36은 저장된 인증정보 수집 도구도 소개한다. 이는 수집 범위를 이해하기 위한 내용이며 이 문서에는 실제 인증정보를 포함하지 않는다.

## 6. 실습 D: 라이브 사례 분석 (p.40-44)

1. 정상 프로세스의 부모·경로·계정과 비교해 조사할 프로세스를 고른다.
2. PID를 기준으로 `netstat`, cports, 프로세스 목록을 연결한다.
3. 명령행, 부모·자식, 서비스, 로드 DLL, 열린 파일을 확인한다.
4. 실행 경로·파일명을 Prefetch, MFT, 이벤트와 대조한다.
5. 예약 작업·서비스·자동실행 등록을 확인해 지속성을 조사한다.
6. 브라우저·다운로드·로그온·원격 접근 이력에서 유입과 전파를 조사한다.

현재 악성 프로세스가 없더라도 과거 감염을 배제할 수 없다. 수집 시점 차이에 따른 PID 재사용과 종료된 연결에도 주의한다. 프로세스 이름의 유사성만으로 악성이라고 결론내리지 않는다.

## 7. 현재 자료 확인

- `../test/live/live.bat`, `DATA/live.bat`: 수집 명령을 채워 넣는 템플릿. 완성된 자동 수집 스크립트로 볼 수 없다.
- `DATA/LIVE CASE #1/LIVE CASE #1/`: FPLive 수집 로그와 분석 자료 존재.
- `DATA/LIVE_RESPONSE_01/`: BITLive 수집 로그, 활성 75개·비활성 195개 파일 존재.
- 위 로그는 2013년·2023년의 교육용 사례 기록이다. 사용자의 현재 수업 수행 시각을 뜻하지 않는다.
