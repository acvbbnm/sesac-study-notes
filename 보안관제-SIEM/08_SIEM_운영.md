# 08. SIEM 운영

---

## 1. SIEM 구성요소

### Manager
- 경보·감사 데이터 발생 시 다양한 알람 처리 (Sound, Email, SMS, 스크립트, SNMP)
- 감사 데이터 및 설정 데이터 저장을 위한 DB 백업·삭제 스케줄링 처리
- 모든 자체 감사 데이터 생성 및 DB 저장

### Console
- 사용자 및 에이전트 그룹 관리
- 구성관리, 수집조건, 연관성 분석, DB 백업·삭제 관리 등 모든 설정 화면 제공

### Agent
- 관리 대상 장비에서 수집한 로그를 정해진 규칙에 따라 **정규화**
- 수집조건 규칙과 비교 → Manager 전송 여부 결정
- 동일 패턴 이벤트는 **축약 처리** → 네트워크·DB 부하 최소화

### 구성도

```
침입차단 이벤트 ─┐
침입탐지 이벤트 ─┤ [Agent] ──SSL 통신──→ [Manager] ──→ [Console]
Virus 이벤트  ─┤               (데이터 수집·판단)    (감시자/리포팅/분석)
기타 이벤트   ─┘                    │
                               [데이터베이스]
                                         ↘ 알림 경보 (Email/SMS)
```

## 2. 로그와 파싱

### 로그 (Log)
컴퓨터나 서버에서 사용자의 행위 정보를 **시간에 따라 기록**한 데이터.

### 파싱 (Parsing)
원본 로그를 **필드 별로 구분**하는 작업.

```
원본 로그 (Raw):
duration=3 machine_name=FW1 src_ip=10.20.30.149 src_port=53209 dst_ip=192.168.100.100 ...

파싱 후:
┌────────────┬──────────────────┐
│ duration   │ 3                │
│ machine    │ FW1              │
│ src_ip     │ 10.20.30.149     │
│ src_port   │ 53209            │
│ dst_ip     │ 192.168.100.100  │
│ dst_port   │ 80               │
│ protocol   │ TCP              │
└────────────┴──────────────────┘
```

## 3. 이벤트 검색

### 검색 경로
```
SIEM → 보안관제 탭 → 통합 로그 검색
```

### 검색 조건 설정
- **로그유형 탭 선택**: Firewall, IPS, UTM, WebFW 등
- **로그 소스 탭 선택**: 실제 이벤트가 수집되는 Agent 장비 선택
- **Query 조건 설정**: 시간 / 출발지 IP / 목적지 IP / 출발지 Port / 목적지 Port / Method

## 4. 이상 그래프 확인

연동된 각 보안장비에 대해 일일 그래프 또는 30분별 그래프를 생성하여 이벤트 수치를 시각적으로 확인.

### 이상 그래프 탐지 시 확인 절차
```
① 검색할 Agent 선택
② 30분 / 일일 / 30분 경보 등 원하는 그래프 선택
③ 로그 소스 유형 선택 (FW, IPS, WebFW 등)
④ 적용

→ 이벤트 급증 구간 클릭
→ 해당 시간대의 상세 로그 확인
   (시간 / 로그소스IP / 로그소스명 / Source IP / Destination IP / Port 등)
```

### 그래프 프로파일 저장 및 불러오기
- 장비별 그래프를 **프로파일**로 저장 → 매번 새로 생성할 필요 없이 빠르게 관제
- 프로파일 열기: 우측 상단 탭 → 프로파일 목록에서 선택
- 프로파일 삭제: 리스트에서 삭제할 프로파일 선택 → X 버튼 클릭

## 5. 번들룰 (Bundle Rule)

가용성 체크를 위한 경보. 장비 장애로 인한 이벤트 미수집, 펌웨어 업데이트로 인한 필드 변경 시 미수집 등 탐지.

| 종류 | 설명 |
|------|------|
| **핑 체크** | 주기적으로 대상 장비에 Ping 전송 → 실패 시 경보 발생 |
| **프로세스 체크** | 대상 프로세스 동작 여부 주기 확인 |
| **미수집 체크** | 일정 시간 동안 로그가 수집되지 않을 경우 경보 |

## 6. 단일경보 생성

특정 조건(Object)이 충족될 때 경보를 발생시키는 가장 기본 단위의 경보.

### 생성 과정

```
① 장비에서 발생하는 이벤트가 SIEM에 어떤 식으로 수집되는지 확인
   → 통합 로그 검색에서 조건에 맞는 Query 입력 후 검색

② 탐지할 Column 선택
   (주의: Stealth Commanding 같은 문자열이 RAW에는 있지만 다른 Column에는 없을 수 있음
    → 장비별 수집 방식을 먼저 파악해야 함)

③ Object 생성
   → 필드명·연산자(AND/OR/Like)·값 입력 → '+' 버튼 클릭 → 오브젝트 그룹 지정 → 이름 설정 → 생성/수정

④ 경보 설정
   → 룰 이름 / 발생 주기(분) / 발생 건수 설정
   → 로그 소스 선택
   → Object 추가 → 등록

⑤ 제외 조건 설정 (오탐 감소)
   → 고객사 요청 IP, Google IP 등 특정 출발지 IP 제외 등록
```

**Object 이름 규칙 예시**
- `[WAF_Wapple]경보명`
- `[고객사_WAF]경보명`
- Object 그룹은 벤더사별 또는 고객사별로 구분하여 관리 용이하게 구성

**경보 설정 예시**
```
룰 이름: [WAF] Buffer Overflow 탐지
발생 주기: 1분
발생 건수: 1건
→ 1분에 해당 이벤트가 1건 발생하면 경보
```

## 7. 상관분석 (Correlation) 경보

단일 경보의 조합으로 생성. Step 별로 경보 단계가 진행되므로 고도화된 경보 생성에 적합.

### 특징
- 단일 경보를 기반으로 단계별 탐지 설정 가능
- 이기종 장비 간 연계 탐지 가능
- 1단계 탐지 로그 중에서 2단계를 통해 원하는 로그만 필터링

### 상관분석 응용 예시

**공격자 침투 시나리오 탐지**
```
Step 1: 방화벽 포트 스캔 탐지 (정보수집 단계)
Step 2: IPS/WAF 시그니처 기반 탐지 (침투·시스템 장악 단계)
```

**내부 사용자 비정상 행위 탐지**
```
Step 1: 내부 사용자 IP + 내부 서버 접근 탐지
Step 2: 업무 시간 외 특정 서버 접근 탐지 (비정상 행위)
```

---

## 8. 단일경보 vs 상관분석 비교

| 항목 | 단일경보 | 상관분석 |
|------|---------|---------|
| 조건 | 단일 이벤트 조건 충족 | 단일경보 여러 개의 조합 |
| 단계 | 1단계 | 다단계 (Step 1 → Step 2 → ...) |
| 활용 | 개별 장비의 특정 이벤트 탐지 | 복잡한 공격 시나리오, 이기종 연계 탐지 |
| 오탐 관리 | 제외 IP, 제외 조건 설정 | 단계별 필터링으로 정밀도 향상 |
