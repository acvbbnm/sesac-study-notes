# 02. 네트워크의 이해

## 1. OSI 7계층

| 계층 | 이름 | 설명 | 보안장비 |
|------|------|------|---------|
| 7 | Application (응용) | 응용 프로세스가 네트워크에 연결할 수 있도록 인터페이스 제공 | IPS, WAF |
| 6 | Presentation (표현) | 데이터 표현 차이 해결, 형식 변환 | - |
| 5 | Session (세션) | 응용 계층 간 연결 설정·유지·종료 | - |
| 4 | Transport (전송) | 컴퓨터 간 연결 설정·유지·종료 | IDS, 방화벽(TCP/UDP 차단) |
| 3 | Network (네트워크) | 라우팅 프로토콜로 최적 경로 선택 및 자료 전송 | 방화벽(IP 차단) |
| 2 | Data Link (데이터링크) | 물리 전송 링크를 통해 자료를 안전하게 전송 | - |
| 1 | Physical (물리) | 물리 링크의 전기적·기계적 규약 정의 | - |

## 2. 보안관제 네트워크 시나리오

```
공격자#1 ─┐
           ├→ [라우터] → [방화벽] → [IPS] → [IDS] → [스위치] → 내부망
공격자#2 ─┘
                                              ↑
                                          관제 요원 분석
                                    (공격 유효성 확인 후 방화벽 IP 차단)
```

1. 공격자가 내부 시스템 권한 획득 목적으로 공격 시도
2. 관제 요원이 보안장비(방화벽·IPS·IDS·WAF) 이벤트 분석
3. 공격 유효성 확인 → 방화벽에서 공격자 IP 차단
4. 탐지 이벤트에 대한 공격 설명 및 대응 조치를 보고서로 작성 → 담당자 통보

## 3. 네트워크 구성 방식

### In-line 모드 (일반적)

```
[라우터] → [방화벽] → [IPS] → [스위치] → [서버]
```

- 모든 트래픽이 보안장비를 반드시 통과
- 탐지 + **차단** 가능
- 요구 사항:
  - 빠른 패킷 처리 속도
  - 변종 패턴 검출 정확성
  - 장비 오류 시 **Bypass** 기능
  - 2대 이상 구성 시 **Fail-Over** 기능

### Sniffing 모드

```
[라우터] → [방화벽] → [스위치] → [서버]
                          ↓ (미러링)
                         [IDS]
```

- 미러링 장비를 통해 트래픽을 복사하여 분석
- **탐지만 가능**, 차단 기능 없음
- IDS 장비에서 주로 사용

### Out of Path 모드

```
[인터넷] → [라우터] → [미러링 장비] → [라우터] → [방화벽] → 내부망
                              ↓
                      [DDoS 탐지장비(센서)]
                              ↓
                      [DDoS 차단장비]
```

- 물리 회선 바깥에 탐지·차단 장비 설치
- 미러링으로 트래픽 분석 → 공격 차단
- Inline 방식보다 구성 복잡, 고비용
- ISP 및 대형 서비스 망에서 주로 사용 (DDoS 대응)

### HA (High Availability) 구성

**Active-Active 방식**
```
인터넷 ─┐        ┌─ 방화벽A ─┐
         ├─ L4 ─┤            ├─ 내부망
         │        └─ 방화벽B ─┘
         │   (한쪽 장애 시 Fail-Over)
```
- 트래픽 Load Balancing
- 한쪽 장애 시 Fail-Over로 서비스 가용성 보장

**Active-Standby 방식**
```
평상시: [방화벽A(Active)] ──→ 내부망
장애 시: [방화벽B(Standby)] ──→ 내부망
```
- 평소 Active 방화벽으로 통신
- Active 장애 시 Standby 자동 전환

## 4. Zone 개념

| Zone | 정의 |
|------|------|
| **내부망** | 물리적 망분리·접근통제시스템으로 외부 직접 접근이 차단되는 구간 |
| **DMZ** | 인터넷과 내부망 사이 중간 지점. 외부 서비스 제공 시 내부 보호 목적 |
| **인터넷 구간** | 개인정보처리시스템과 인터넷이 직접 연결된 구간 |

```
인터넷 → [방화벽] → DMZ 구간 (웹서버, 메일서버 등 대외 서비스)
                  └→ 내부망 (DB 서버, 내부 업무 시스템)
```

### Zone 간 통신 흐름

- 외부(Untrust) ↔ 내부(Trust): 방화벽에서 엄격히 통제
- 외부(Untrust) ↔ DMZ: 허용된 서비스 포트만 오픈
- 내부(Trust) ↔ DMZ: 내부에서 DMZ 접근은 상대적으로 허용

## 5. Health Check (가용성 모니터링)

**사용 도구**: NMS (Network Management System), Cacti

**프로토콜**: ICMP (Ping), SNMP

**동작 원리**
```
NMS/Cacti ──[Request]──→ [라우터] → [방화벽(Port Open 필요)] → 서버
          ←─[Response]──

(서버 다운 시 Response 없음 → 장애 감지)
```

> 방화벽에서 Health Check 패킷(ICMP, SNMP)이 통과할 수 있도록 필요한 포트를 사전에 오픈해야 함.
