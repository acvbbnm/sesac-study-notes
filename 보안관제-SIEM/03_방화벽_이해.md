# 03. 방화벽의 이해

---

## 1. 방화벽 정의

**Firewall**은 외부로부터 내부망을 보호하기 위한 네트워크 구성요소로, 외부의 불법침입으로부터 내부 정보자산을 보호하고 유해정보 유입을 차단하기 위한 **정책 + 하드웨어 + 소프트웨어**의 총칭.

- **효과**: 네트워크 출입로를 단일화하여 보안관리 범위를 좁히고 접근제어를 효과적으로 수행
- **원리**: 관리자가 사전 설정한 보안 규칙(ACL)에 따라 패킷을 허용 또는 차단
- **위치**: 내부 네트워크와 외부 네트워크(인터넷) 중간

```
인터넷 → [방화벽(접근제어 목록)] → 내부 네트워크
              ↑ 접근 허용 / 접근 차단
```

---

## 2. 방화벽 보안정책 4종

| 정책 | 방향 | 설명 |
|------|------|------|
| **Paranoid** | All Block | 모든 트래픽 차단 |
| **Prudent** | Any Open + Drop | 특정 트래픽 허용, 나머지 Drop |
| **Cautious** | Any Block + Allow | 특정 트래픽 차단, 나머지 Allow |
| **Promiscuous** | All Open | 모든 트래픽 허용 |

> 실무에서는 기본 정책을 **Any Drop** (Deny All)으로 설정하고, 필요한 트래픽만 허용하는 **Whitelist** 방식이 일반적.

---

## 3. 방화벽 NAT

**NAT (Network Address Translation)**: 사설 IP를 공인 IP로 변환하는 주소 변환 서비스.

**필요성**
- 공인 IP 주소 절약 (IPv4 고갈 문제)
- 보안 강화: 내부 사설 IP를 외부에서 직접 접근 불가

```
내부PC (192.168.1.x) → [방화벽/NAT] → 외부서버
                        101.89.1.12 (공인IP)
```

### NAT 종류 (Juniper 기준 4종)

| 종류 | 방향 | 동작방식 | 사용 시나리오 |
|------|------|---------|-------------|
| **PAT (N:1)** | 내→외 | 다수 사설IP → 공인IP 하나로 변환 | 일반적인 인터넷 접속 |
| **DIP (N:N)** | 내→외 | 특정 사설IP 대역 → 특정 공인IP 또는 대역 | IP 인증이 필요한 외부 서비스 접속 |
| **VIP (1:N)** | 외→내 | 공인IP 하나를 포트 번호에 따라 내부 서버로 분산 | 공인IP 1개, 내부 서버 2대 이상 |
| **MIP (1:1)** | 외→내 | 공인IP 하나 ↔ 내부 서버 1:1 매핑 | 다수의 공인IP 보유 시 각 서버에 1:1 할당 |

## 4. 방화벽 운영 모드

| 모드 | OSI 계층 | 특징 |
|------|---------|------|
| **Transparent Mode (L2)** | Layer 2 | Route·Switch 사이에서 Bridge로 구성. 장비에 Manage IP만 할당. IP 재설계 불필요 |
| **NAT Mode (L3)** | Layer 3 | 내부 사설IP 사용. Outbound 트래픽은 공인IP로 Source IP 변환. Routing Table 필요 |
| **Route Mode (L3)** | Layer 3 | 방화벽 하단 네트워크도 공인IP 사용. NAT 불필요. Routing Table 필요 |

## 5. 방화벽 정책 설정 순서 (우선순위)

방화벽은 기본적으로 **상위에서 하위로** 정책이 적용됨.

```
1. Block IP (P2P, 메신저 등 차단)
2. 방화벽 접근 룰 (ADMIN 권한)
3. Client 인증 및 VPN 접근 룰
4. 대외용 서비스 룰
5. 외부 접근 룰 (서버 접근 권한)
6. 내부에서 외부로 나가는 룰
7. Any Drop (기본 차단)
```

**주의사항**
- 방화벽에 대한 ICMP는 기본적으로 차단
- 방화벽 접근은 관리자 Client만 허용

## 6. 방화벽 로그 구성

```
duration=3
machine_name=IG_MAIN_FW1      ← 방화벽 장비 이름
fw_rule_id=538                 ← 방화벽 정책 ID
nat_rule_id=31                 ← NAT 정책 ID
src_ip=10.20.30.149            ← 출발지 IP
src_port=53209                 ← 출발지 PORT
dst_ip=192.168.100.100         ← 목적지 IP
dst_port=80                    ← 목적지 PORT
protocol=TCP                   ← 프로토콜
ingress_if=INT                 ← ZONE 정보
tx_packets=19                  ← 전송 패킷 수
rx_packets=19                  ← 수신 패킷 수
```

## 7. 방화벽 관리방안

방화벽은 네트워크 관문에서 오가는 패킷을 제어하므로 이상 발생 시 전체 피해 가능 → 효율적 관리 필수.

**정기 점검사항**
- 정기적인 룰 점검 (불필요한 룰 정리)
- 정기적인 로그 및 룰 백업
- 정기적인 로그 분석
- 방화벽 장애 시 대처방안 사전 준비 (Fail-Over 테스트)

---

## 8. 방화벽의 한계

방화벽을 우회하는 다양한 해킹 방법이 존재.

**한계점**
- VPN 등 일반적이지 않은 패킷 처리 한계
- 방화벽에서 허용한 경로(telnet, ftp 등)를 통한 취약점 공격 대응 어려움
- 물리적 보안, WWW, Mail을 이용한 해킹 대응 한계
- 허용된 포트(80, 443)를 통한 애플리케이션 레벨 공격은 방화벽으로 차단 불가

→ **IPS, WAF, IDS**와의 다층 방어(Defense in Depth) 필요
