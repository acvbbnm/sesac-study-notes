## 1. 가상화 인프라 (물리 계층)

### 구조: 물리 PC → VMware Workstation → ESXi → VM들

이 랩은 **Nested Virtualization(중첩 가상화)** 구조다.

```
물리 PC (Windows 11, i7-12700, RAM 16GB)
  └── VMware Workstation 17.6.0
        └── VMware ESXi 6.7.0 (가상 하이퍼바이저)
              ├── Vyos 라우터
              ├── pfSense 방화벽
              ├── Mng-Mint (관리 클라이언트)
              ├── Bee-box (취약 웹서버)
              ├── Ubuntu + Splunk (SIEM 서버)
              └── Att-Mint (공격자 클라이언트) ← 미설치
```

**왜 이렇게 하는가?**
- 실제 기업 환경에서는 물리 서버에 ESXi를 설치하고 VM을 운영함
- 학습 환경에서는 물리 서버가 없으므로, PC 위에 Workstation을 깔고 그 안에 ESXi를 넣어서 동일한 구조를 시뮬레이션
- ESXi가 제공하는 가상 스위치(vSwitch)를 이용해 네트워크 존을 분리

### ESXi 가상 스위치 (vSwitch)

물리 스위치 없이 **소프트웨어로 네트워크를 분리**하는 장치.
각 vSwitch는 독립된 네트워크 구간을 만든다.

| vSwitch 이름 | 네트워크 대역 | 용도 | 연결된 VM |
|-------------|------------|------|---------|
| VM Network | 192.168.190.0/24 | 외부 인터넷 연결 (out-net) | Vyos eth0 |
| att-net | 10.50.50.0/24 | 공격자 네트워크 | Vyos eth2, Att-Mint |
| rf-net | 10.0.0.0/24 | 라우터 ↔ 방화벽 연결 | Vyos eth1, pfSense WAN |
| dmz-net | 10.0.10.0/24 | DMZ (웹서버) | pfSense OPT1, Bee-box |
| mng-net | 10.0.50.0/24 | 관리 네트워크 | pfSense LAN, Mng-Mint |
| inner-net | 10.0.100.0/24 | 내부 네트워크 (SIEM) | pfSense OPT2, Ubuntu |

## 2. 네트워크 장비

### Vyos 라우터 — 외부와 내부를 연결하는 관문

**역할:** 인터넷(외부)과 내부 네트워크를 연결하고, 서로 다른 네트워크 간 트래픽을 전달(라우팅)

```
인터넷 ←→ [eth0: DHCP] Vyos [eth1: 10.0.0.1] ←→ pfSense
                              [eth2: 10.50.50.1] ←→ Att-Mint (공격자)
```

**주요 설정:**

| 설정 | 값 | 왜 필요한가 |
|------|-----|----------|
| NAT Masquerade | 10.0.0.0/8 → eth0 | 내부 네트워크가 인터넷에 나갈 수 있게 IP를 변환 |
| 정적 라우팅 | 10.0.10.0/24 → 10.0.0.254 | pfSense 뒤에 있는 DMZ로 가는 길을 알려줌 |
| 정적 라우팅 | 10.0.50.0/24 → 10.0.0.254 | pfSense 뒤에 있는 mng-net으로 가는 길을 알려줌 |
| 정적 라우팅 | 10.0.100.0/24 → 10.0.0.254 | pfSense 뒤에 있는 inner-net으로 가는 길을 알려줌 |
| DNS | 8.8.8.8 | 도메인 이름을 IP로 변환 |

**핵심 개념 — NAT (Network Address Translation):**
- 내부 IP(예: 10.0.50.100)는 인터넷에서 사용할 수 없는 사설 IP
- Vyos가 이 사설 IP를 자기 공인 IP(192.168.190.x)로 변환해서 인터넷에 보냄
- 응답이 오면 다시 원래 사설 IP로 바꿔서 돌려줌
- 집에서 쓰는 공유기가 하는 일과 동일

**핵심 개념 — 정적 라우팅:**
- Vyos는 10.0.10.0, 10.0.50.0, 10.0.100.0 네트워크가 직접 연결되어 있지 않음
- 이 네트워크들은 pfSense(10.0.0.254) 뒤에 있으므로, "저쪽으로 가려면 pfSense에게 보내라"고 경로를 지정
- 이 설정이 없으면 Vyos는 해당 네트워크로 가는 길을 모르므로 패킷을 버림

### pfSense 방화벽 — 네트워크 존 사이의 문지기

**역할:** 네트워크 존(mng, dmz, inner) 사이의 트래픽을 검사하고, 허용/차단 결정

```
         Vyos (rf-net)
            │
     ┌──────┴──────┐
     │  pfSense     │
     │  (방화벽)    │
     └──┬──┬──┬────┘
        │  │  │
   mng  │  │  │ inner
   net  │  │  │ net
        │  │
      dmz-net
```

**인터페이스 매핑:**

| pfSense 역할 | IP 주소 | 연결된 네트워크 | 설명 |
|-------------|---------|------------|------|
| WAN | 10.0.0.254/24 | rf-net | 외부(라우터)에서 들어오는 트래픽 |
| LAN | 10.0.50.1/24 | mng-net | 관리자가 접속하는 네트워크 |
| OPT1 (DMZNET) | 10.0.10.1/24 | dmz-net | 웹서버가 있는 DMZ |
| OPT2 (INNERNET) | 10.0.100.1/24 | inner-net | SIEM이 있는 내부 |

**방화벽 룰 현황:**

| 인터페이스 | 룰 | 의미 |
|----------|-----|------|
| WAN | Allow TCP * → 10.0.10.50:80 (NAT) | 외부에서 Bee-box 웹서버 접속 허용 |
| WAN | Deny all TCP | 나머지 외부 트래픽 차단 |
| MNGNET | Anti-lockout 기본룰 | 관리자가 방화벽 자체에 접속 가능 |
| DMZNET | Deny all TCP | DMZ에서 나가는 트래픽 차단 |
| INNERNET | Deny all TCP | 내부에서 나가는 트래픽 차단 |

**핵심 개념 — 방화벽 룰:**
- 방화벽은 기본적으로 **모든 트래픽을 차단**하고, 명시적으로 허용한 것만 통과시킴
- WAN 룰: 외부에서 Bee-box 웹서버(포트 80)로의 접속만 허용
- MNGNET에는 anti-lockout 룰이 있어서 관리자가 항상 pfSense에 접속 가능

**핵심 개념 — NAT 포트포워딩:**
- 외부에서 10.0.10.50(Bee-box)으로 직접 접근할 수 없음 (사설 IP)
- pfSense가 WAN(10.0.0.254)으로 들어오는 80번 포트 트래픽을 Bee-box(10.0.10.50:80)로 전달
- 외부 공격자(Att-Mint) → Vyos → pfSense WAN → NAT → Bee-box

**Snort IPS:**
- pfSense 위에 설치된 **침입 탐지/방지 시스템**
- WAN 인터페이스에서 동작하여 외부에서 들어오는 모든 트래픽을 검사
- GPLv2 + ET Open 룰셋 적용 (알려진 공격 패턴 탐지)
- 탐지된 공격 로그를 Splunk로 전송할 예정

## 3. 네트워크 존별 설명

### att-net — 공격자 네트워크 (10.50.50.0/24)

**왜 별도 네트워크인가:**
- 실제 환경에서 공격자는 인터넷(외부)에 있음
- 이 랩에서는 att-net이 "외부 인터넷" 역할을 대신함
- 공격자는 Vyos 라우터를 통해서만 내부에 접근 가능 (실제 환경과 동일)

**Att-Mint (미설치):**
- IP: 10.50.50.17/24, GW: 10.50.50.1 (Vyos eth2)
- Vyos → pfSense → Bee-box 경로로 웹 공격 수행 예정

### dmz-net — DMZ 네트워크 (10.0.10.0/24)

**DMZ(Demilitarized Zone)란:**
- 외부에 서비스를 제공하지만, 내부 네트워크와는 격리된 구간
- 웹서버, 메일서버 등 외부 접근이 필요한 서버를 배치
- 만약 웹서버가 해킹당해도, 내부 네트워크(inner-net)까지는 침투 불가

**Bee-box (bWAPP 취약 웹서버):**

| 항목 | 값 |
|------|-----|
| OS | Ubuntu 32비트 |
| IP | 10.0.10.50/24 (GW: 10.0.10.1) |
| 계정 | bee / bug |
| 용도 | 의도적으로 취약한 웹 애플리케이션 (모의해킹 연습용) |

- bWAPP = "buggy Web APPlication"
- SQL Injection, XSS, Command Injection 등 다양한 취약점이 일부러 포함됨
- 공격자(Att-Mint)가 이 서버를 대상으로 공격을 수행하면, Snort가 탐지하고 Splunk가 로그를 수집

### mng-net — 관리 네트워크 (10.0.50.0/24)

**왜 관리 네트워크를 분리하는가:**
- 보안 장비(방화벽, SIEM)를 관리하는 접속은 일반 트래픽과 분리해야 함
- 만약 DMZ의 웹서버가 해킹당해도, 관리 네트워크는 별도이므로 방화벽 설정을 변조할 수 없음
- 실제 기업에서도 보안관제 센터(SOC)는 별도 네트워크에 위치

**Mng-Mint (관리 클라이언트):**

| 항목 | 값 |
|------|-----|
| OS | Linux Mint |
| IP | 10.0.50.100/24 (GW: 10.0.50.1) |
| 계정 | kim / (설정한 비밀번호) |

**이 VM에서 할 수 있는 것들:**
1. pfSense 웹콘솔 접속: `http://10.0.50.1` (방화벽 관리)
2. Ubuntu SSH 접속: `ssh user@10.0.100.50` (Splunk 서버 관리)
3. Splunk 웹 접속: `http://10.0.100.50:8000` (로그 분석)

### inner-net — 내부 네트워크 (10.0.100.0/24)

**왜 SIEM을 내부에 두는가:**
- SIEM은 보안 로그를 수집/분석하는 핵심 시스템
- 외부에서 절대 직접 접근할 수 없어야 함 (해킹당하면 로그 조작 가능)
- 관리자만 mng-net을 통해 pfSense를 경유하여 접속 가능

**Ubuntu + Splunk (SIEM 서버):**

| 항목 | 값 |
|------|-----|
| OS | Ubuntu Server 20.04 LTS |
| IP | 10.0.100.50/24 (GW: 10.0.100.1) |
| hostname | splunk |
| Splunk 버전 | 8.2.0 |
| Splunk 계정 | kisia01 / qwer12#$ |
| Splunk 웹 | http://10.0.100.50:8000 |
| SSH 계정 | user / (설정한 비밀번호) |

## 4. 데이터 흐름 — 공격 시나리오

```
1. 공격자 (Att-Mint, 10.50.50.17)
   │
   │ att-net → Vyos eth2
   ▼
2. Vyos 라우터
   │ 정적 라우팅: 10.0.10.0/24 → 10.0.0.254 (pfSense)
   │ eth1 → rf-net
   ▼
3. pfSense WAN (10.0.0.254)
   │ ★ Snort IPS가 여기서 트래픽 검사 → 공격 탐지!
   │ NAT 포트포워딩: :80 → 10.0.10.50:80
   ▼
4. Bee-box (10.0.10.50)
   │ 취약 웹서버에 공격 도달
   │
   ▼
5. pfSense/Snort → 로그 전송 (syslog) → Splunk (10.0.100.50)
   │
   ▼
6. 관리자 (Mng-Mint, 10.0.50.100)
   │ Splunk 웹(http://10.0.100.50:8000)에서 공격 로그 분석
   │ pfSense 웹(http://10.0.50.1)에서 방화벽 룰 조정
```

## 5. 접속 경로 정리

### 물리 PC(Windows)에서 접속 가능한 것

| 대상 | URL/IP | 방법 |
|------|--------|------|
| ESXi 웹 콘솔 | http://192.168.190.128 | 브라우저 |
| Vyos 콘솔 | ESXi 웹 → VM 콘솔 | ESXi 경유 |
| pfSense 콘솔 | ESXi 웹 → VM 콘솔 | ESXi 경유 |

### Mng-Mint에서 접속 가능한 것

| 대상 | URL/IP | 방법 |
|------|--------|------|
| pfSense 웹콘솔 | http://10.0.50.1 | 브라우저 (HTTP, 포트 80) |
| Ubuntu SSH | ssh user@10.0.100.50 | 터미널 (pfSense가 라우팅) |
| Splunk 웹 | http://10.0.100.50:8000 | 브라우저 (pfSense가 라우팅) |
| Bee-box | 10.0.10.50 | pfSense가 라우팅 |

### 직접 접속 불가능한 것

| 시도 | 이유 |
|------|------|
| Windows → pfSense 웹 | Windows는 mng-net에 없음 (다른 네트워크) |
| Windows → Splunk 웹 | Windows는 inner-net에 없음 |
| Windows → MobaXterm SSH(10.0.100.50) | inner-net 전환 후 직접 접근 불가 |
| 외부 → Splunk 직접 접속 | inner-net은 외부와 완전 격리 |

## 6. 핵심 개념 요약

### SIEM (Security Information and Event Management)

- **보안 정보 및 이벤트 관리** 시스템
- 여러 보안 장비(방화벽, IPS, 서버 등)에서 로그를 수집
- 한 곳에서 통합 분석하여 보안 위협을 탐지
- 이 랩에서는 Splunk가 SIEM 역할

### IPS (Intrusion Prevention System)

- **침입 방지 시스템**
- 네트워크 트래픽을 실시간으로 검사하여 알려진 공격 패턴을 탐지
- 탐지 시 차단(Prevention)까지 수행 가능
- 이 랩에서는 pfSense 위의 Snort가 IPS 역할
- WAN 인터페이스에 설치하여 외부에서 들어오는 모든 트래픽을 감시

### DMZ (Demilitarized Zone)

- 외부와 내부 사이의 **완충 지대**
- 외부에 서비스를 제공해야 하는 서버(웹서버)를 배치
- 외부에서 DMZ까지는 접근 가능하지만, DMZ에서 내부(inner-net)로는 접근 불가
- DMZ의 서버가 해킹당해도 내부 네트워크는 안전

### 네트워크 존 분리

- 목적이 다른 시스템을 서로 다른 네트워크에 배치
- 방화벽이 존 사이의 트래픽을 제어
- 하나의 존이 침해당해도 다른 존으로의 확산을 방지
- **최소 권한 원칙**: 필요한 통신만 허용, 나머지는 모두 차단
