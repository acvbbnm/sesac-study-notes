# 01. 보안관제 & SOC

---

## 1. 보안관제란

**보안관제 (保安官制, MSS: Managed Security Service)**

외부로부터의 침해시도를 예방하고 내부 정보자산을 보호하기 위해 자체 정보보호 조직 또는 전문 정보보안 업체를 통해 효율적이고 효과적인 정보보안 업무를 수행하는 것.

**목적**  
이기종 보안장비에서 탐지되는 보안 이벤트를 수집하고, 사이버 침해 공격에 대해 **탐지 / 차단 / 대응**하여 사이버 침해를 사전에 예방하고 보안을 강화.

## 2. 배경지식: 보안관제의 역사적 필요성

### 2.1 주요 사이버 침해사고 연표

보안관제는 단순한 기술적 필요가 아니라, 실제 대규모 사이버 침해사고를 겪으면서 국가적 차원에서 그 중요성이 인식되어 발전해 왔다.

| 시기 | 사건명 | 내용 | 영향 및 교훈 |
|------|--------|------|-------------|
| **2003.01.25** | **1.25 인터넷 대란** | SQL Slammer 웜이 MS-SQL 취약점을 악용하여 전 세계적으로 확산. 한국은 DNS 서버 마비로 약 9시간 동안 전국적 인터넷 마비 | 국가 차원의 사이버 위기대응 체계 필요성 대두. 국가사이버안전센터(NCSC) 설립 계기 |
| **2009.07.07** | **7.7 DDoS 공격** | 청와대, 국방부, 주요 금융기관, 포털 사이트 등 35개 주요 웹사이트에 대규모 DDoS 공격. 좀비 PC 약 11만 5천대 동원 | 「정보통신기반보호법」 강화, DDoS 대응체계 구축, 민간 보안관제 활성화 |
| **2011.03** | **3.4 DDoS 공격** | 7.7 DDoS와 유사한 형태의 재공격. 국내 주요 40개 웹사이트 대상 | 하드디스크 파괴 기능 추가로 더욱 악성화. APT(지능형 지속위협) 개념 대두 |
| **2011.04** | **농협 전산망 마비** | 내부 서버 약 270대 파괴, 금융 거래 장기간 중단 | 내부자 위협 및 공급망 공격의 심각성 인식. 금융권 보안관제 의무화 촉진 |
| **2013.03.20** | **3.20 사이버테러** | KBS, MBC, YTN 방송사 및 신한은행, 농협 등 금융기관의 전산망 동시 마비. PC 약 4만 8천대 및 서버 파괴 | 역대 최대 규모의 사이버 공격. 국가 사이버안보 컨트롤타워 강화. 사이버안전센터 확대 운영 |
| **2013.06.25** | **6.25 사이버 공격** | 청와대 홈페이지 변조, 정부기관 DDoS 공격, 방송사 서버 파괴 | 복합적 공격(DDoS + 웹 변조 + 데이터 파괴) 대응 필요성 |
| **2014** | **한국수력원자력 해킹** | 원전 도면 등 내부 기밀문서 유출, 협박 | 국가 핵심 기반시설 보안관제 강화. 산업제어시스템(ICS/SCADA) 보안 중요성 부각 |
| **2016** | **인터파크 개인정보 유출** | 약 1,030만 건의 고객 개인정보 유출 | 개인정보보호법 강화, 기업 보안관제의 개인정보 보호 영역 확대 |
| **2017** | **워너크라이 랜섬웨어** | 전 세계적 랜섬웨어 대유행. 국내 일부 기업 피해 발생 | 랜섬웨어 대응 역량 강화, 엔드포인트 보안관제 중요성 증대 |
| **2021~현재** | **공급망 공격 증가** | SolarWinds, Log4Shell 등 글로벌 공급망 공격 영향 | 위협 인텔리전스 기반 사전 탐지 역량, 제로트러스트 아키텍처 도입 가속 |

### 2.2 보안관제의 발전 단계

```
[1세대] 단순 모니터링        → 방화벽 로그 수동 확인, 단순 이벤트 알림
         (2000년대 초반)

[2세대] 통합 로그 관리       → ESM(Enterprise Security Management) 도입
         (2000년대 중반)        이기종 장비 로그 통합 수집·분석

[3세대] SIEM 기반 관제       → SIEM(Security Information and Event Management)
         (2010년대)             상관분석, 위협 인텔리전스 연동, 실시간 분석

[4세대] AI/자동화 기반 관제  → SOAR(Security Orchestration, Automation and Response)
         (2020년대~)            머신러닝 기반 이상 탐지, 자동 대응, XDR
```

## 3. 보안관제 종류

| 분류 | 장점 | 단점 |
|------|------|------|
| **자체관제** | 사전 정보 입수 및 특수 환경 파악 용이. 추후 확장·구성 변경 지원 | 보안관제만의 전문성 부족. 인력 이동·업무 공백으로 신규 채용 필요 |
| **파견관제** | 의사소통 원활. 침해·장애 시 즉각 조치. 파견 인력 통한 사이트 특화 정책 수립 | 인력 관리 필요(휴무·교체). 단가 높음. 파견 인력 등급에 따른 서비스 편차 |
| **파견+원격** | 파견·원격 장점 융합. 침해 시 파견 인력 선조치 → 원격 팀 공조 | 서비스 품질 편차. 파견 인력 관리 어려움 |
| **원격관제** | 저비용. 별도 회선 없이 인터넷망 활용. 인력 관리 부담 없음 | 즉각 조치 어려움(통보는 즉시, 조치 인력 수급 필요) |

## 4. 보안관제 핵심 원칙

「국가사이버안전관리규정」에 따른 보안관제의 3대 원칙:

### 4.1 무중단의 원칙

- 사이버 공격은 시간과 장소를 가리지 않으므로 보안관제 업무는 **24시간 365일** 중단 없이 수행해야 한다
- 교대근무(주간/야간/비번/휴무) 편성을 통해 관제 공백이 발생하지 않도록 운영
- 일반적인 교대 편성 예시:

| 조 | 근무시간 | 비고 |
|----|----------|------|
| A조 | 09:00~18:00 (주간) | |
| B조 | 18:00~09:00 (야간) | |
| C조 | 비번 | 전일 야간근무 후 휴식 |
| D조 | 휴무 | |

### 4.2 전문성의 원칙

- 보안관제 업무는 **전문 지식과 경험을 갖춘 인력**이 수행해야 한다
- 관제 인력의 지속적인 교육, 훈련, 자격 취득을 지원해야 한다
- 관련 자격증: 정보보안기사, CISSP, CEH, CISA, 정보처리기사 등
- 최신 보안 동향, 공격 기법, 취약점 정보에 대한 지속적 학습 필요

### 4.3 정보공유의 원칙

- 보안관제 과정에서 획득한 **위협정보, 침해지표(IoC), 공격 기법** 등을 유관기관과 공유해야 한다
- 위협정보 공유를 통해 동일 유형의 공격에 대한 사전 차단 가능
- 주요 정보공유 채널:

| 채널 | 설명 |
|------|------|
| C-TAS | KISA 사이버위협정보 분석·공유 시스템 |
| STIX/TAXII | 국제 표준 위협정보 공유 프로토콜 |
| 사이버위협 합동대응팀 | 민·관·군 합동 대응 체계 |
| ISAC (정보공유분석센터) | 금융, 통신, 에너지 등 분야별 정보공유 |

## 5. 보안관제 구성요소 (3P)

```
           Process
          (관제 방법론)
         /            \
        /              \
   People ---------- System
 (숙련된 인력)      (모니터링 툴/인프라)
```

- **Process**: 조직 규모·목표에 따른 절차, 위기대응 매뉴얼, 유관부서 역할 정의
- **People**: 역할별 기능 수행 인력 (관제 요원, 분석가, CERT 등)
- **System**: 보안관제 모니터링 솔루션, 침해사고대응관리시스템, 다양한 분석 시스템

## 6. 보안관제 수행 업무

**24시간 365일 보안관제**
- 보안 이벤트 모니터링
- 사이버 침해 대응/분석
- 홈페이지 위·변조 탐지 및 서비스 장애 관제
- 보안장비 운영/관리, 보안정책 적용/관리
- 시스템 헬스 체크

**사전 침해 예방 서비스**
- 인프라 취약점 진단
- 모의해킹
- 최신 보안 동향 제공
- 소스코드 진단
- 보안 실태 점검
- 보안 수준 진단
- 모의훈련 (악성메일 등)

**기타 정보보안 업무 지원**
- 각종 인증 사전 준비 지원
- 지침/매뉴얼 개정 지원
- 정보보안 법적 대응 지원
- 보안 교육 수행

## 7. 관제 업무 사이클 상세

### 7.1 일일 업무 사이클

| 시점 | 업무 내용 |
|------|----------|
| **근무 교대 시** | 인수인계 (전 근무조 특이사항, 진행 중인 이슈, 장비 상태 확인) |
| **상시** | 보안 이벤트 실시간 모니터링 (SIEM 대시보드 감시) |
| **상시** | 탐지된 이벤트의 정/오탐 분석 및 분류 |
| **발생 시** | 침해사고 탐지 → 초동 대응 → 에스컬레이션 → 보고 |
| **오전** | 일일 보안관제 보고서 작성 (전일 이벤트 요약, 주요 탐지 내역) |
| **수시** | 신규 취약점·위협정보 확인 및 탐지 룰 반영 |
| **수시** | 보안장비 정상 가동 여부 점검 (헬스 체크) |
| **근무 종료 시** | 인수인계 문서 작성, 미처리 이벤트 현황 정리 |

### 7.2 주간 업무 사이클

| 업무 | 내용 |
|------|------|
| **주간 보고서 작성** | 주간 탐지 이벤트 통계, 주요 침해시도 분석, 대응 결과 요약 |
| **탐지 정책 검토** | 오탐률 분석, 탐지 룰 최적화, 신규 시그니처 적용 |
| **위협 동향 공유** | 주간 보안 동향 브리핑, 신규 CVE 공유, 관련 IoC 배포 |
| **장비 점검** | 보안장비 성능·용량 점검, 로그 저장 상태 확인 |
| **교육/훈련** | 관제 인력 역량 강화 교육 (최신 공격 기법, 분석 도구 활용 등) |

### 7.3 월간 업무 사이클

| 업무 | 내용 |
|------|------|
| **월간 보고서 작성** | 월간 보안관제 현황, 이벤트 추이 분석, 개선 사항 도출 |
| **보안정책 재검토** | 관제 정책·절차 유효성 검토, 환경 변화 반영 |
| **취약점 점검** | 정기 인프라 취약점 스캔, 결과 분석 및 조치 권고 |
| **모의훈련** | 침해사고 대응 모의훈련 (시나리오 기반) |
| **SLA 점검** | 서비스 수준 달성도 점검 (탐지율, 대응시간, 가용성 등) |
| **인력 관리** | 교대 근무 편성, 휴가 조정, 역량 평가 |

## 9. SOC (Security Operation Center)

중앙 집중화된 환경에서 사람·프로세스·기술을 활용하여 조직의 사이버위협을 식별·예방·탐지·대응·복구·관리하며 사이버보안의 최전방에서 자산 및 정보를 보호하는 조직.

| 명칭 | 기관 |
|------|------|
| 국가사이버안전센터 | 국가정보원 |
| 사이버안전센터 | 중앙부처 |
| 사이버침해대응센터 | 지방자치단체 |
| 통합보안관제센터 | 기업 |
| Security Operation Center | 해외 |

### 9.1 SOC 구성요소

**전문조직 (People)**
- SOC 매니저 / 위협헌터 / 진단·모의해킹 / 침해대응·분석 / 보안관제 / 보안시스템 운영

**기술 (Technology)**
- 네트워크 / 엔드포인트 / 모니터링 / 포렌식

**프로세스 (Process)**
- 위협헌팅 / 사고처리 / 위협정보공유

---

### 9.2 SOC 인력 구성 상세 (Tier 구조)

SOC는 일반적으로 3단계(Tier) 분석가 체계로 인력을 구성하며, 이벤트의 심각도와 복잡도에 따라 단계적으로 에스컬레이션한다.

```
 [이벤트 발생]
      │
      ▼
 ┌─────────────┐    정/오탐 판별,     ┌─────────────┐    심층 분석 필요    ┌─────────────┐
 │   Tier 1    │ ──────────────────→ │   Tier 2    │ ──────────────────→ │   Tier 3    │
 │ (Alert 분석) │    에스컬레이션      │ (심층 분석)  │    에스컬레이션      │(고급 분석/헌팅)│
 └─────────────┘                     └─────────────┘                     └─────────────┘
      │                                    │                                    │
      ▼                                    ▼                                    ▼
  초동 대응·차단                       원인 분석·대응                    위협 헌팅·포렌식
```

#### Tier 1 분석가 (Alert Analyst / 초급 관제요원)

| 항목 | 내용 |
|------|------|
| **역할** | 1차 이벤트 모니터링 및 분류 |
| **주요 업무** | SIEM 대시보드 실시간 감시, 경보(Alert) 확인 및 정/오탐 판별, 기초 분석 후 티켓 생성, 정해진 절차(Playbook)에 따른 초동 대응 |
| **에스컬레이션 기준** | 오탐이 아닌 실제 위협으로 판단되거나, 단순 Playbook으로 대응 불가한 경우 Tier 2로 에스컬레이션 |
| **필요 역량** | 네트워크/시스템 기초 지식, 보안장비(IDS/IPS/FW) 로그 해석, SIEM 운용 능력 |
| **근무 형태** | 24/7 교대근무 (관제의 핵심 인력) |

#### Tier 2 분석가 (Incident Responder / 중급 분석가)

| 항목 | 내용 |
|------|------|
| **역할** | 에스컬레이션된 이벤트의 심층 분석 및 침해사고 대응 |
| **주요 업무** | 악성코드 분석(정적/동적 분석), 네트워크 패킷 분석, 침해 범위 및 영향도 파악, 상세 대응 방안 수립 및 실행, 침해사고 보고서 작성 |
| **에스컬레이션 기준** | APT 등 고도화된 공격으로 판단되거나, 디지털 포렌식이 필요한 경우 Tier 3로 에스컬레이션 |
| **필요 역량** | 악성코드 분석 도구(IDA, Ghidra 등), 패킷 분석(Wireshark), 침해사고 대응 절차 숙지, MITRE ATT&CK 프레임워크 활용 |

#### Tier 3 분석가 (Threat Hunter / Expert / 고급 분석가)

| 항목 | 내용 |
|------|------|
| **역할** | 능동적 위협 헌팅, 고급 포렌식 분석, 탐지 역량 고도화 |
| **주요 업무** | 위협 인텔리전스 기반의 사전 위협 헌팅, 디지털 포렌식 수행, 신규 탐지 룰·시그니처 개발, 보안 아키텍처 개선 자문, MITRE ATT&CK 매핑 및 탐지 커버리지 분석 |
| **필요 역량** | 리버스 엔지니어링, 디지털 포렌식, 위협 인텔리전스 분석, 프로그래밍/스크립팅(Python 등), 침투테스트 경험 |

#### 기타 SOC 핵심 역할

| 역할 | 설명 |
|------|------|
| **SOC Manager** | SOC 전체 운영 관리, 인력·예산·SLA 관리, 경영진 보고 |
| **CISO** | 조직 전체 정보보안 전략 수립 및 총괄 (SOC 상위 의사결정자) |
| **보안 엔지니어** | 보안장비 구축·운영·유지보수, 정책 튜닝, 시스템 가용성 관리 |
| **컴플라이언스 담당** | 법규·규정 준수 여부 점검, 감사 대응, 인증 관리 |

### 9.3 SOC 성숙도 모델

조직의 SOC가 얼마나 체계적이고 효과적으로 운영되고 있는지를 평가하는 모델. 일반적으로 5단계로 구분하며, 각 단계에서의 역량과 특성은 다음과 같다.

| 레벨 | 명칭 | 특성 | 주요 역량 |
|------|------|------|----------|
| **Level 1** | **초기 (Initial)** | 비정형적, 개인 역량에 의존 | 기본적인 로그 수집, 방화벽·IDS 알림 수동 확인, 정형화된 절차 없음, 사후 대응 중심 |
| **Level 2** | **관리 (Managed)** | 기본 프로세스 정립 | SIEM 도입 및 기본 상관분석, 표준 운영절차(SOP) 수립, 교대근무 체계 확립, 기본 인시던트 대응 절차 운용 |
| **Level 3** | **정의 (Defined)** | 표준화된 프로세스, 조직적 운영 | Playbook 기반 체계적 대응, Tier 1/2/3 역할 분담 명확, 정기적 보고 체계, 위협 인텔리전스 기초 활용, KPI 측정 시작 |
| **Level 4** | **정량적 관리 (Quantitatively Managed)** | 측정 가능, 데이터 기반 의사결정 | SOAR 도입으로 반복 업무 자동화, 위협 헌팅 프로그램 운영, MITRE ATT&CK 기반 탐지 커버리지 측정, 고도화된 위협 인텔리전스 연동, SLA·KPI 정량 관리 |
| **Level 5** | **최적화 (Optimizing)** | 지속적 개선, 선제적 방어 | AI/ML 기반 이상 탐지, 완전 자동화된 대응 워크플로우, 레드팀·퍼플팀 상시 운영, 제로트러스트 아키텍처 통합, 조직 전체 보안 문화 내재화, 예측적 보안관제 |

```
성숙도 향상 방향:

Level 1         Level 2         Level 3         Level 4         Level 5
[초기]  ──→   [관리]  ──→    [정의]  ──→   [정량관리] ──→  [최적화]

수동/반응적 ─────────────────────────────────────────→ 자동화/선제적
개인 의존   ─────────────────────────────────────────→ 조직적·체계적
사후 대응   ─────────────────────────────────────────→ 예측·예방
```

---

### 9.4 업무 사이클 (NIST CSF 기반) 상세

```
식별(Identify) → 예방(Protect) → 탐지(Detect) → 대응(Respond) → 복구(Recovery)
```

#### (1) 식별 (Identify) - "무엇을 보호해야 하는가?"

조직이 보유한 자산, 비즈니스 환경, 거버넌스, 리스크를 파악하는 단계.

| 활동 | 구체적 내용 |
|------|-----------|
| **자산 관리 (Asset Management)** | IT 자산 목록 작성 (서버, 네트워크 장비, 단말 등), 자산 중요도 등급 분류, 자산 변경 이력 관리 |
| **비즈니스 환경 파악** | 조직의 미션·목표와 연계된 정보자산 식별, 핵심 업무 프로세스의 의존 관계 매핑 |
| **거버넌스** | 정보보안 정책·지침·절차 수립, 법적·규제 요구사항 파악 (개인정보보호법, ISMS-P 등) |
| **위험 평가 (Risk Assessment)** | 자산별 위협·취약점 식별, 위험도 산정 (영향도 x 발생 가능성), 수용 가능한 위험 수준 결정 |
| **공급망 위험 관리** | 외주 업체, 클라우드 서비스 등 공급망 보안 위험 평가 |

#### (2) 예방 (Protect) - "어떻게 보호할 것인가?"

식별된 자산과 리스크에 기반하여 적절한 보호 조치를 적용하는 단계.

| 활동 | 구체적 내용 |
|------|-----------|
| **접근 통제** | 최소 권한 원칙 적용, 다중 인증(MFA) 구현, 네트워크 세그멘테이션, 방화벽 정책 수립 |
| **보안 인식 교육** | 전 직원 대상 정기 보안 교육, 악성메일 모의훈련, 보안사고 신고 절차 교육 |
| **데이터 보안** | 데이터 암호화(저장·전송), 데이터 분류 체계 수립, DLP(Data Loss Prevention) 적용 |
| **정보보호 프로세스** | 변경 관리 절차, 패치 관리 프로세스, 백업 정책 수립 및 이행 |
| **보호 기술 구현** | IPS, WAF, EDR, NAC 등 보안 솔루션 배치, 보안 설정 하드닝(Hardening) |
| **유지보수** | 보안장비 정기 점검, 소프트웨어 업데이트, 취약점 패치 적용 |

#### (3) 탐지 (Detect) - "위협을 어떻게 발견할 것인가?"

보안 이벤트를 적시에 탐지하는 단계. 보안관제의 핵심 영역.

| 활동 | 구체적 내용 |
|------|-----------|
| **이상 징후 탐지** | SIEM 상관분석 룰 운영, 행위 기반 이상 탐지(UEBA), 베이스라인 대비 이상 패턴 식별 |
| **지속적 모니터링** | 24/7 보안 이벤트 실시간 모니터링, 네트워크 트래픽 분석(NTA), 엔드포인트 행위 모니터링(EDR) |
| **탐지 프로세스** | 탐지 룰 개발·튜닝·검증 사이클, 오탐률 관리, 탐지 커버리지 평가 (MITRE ATT&CK 매핑) |
| **위협 인텔리전스 연동** | IoC(침해지표) 기반 탐지, TTP(전술·기법·절차) 기반 행위 탐지, C-TAS 등 위협정보 피드 연동 |

#### (4) 대응 (Respond) - "침해 발생 시 어떻게 조치할 것인가?"

탐지된 보안사고에 대해 영향을 최소화하기 위한 조치를 수행하는 단계.

| 활동 | 구체적 내용 |
|------|-----------|
| **대응 계획** | 침해사고 대응 계획(IR Plan) 수립, 역할·책임 정의, 의사결정 권한 명확화 |
| **분석** | 사고 범위·영향도 파악, 공격 벡터·TTP 분석, 타임라인 재구성, 증거 확보(포렌식) |
| **완화 (Mitigation)** | 악성 IP/URL 차단, 감염 시스템 네트워크 격리, 계정 비활성화, 임시 보안 정책 적용 |
| **보고 (Reporting)** | 경영진 보고, 유관기관 신고 (KISA, 수사기관 등), 침해사고 보고서 작성 |
| **개선** | 사후 분석(Post-Incident Review), 교훈 도출, 대응 절차 개선, 재발 방지 대책 수립 |

#### (5) 복구 (Recovery) - "어떻게 정상으로 되돌릴 것인가?"

침해사고 이후 정상 운영 상태로 복원하는 단계.

| 활동 | 구체적 내용 |
|------|-----------|
| **복구 계획 실행** | 사전 수립된 BCP(Business Continuity Plan) / DRP(Disaster Recovery Plan)에 따른 복구 수행 |
| **시스템 복원** | 백업 데이터로부터 시스템 복원, 클린 이미지 재설치, 복구 후 무결성 검증 |
| **서비스 정상화** | 단계적 서비스 복구, 복구 후 모니터링 강화, 이해관계자 커뮤니케이션 |
| **개선 사항 반영** | 사고 원인 분석 결과를 보안 정책에 반영, 탐지 룰 보강, 아키텍처 개선, 교훈 공유 |

## 10. 실무 용어 정리

### 10.1 조직 관련 용어

| 용어 | 풀네임 | 설명 |
|------|--------|------|
| **SOC** | Security Operation Center | 보안관제센터. 사이버 위협을 실시간 모니터링·탐지·대응하는 중앙 조직 |
| **CERT** | Computer Emergency Response Team | 컴퓨터 비상 대응팀. 침해사고 발생 시 기술적 대응을 수행하는 전문 조직 |
| **CSIRT** | Computer Security Incident Response Team | 컴퓨터 보안 사고 대응팀. CERT와 유사하나 보다 광범위한 보안사고 대응 범위를 가짐 |
| **ISAC** | Information Sharing and Analysis Center | 정보공유분석센터. 특정 산업 분야의 사이버 위협정보를 수집·분석·공유하는 조직 (금융ISAC, 통신ISAC 등) |
| **PSIRT** | Product Security Incident Response Team | 제품 보안 사고 대응팀. 자사 제품의 보안 취약점 대응 전담 조직 |

### 10.2 직책/역할 관련 용어

| 용어 | 풀네임 | 설명 |
|------|--------|------|
| **CISO** | Chief Information Security Officer | 최고정보보안책임자. 조직의 정보보안 전략 수립 및 총괄 책임자 |
| **CPO** | Chief Privacy Officer | 개인정보보호책임자. 조직의 개인정보 관리 및 보호 총괄 |
| **보안관제사** | - | Tier 1~3 분석가를 통칭. 실시간 모니터링·분석·대응 수행 인력 |
| **위협 헌터 (Threat Hunter)** | - | 기존 탐지 체계를 우회하는 잠재적 위협을 능동적으로 탐색하는 전문가 |

### 10.3 기술/프레임워크 관련 용어

| 용어 | 풀네임 | 설명 |
|------|--------|------|
| **SIEM** | Security Information and Event Management | 보안정보·이벤트관리. 이기종 장비의 로그를 통합 수집·상관분석하여 위협을 탐지하는 시스템 |
| **SOAR** | Security Orchestration, Automation and Response | 보안 오케스트레이션·자동화·대응. 반복적인 보안 업무를 자동화하고 대응 절차를 통합 관리 |
| **EDR** | Endpoint Detection and Response | 엔드포인트 탐지·대응. 단말(PC, 서버)에서의 위협을 탐지하고 대응하는 솔루션 |
| **XDR** | Extended Detection and Response | 확장된 탐지·대응. 네트워크·엔드포인트·클라우드 등 다중 영역의 위협을 통합 탐지·대응 |
| **NDR** | Network Detection and Response | 네트워크 탐지·대응. 네트워크 트래픽을 분석하여 위협을 탐지하는 솔루션 |
| **TI** | Threat Intelligence | 위협 인텔리전스. 사이버 위협에 대한 증거 기반의 정보 (IoC, TTP 등을 포함) |
| **IoC** | Indicator of Compromise | 침해지표. 침해사고의 흔적을 식별하는 기술적 지표 (악성 IP, 해시값, 도메인 등) |
| **TTP** | Tactics, Techniques, and Procedures | 전술·기법·절차. 공격자의 행위 패턴을 체계적으로 분류한 것 (MITRE ATT&CK 기반) |
| **MITRE ATT&CK** | - | 실제 사이버 공격 사례를 기반으로 공격자의 전술·기법을 체계적으로 분류한 지식 베이스 |
| **CTI** | Cyber Threat Intelligence | 사이버 위협 인텔리전스. 위협 행위자, 동기, 공격 기법 등에 대한 분석 정보 |
| **UEBA** | User and Entity Behavior Analytics | 사용자·엔티티 행위 분석. 정상 행위 패턴을 학습하여 이상 행위를 탐지하는 기술 |

### 10.4 규정/인증 관련 용어

| 용어 | 설명 |
|------|------|
| **ISMS-P** | 정보보호 및 개인정보보호 관리체계 인증. KISA에서 운영하는 국내 인증 제도 |
| **NIST CSF** | 미국 국립표준기술연구소의 사이버보안 프레임워크. 식별-보호-탐지-대응-복구 5단계 |
| **ISO 27001** | 국제 정보보안 경영시스템(ISMS) 인증 표준 |
| **PCIDSS** | Payment Card Industry Data Security Standard. 카드 결제 산업 보안 표준 |
| **국가사이버안전관리규정** | 대통령훈령. 국가 사이버안전 관리에 관한 기본 사항을 규정 |

### 10.5 공격/방어 관련 용어

| 용어 | 설명 |
|------|------|
| **APT (Advanced Persistent Threat)** | 지능형 지속위협. 특정 대상에 대해 장기간에 걸쳐 다양한 공격 기법을 조합하여 수행하는 고도화된 공격 |
| **DDoS (Distributed Denial of Service)** | 분산 서비스 거부 공격. 다수의 시스템을 동원하여 대상 시스템의 서비스를 마비시키는 공격 |
| **제로데이 (Zero-Day)** | 패치가 존재하지 않는 신규 취약점 또는 이를 이용한 공격 |
| **C&C (Command and Control)** | 공격자가 감염된 시스템(좀비 PC)을 원격으로 제어하기 위한 서버 |
| **Kill Chain** | 사이버 공격의 단계를 체계적으로 분류한 모델 (정찰 → 무기화 → 전달 → 익스플로잇 → 설치 → C&C → 목표 달성) |
| **레드팀 / 블루팀 / 퍼플팀** | 레드팀: 공격 시뮬레이션, 블루팀: 방어·탐지, 퍼플팀: 양 팀의 협업을 통한 보안 역량 강화 |
