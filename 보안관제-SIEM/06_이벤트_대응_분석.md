# 06. 이벤트 대응 및 분석

---

## 1. 이벤트 대응 처리 프로세스

```
① 보안장비 로그 수집
   └─ 각 보안장비를 SIEM과 연동하여 로그 수집

② 이벤트 탐지
   └─ SIEM 연관성 분석 룰 또는 보안장비 사용자 정의 룰 조건 충족 시
      경보 발생 + 관제 인원에게 메일 발송

③ 이벤트 1차 분석
   └─ 수신 이벤트 메일 확인 → 장비 접근 → 상세 데이터 분석
      정탐 / 오탐 여부 판단
      공격에 대한 유효성 테스트

④ 공격자 IP 차단 + 이벤트 탐지 보고서 작성
   └─ 정탐 판정 시 방화벽에서 공격자 IP 차단
      보고서 내용: 공격자IP / 대상IP / Port / 이벤트명 / 상세데이터 /
                   공격 설명 / 조치방안 / 조치결과

⑤ 담당자 통보
   └─ 작성된 보고서를 메일 발송 (일부 고객사: 메일 + SMS 동시 발송)
      Critical 공격의 경우 유선으로 담당자에게 전달

⑥ 침해사고 조치 지원 (CERT)
   └─ 탐지된 이벤트로 침해사고 발생 시 피해 서버 2차 분석
      자체 서버 분석 or CERT 팀 지원
```

## 2. OSI 계층별 공격 유형

| 계층 | 공격 유형 |
|------|----------|
| 7~5 (App) | 바이러스/웜/트로이목마, OS/Application 취약점 공격, HTTP GET/POST Flooding, FTP PASV DoS |
| 4 (Transport) | TCP/UDP Flooding, DNS Reply Flooding, 포트 스캐닝 |
| 3 (Network) | IP Spoofing, ICMP/IGMP/Ping Flooding, Ping of Death |
| 2 (Data Link) | ARP Spoofing, MAC Spoofing, ARP Cache Poisoning |
| 1 (Physical) | 케이블 단절 |

## 3. 주요 공격 상세 분석

### SQL Injection

**개념**  
웹 파라미터에 강제로 SQL 질의문을 삽입하여 내부 DB 서버의 데이터를 유출·변조하거나 관리자 인증을 우회하는 공격.

**원리**
- SQL 질의문이 DB에 전달되어 조건이 TRUE가 되면 데이터 반환
- 에러 메시지를 통해 2차 공격 시도 가능

**공격 영향**
- 인증 절차 우회 가능
- DB에 저장된 데이터 열람/삭제/수정 가능
- 시스템 명령어 조작으로 운영 시스템에 영향

---

### Webshell 공격

**개념**  
웹(Web) + 쉘(Shell)의 합성어. 웹서버(PHP/ASP/JSP)의 취약점을 이용해 웹쉘을 업로드한 후 웹브라우저로 서버 명령을 실행하는 공격.

**대표 공격 형태**
- 확장자 우회 공격
- 자바스크립트 우회 공격
- MIME Type 우회
- 그림 파일을 이용한 한 줄 웹쉘

**공격 영향**
- 관리자 권한 탈취 및 내부망 접근 → 내부 자료 및 개인정보 유출
- 웜/바이러스 배포 서버로 악용

**대응 방안**
- 허용된 확장자 외 업로드 금지 (Whitelist 방식)
- Directory Listing 취약점 제거 (소스코드·구조 노출 방지)

---

### Command / Code Injection

**개념**  
시스템 명령어를 호출하는 어플리케이션의 인자값을 조작하여 의도하지 않은 OS 명령어를 실행시키는 공격. 대표 사례: **Bash ShellShock**

**공격 영향**  
유효성이 있을 경우 웹 어플리케이션을 구동하는 시스템 계정의 Shell 권한(관리자 권한) 획득.

**대응 방안**
- 지정된 변수 입력값 외의 값이 들어올 경우 차단
- 운영체제 시스템 명령어가 사용자 입력에 의해 존재하는지 확인
- 파이프라인(`|`), `open()` 명령 등으로 미확인 사용자 입력 전달 금지

---

### XSS (Cross Site Scripting)

**개념**  
JavaScript·VBScript 등 Client Side Script로 작성된 악성 스크립트를 웹페이지/게시판/메일에 삽입하여 사용자가 열람 시 실행되는 공격.

**실행 순서**
```
① 게시물에 악성 스크립트 등록
② 사용자·관리자가 스크립트 게시물 열람
③ 사용자 쿠키를 공격자 서버로 전송 (쿠키 탈취)
④ 공격자가 탈취된 쿠키로 로그인
⑤ 해당 권한으로 2·3차 공격 시도
```

**공격 영향**
- 악성 스크립트 삽입 게시판 접근 사용자에게 웜/바이러스 배포
- 세션 정보 탈취 → 재사용 (관리자 계정 탈취 가능)

**대응 방안**
- 쿠키에 인증/권한 등 중요 정보 기록 금지 → 세션 인증 방식으로 전환
- 특수문자 적절한 필터링: `<`, `>`, `&` 등
- 사용자가 게시판에 사용할 수 있는 HTML 포맷만 허용 (White List)

## 4. GET / POST 이벤트 분석

| 방식 | 특징 | 분석 방법 |
|------|------|----------|
| **GET** | 파라미터가 URL에 Query String 형식으로 전달 (`?` 뒤에 노출) | URL에서 직접 확인 가능 |
| **POST** | HTTP Body 안에 값을 숨겨서 전달 (GET보다 상대적으로 안전) | WAF: Body 직접 확인. IPS: RawData 잘릴 경우 확인 불가 |

**POST 분석 주의사항**
- 확인하려는 파라미터가 서버·DB에 영향을 줄 수 있는 값이라면 테스트보다 담당자 통보 우선 (SQL Injection 등)
- 업로드나 영향을 줄 이벤트가 아니고 유효 데이터가 아닌 경우 → 프록시 서버로 Method 변경 후 테스트

## 5. 보안장비 RawData 활용 방법

### Sniper IPS/IDS
1. 탐지 정책 설정에서 RawData 여부 체크 확인
2. 탐지 이벤트 검색 → 원하는 항목 우클릭 → 'RawData' 클릭
3. RawData 팝업 내용 복사 → Decode 툴/사이트에서 Decoding
4. 디코딩된 상세 데이터로 정탐/오탐 판단

### TMS IDS
- '뷰어' 탭 → 탐지 이벤트 더블클릭 → '상세정보', '패킷분석' 탭 확인 → Decoding
- `@`가 붙은 사용자 정의 패턴은 `C:\Program Files\Tess\Manager\Config\Manager\UserRule.pol` 파일에서 탐지 문자열 확인 가능

### WAF (Wapples, Web Insight, SecureSphere 등)
- 대부분 탐지 이벤트 상세보기에서 별도 Decoding 없이 탐지 데이터 확인 가능

## 6. 정탐 / 오탐 확인 방법

### SIEM (F/W 로그 기반)
- 연관성 분석 데이터 토대로 분석
- 주요 사용 케이스: '특정 포트 Brute Force', 'IP/Port Scanning', '동일 출발지 IP N건 이상 탐지'

### RawData (IPS/WAF)
- 정규식·행위기반·임계치 기반 패턴 외 대부분은 HTTP Header 값의 **특정 문자열 기반** 탐지
- Encoding된 RawData를 Decoding 후 실제 악성 문자열 포함 여부 확인
