# 00. 웹 서비스 구조 (Web Server · WAS · DB)

> 웹 취약점을 이해하려면 요청이 **어느 계층에서 처리되는지** 알아야 한다. (교안 보충)

---

## ⭐ 1. 3-Tier 아키텍처 — **시험 출제 예상**

웹 서비스는 보통 역할이 다른 3개 계층으로 나뉜다.

```
[클라이언트]        [1계층]           [2계층]            [3계층]
 브라우저   ──→   Web Server   ──→   WAS         ──→   DB Server
 (사용자)         (정적 처리)        (동적 처리)         (데이터 저장)
             Apache/Nginx/IIS   Tomcat/JEUS/JBoss    MySQL/Oracle
```

| 계층 | 구성요소 | 역할 |
|------|---------|------|
| **1계층 Web Server** | Apache, Nginx, IIS | **정적 콘텐츠**(HTML·CSS·JS·이미지) 처리, 요청 중계(리버스 프록시) |
| **2계층 WAS** | Tomcat, JEUS, WebLogic, JBoss | **동적 콘텐츠**(JSP·Servlet·비즈니스 로직) 처리 |
| **3계층 DB Server** | MySQL, Oracle, PostgreSQL, MS-SQL | 데이터 저장·조회 |

> 소규모는 Web+WAS를 한 서버에 두기도 하지만, 보안·성능상 **계층 분리**가 원칙.

💬 **강사 보충 — 시험 포인트**
> - **3-Tier 구조** 각 계층 이름 + 역할 + 대표 제품을 세트로 암기
> - "Apache는 WAS다" → **오답** (Apache는 Web Server, WAS는 Tomcat)
> - "Tomcat은 웹 서버다" → **오답** (Tomcat은 WAS, 정확히는 서블릿 컨테이너)
> - Apache + Tomcat 조합이 가장 흔한 구성 — Apache가 앞에서 받고 Tomcat이 뒤에서 처리

## ⭐ 2. Web Server vs WAS — **시험 출제 예상**

| 구분 | Web Server | WAS (Web Application Server) |
|------|-----------|------------------------------|
| **처리 대상** | **정적** 페이지 (HTML, CSS, JS, 이미지) | **동적** 페이지 (JSP, Servlet, PHP 로직) |
| **역할** | 요청 수신 · 정적 응답 · WAS로 전달 | 프로그램 실행 · DB 연동 · 결과 생성 |
| **대표 제품** | **Apache**, Nginx, IIS | **Tomcat**, JEUS, WebLogic, JBoss |
| **컨테이너** | 없음 | **서블릿 컨테이너** (JSP/Servlet 실행 엔진) 포함 |
| **DB 직접 연결** | ❌ 하지 않음 | ✅ 직접 연결 (JDBC 등) |
| **네트워크 위치** | DMZ (외부 노출) | 내부망 (외부 직접 접근 차단) |

### Web Server만으로 안 되는 이유

```
[정적 요청] http://site.com/index.html
→ Web Server가 파일 그대로 반환 → 끝 (WAS 불필요)

[동적 요청] http://site.com/login.jsp?id=hong&pw=1234
→ Web Server: "이건 .jsp, 나는 못 처리해"
→ WAS로 전달: 로그인 로직 실행 → DB 조회 → 결과 HTML 생성
→ Web Server를 통해 사용자에게 응답
```

### 왜 두 계층으로 나누는가

| 목적 | 설명 |
|------|------|
| **성능** | Web Server가 정적 파일을 먼저 처리해 WAS 부하 감소 |
| **보안** | WAS·DB를 내부망에 두고 Web Server만 DMZ에 노출 → 공격 표면 축소 |
| **부하 분산** | Web Server 1대가 WAS 여러 대로 로드밸런싱 가능 |
| **역할 분리** | 역할에 맞는 최적화 (Nginx는 정적 처리에 최적, Tomcat은 Java 실행에 최적) |

💬 **강사 보충 — 시험 포인트**
> **자주 나오는 혼동 정리:**
>
> | 헷갈리는 표현 | 정답 |
> |---|---|
> | Apache는 어느 계층? | Web Server (1계층) |
> | Tomcat은 어느 계층? | WAS (2계층) |
> | JSP 처리는 어디서? | WAS (서블릿 컨테이너) |
> | HTML 처리는 어디서? | Web Server |
> | DB에 연결하는 계층? | WAS |
> | 외부에 노출하는 계층? | Web Server (DMZ) |
>
> "서블릿 컨테이너 = WAS의 핵심 구성요소" — Tomcat 자체가 서블릿 컨테이너이면서 경량 WAS

## 3. 요청 처리 흐름

```
① 사용자가 URL 요청 (http://site.com/board.jsp?id=1)
       │
② Web Server 수신
   - 정적 파일(.html/.jpg)이면 → 바로 응답 (③~⑤ 생략)
   - 동적 파일(.jsp/.do)이면  → WAS로 전달
       │
③ WAS가 프로그램 실행 (board.jsp)
   - 비즈니스 로직 수행
   - DB 조회가 필요하면 → DB Server로 SQL 전송
       │
④ DB Server가 SQL 실행 후 결과 반환
       │
⑤ WAS가 결과로 HTML 생성 → Web Server → 사용자 브라우저 출력
```

> **보안 관점**: 사용자 입력(`id=1`)이 ③에서 로직에 쓰이고 ④에서 SQL이 되므로, 검증 없이 흘러가면 **SQL 인젝션**이 ④ 계층(DB)까지 도달한다. 각 계층에서 입력값을 검증해야 한다.

## 4. 계층별 보안 위협 & 진단 항목 매핑

| 계층 | 대표 위협 | 웹 취약점 항목 |
|------|----------|---------------|
| **Web Server** | 디렉터리 인덱싱, 불필요 Method(PUT/DELETE), 헤더 정보 노출, 에러 페이지 | WEB-04·16·18, 취약한 보안설정 |
| **WAS** | 관리 콘솔 노출(Tomcat Manager), 기본 계정, 소스 노출, 파일 업로드 | WEB-01·02·13, 악성 파일 업로드 |
| **애플리케이션(로직)** | SQL 인젝션, XSS, 불충분한 인가/인증, 파일 다운로드 | 코드/SQL 인젝션, XSS, 인가 |
| **DB Server** | 평문 저장, 과다 권한, 외부 노출(3306/1521) | 데이터 평문 전송, DB 접근통제 |

## ⭐ 5. 계층 분리 & 네트워크 구성 (보안) — **시험 출제 예상**

```
[인터넷]
    │
[방화벽 / WAF]
    │
┌─[DMZ]─────────────────────────────────┐
│  Web Server (Apache/Nginx)             │  ← 외부 노출 허용
│  포트 80(HTTP), 443(HTTPS)만 개방      │
└────────────────────────────────────────┘
    │ (내부 방화벽)
┌─[내부망]───────────────────────────────┐
│  WAS (Tomcat/JEUS)                     │  ← 외부 직접 접근 차단
│  Web Server → WAS 포트(8009/8080)만 허용│
└────────────────────────────────────────┘
    │
┌─[DB 전용망]────────────────────────────┐
│  DB Server (MySQL/Oracle)              │  ← WAS에서만 접근 허용
│  3306(MySQL)/1521(Oracle) 외부 차단    │
└────────────────────────────────────────┘
```

**핵심 원칙**

| 원칙 | 설명 |
|------|------|
| **Web Server만 DMZ에** | WAS·DB는 내부망 격리, 외부 직접 접근 불가 |
| **DB는 WAS만 접근** | 3306/1521 포트를 외부·불특정에 열지 않음 |
| **최소 포트·최소 권한** | 계층 간 통신은 필요한 포트만 개방 |
| **전용 계정으로 구동** | apache/tomcat/mysql 계정 사용, root 구동 금지 |

💬 **강사 보충 — 시험 포인트**
> - **DMZ에 위치하는 계층 = Web Server** (WAS, DB가 DMZ에 있으면 취약한 구성)
> - DB 포트(3306/1521)가 인터넷에 열려있으면 → 즉시 취약 판정
> - "WAS가 외부에서 직접 접근 가능하다" → 취약 (Web Server를 거치지 않으므로)

## 6. 정적 vs 동적 콘텐츠

| 구분 | 정적(Static) | 동적(Dynamic) |
|------|-------------|--------------|
| **예시** | `.html`, `.css`, `.js`, `.jpg` | `.jsp`, `.php`, `.asp`, `.do` |
| **처리 계층** | Web Server | WAS |
| **특징** | 누구에게나 동일한 응답 | 요청·사용자·DB에 따라 결과 변함 |
| **보안 이슈** | 백업파일·소스 노출 주의 | 입력값 검증(인젝션·XSS) 필수 |

> **대부분의 심각한 웹 취약점이 동적 처리 경로에서 발생한다** — 사용자 입력이 WAS에서 코드가 되고, DB에서 SQL이 되는 흐름이 공격의 핵심 경로.
