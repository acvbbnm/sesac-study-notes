# 00. 웹 서비스 구조 (Web Server · WAS · DB)

> 웹 취약점을 이해하려면 요청이 **어느 계층에서 처리되는지** 알아야 한다. (교안 보충)

---

## 1. 3-Tier 아키텍처

웹 서비스는 보통 역할이 다른 3개 계층으로 나뉜다.

```
[클라이언트]        [1계층]           [2계층]            [3계층]
 브라우저   ──→   Web Server   ──→   WAS         ──→   DB Server
 (사용자)         (정적 처리)        (동적 처리)         (데이터 저장)
             Apache/Nginx/IIS   Tomcat/JEUS/JBoss    MySQL/Oracle
```

| 계층 | 구성요소 | 역할 |
|------|---------|------|
| **Web Server** | Apache, Nginx, IIS | **정적 콘텐츠**(HTML·CSS·JS·이미지) 처리, 요청 중계(리버스 프록시) |
| **WAS** | Tomcat, JEUS, WebLogic, JBoss | **동적 콘텐츠**(JSP·Servlet·비즈니스 로직) 처리 |
| **DB Server** | MySQL, Oracle, PostgreSQL, MS-SQL | 데이터 저장·조회 |

> 소규모는 Web+WAS를 한 서버에 두기도 하지만, 보안·성능상 **계층 분리**가 원칙.

---

## 2. Web Server vs WAS

| 구분 | Web Server | WAS (Web Application Server) |
|------|-----------|------------------------------|
| **처리 대상** | 정적 페이지(HTML, 이미지) | 동적 페이지(JSP, Servlet, PHP 로직) |
| **역할** | 요청 수신·정적 응답·WAS로 전달 | 프로그램 실행·DB 연동·결과 생성 |
| **예시** | Apache, Nginx, IIS | Tomcat, JEUS, WebLogic |
| **컨테이너** | - | 서블릿 컨테이너(JSP/Servlet 실행 엔진) 포함 |

**왜 나누는가**
- **성능**: Web Server가 정적 요청을 먼저 처리해 WAS 부하 감소
- **보안**: WAS·DB를 내부망에 두고 Web Server만 외부(DMZ)에 노출 → 공격 표면 축소
- **부하 분산**: Web Server가 여러 WAS로 로드밸런싱

---

## 3. 요청 처리 흐름

```
① 사용자가 URL 요청 (http://site.com/board.jsp?id=1)
       │
② Web Server 수신
   - 정적 파일(.html/.jpg)이면 → 바로 응답 (③~⑤ 생략)
   - 동적 파일(.jsp/.do)이면 → WAS로 전달
       │
③ WAS가 프로그램 실행 (board.jsp)
   - 비즈니스 로직 수행
   - DB 조회가 필요하면 → DB Server로 SQL 전송
       │
④ DB Server가 SQL 실행 후 결과 반환
       │
⑤ WAS가 결과로 HTML 생성 → Web Server → 사용자 브라우저 출력
```

> **보안 관점**: 사용자 입력(`id=1`)이 ③에서 로직에 쓰이고 ④에서 SQL이 되므로, 검증 없이 흘러가면 **SQL 인젝션**이 ④ 계층(DB)까지 도달한다. 각 계층에서 입력값을 검증해야 한다.

## 4. 계층별 보안 위협 & 진단 항목 매핑

| 계층 | 대표 위협 | 웹 취약점 항목 |
|------|----------|---------------|
| **Web Server** | 디렉터리 인덱싱, 불필요 Method(PUT/DELETE), 헤더 정보 노출, 에러 페이지 | WEB-04·16·18, 취약한 보안설정 |
| **WAS** | 관리 콘솔 노출(Tomcat Manager), 기본 계정, 소스 노출, 파일 업로드 | WEB-01·02·13, 악성 파일 업로드 |
| **애플리케이션(로직)** | SQL 인젝션, XSS, 불충분한 인가/인증, 파일 다운로드 | 코드/SQL 인젝션, XSS, 인가 |
| **DB Server** | 평문 저장, 과다 권한, 외부 노출(3306/1521) | 데이터 평문 전송, DB 접근통제 |

## 5. 계층 분리 & 네트워크 구성 (보안)

```
[인터넷]
    │
[방화벽/WAF]
    │
[DMZ]          ← Web Server (외부 노출, 정적 처리)
    │  (내부 방화벽)
[내부망]        ← WAS (동적 처리, 외부 직접 접근 차단)
    │
[DB 전용망]     ← DB Server (WAS만 접근 허용, 외부 완전 차단)
```

**핵심 원칙**
- **Web Server만 외부(DMZ)에 노출**, WAS·DB는 내부망에 격리
- **DB는 WAS에서만 접근** 허용 (3306/1521 포트를 외부·불특정에 열지 않음 → 취약점 진단 U-31, W-DB 관련)
- 계층 간 통신은 **최소 포트·최소 권한**으로 제한
- 각 계층은 **전용 계정**으로 구동 (apache/tomcat/mysql) — root 구동 금지

## 6. 정적 vs 동적 콘텐츠

| 구분 | 정적(Static) | 동적(Dynamic) |
|------|-------------|--------------|
| 예시 | .html, .css, .js, .jpg | .jsp, .php, .asp, .do |
| 처리 | Web Server가 파일 그대로 반환 | WAS가 코드 실행 후 결과 생성 |
| 특징 | 누구에게나 동일 | 요청·사용자·DB에 따라 결과 변함 |
| 보안 | 정보 노출(백업·소스) 주의 | 입력값 검증(인젝션·XSS) 필수 |

> 정적 요청은 Web Server 선에서 끝나 상대적으로 단순하지만, **동적 요청**은 WAS→DB까지 흐르며 사용자 입력이 코드·쿼리가 되므로 **대부분의 심각한 웹 취약점이 동적 처리 경로**에서 발생한다.
