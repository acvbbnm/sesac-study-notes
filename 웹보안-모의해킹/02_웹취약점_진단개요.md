# 02. 웹 취약점 진단 개요

---

## 1. 진단 방식 비교

| 방식 | 장점 | 단점 |
|------|------|------|
| **수동 진단 (전문 인력)** | 전반적 취약성 분석, **비정형 취약점**까지 탐지 | 점검자 기술 수준에 따라 결과 편차 |
| **자동 진단 (스캐닝 도구)** | 시간·인력·비용 절감, 주기적 진단에 유리 | 복잡한 취약점 미탐지, **오탐**으로 신뢰도 저하 |

### 수동 진단 종류
- **웹 응용프로그램 취약점 진단**: 체크리스트 기반 위협요소 진단 + 대응방안 제시
- **모의해킹**: 외부/내부에서 실제 해커처럼 침투 테스트 후 영향도 분석

### 자동 진단 도구

| 구분 | 도구 | 특징 |
|------|------|------|
| **무료** | Nikto | 웹 서버 취약점 스캐너(오래된 SW 탐지) |
| | OpenVAS | 종합 네트워크 취약점 스캐너 |
| | Nmap + NSE | 포트 스캐닝 + NSE 스크립트로 취약점 진단 |
| **유료** | Acunetix | 웹 애플리케이션 전용, XSS/SQLi 탐지 정확 |
| | Nessus | 네트워크/서버 보안 점검, 기업 활용 多 |
| | Qualys | 클라우드 기반, 취약점 진단 + 자산관리 |
| | IBM AppScan | 기업용 웹 진단, 정적 분석 연동 |

## 2. OWASP

## 3. 주요정보통신기반시설 웹 취약점 항목 (21종)

| 항목 | 설명 |
|------|------|
| **코드 인젝션** | LDAP·OS 명령·SSI·XPATH·XML·SSTI 등 외부 입력값이 명령어로 삽입되는지 |
| **SQL 인젝션** | 입력값이 SQL 쿼리에 삽입되어 비인가 DB 접근·조작 가능 여부 |
| 디렉터리 인덱싱 | 서버 디렉터리 목록 노출 여부 |
| 에러 페이지 적용 미흡 | 에러 페이지 내 불필요한 정보 노출 |
| 정보 누출 | 개인정보·주석 디버깅 정보·샘플·백업 파일 노출 |
| **크로스사이트 스크립트(XSS)** | 악성 스크립트가 타 사용자 브라우저에서 실행되는지 |
| **크로스사이트 요청 위조(CSRF)** | 인증 세션 악용한 위조 요청 가능 여부 |
| **서버사이드 요청 위조(SSRF)** | 내부 서버 자원 접근·악의적 요청·정보 유출 |
| 약한 비밀번호 정책 | 복잡성 요구사항 준수 여부 |
| 불충분한 인증 절차 | 중요 페이지 추가 인증·인증 우회 여부 |
| 불충분한 권한 검증 | 타 사용자 권한 탈취로 민감 데이터 접근 |
| 취약한 비밀번호 복구 절차 | 임시 비밀번호 유추 가능 여부 |
| 프로세스 검증 누락 | 입력·실행 단계 흐름 검증 적절성 |
| **악성 파일 업로드** | 악성 파일 업로드·실행 가능 여부 |
| **파일 다운로드** | 허용 경로 외 파일 접근·다운로드 |
| 불충분한 세션 관리 | 세션 만료·예측 가능한 세션 ID·고정 세션 |
| 데이터 평문 전송 | 통신 데이터 암호화 여부 |
| 쿠키 변조 | 쿠키 변조로 타 사용자 권한 탈취 |
| 관리자 페이지 노출 | 유추 가능 URL·설계 오류로 관리자 페이지 접근 |
| 자동화 공격 | 반복 요청(봇) 통제 여부 |
| 불필요한 Method 악용 | PUT·DELETE·TRACE 악용 여부 |

## 4. 보안 진단 프로세스 (기타)

WEB/API 진단은 **8개 그룹 28개 항목** 체크리스트 기반으로 동적/정적 진단 수행.

### 심각도별 조치 기한

| 구분 | Target Date | 정의 |
|------|:-----------:|------|
| **긴급** | 48시간 | 공격 발생/예상되어 즉시 조치 필요 |
| **중요** | 2주 내 | 정보유출·시스템 침입 가능 취약점 |
| **일반** | 4주 내 | 단독 Risk는 없으나 다른 취약점과 연계 시 피해 |

### 진단 절차
```
보안진단 신청 → 진단 수행 → 취약점 조치 → 이행점검 수행 → 보안진단 완료
  (담당자)      (진단자)     (담당자)      (진단자)
```
