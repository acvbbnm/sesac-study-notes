3.1 데이터클래스 (dataclass)

일반 클래스는 __init__·__repr__·__eq__에 같은 필드명을 각각 써야 해 필드를 바꿀 때마다 여러 메서드를 함께 고쳐야 합니다. **@dataclass** 는 필드 선언만 읽어 이 세 메서드를 자동 생성합니다.

from dataclasses import dataclass, field

@dataclass

class LogEntry:

ip: str

status: int \# 필드 선언이 곧 __init__·__repr__·__eq__의 기준

e1 = LogEntry("10.0.0.5", 403)

e2 = LogEntry("10.0.0.5", 403)

print(e1) \# LogEntry(ip='10.0.0.5', status=403)

print(e1 == e2) \# True (값 비교 자동)

주요 옵션

| **옵션** | **효과** | **비고** |
|----|----|----|
| **frozen=True** | 생성 후 필드 재대입 차단 | 재대입 시 FrozenInstanceError. 모든 필드 hashable이면 set 원소·dict 키 가능 |
| **order=True** | __lt__·__le__·__gt__·__ge__ 자동 생성 | **필드 선언 순서 = 정렬 우선순위** |

> **💡 가변 기본값 함정 — default_factory**
> **tags: list = []** 처럼 리스트를 필드 기본값으로 직접 쓰면 정의 시점의 한 객체가 **모든 인스턴스에 공유**됩니다. dataclass는 이를 **ValueError로 미리 차단**합니다. 해결: **tags: list = field(default_factory=list)** — 인스턴스 생성마다 list()를 호출해 각자 독립된 리스트를 만듭니다.

tags: list[str] = field(default_factory=list) \# 인스턴스마다 새 리스트

3.2 프로퍼티 · 메서드

그냥 속성은 e.status = 999처럼 아무 값이나 검증 없이 저장합니다. **property** 는 속성 접근을 getter·setter 메서드로 가로채, 읽고 쓰는 사이에 검증 같은 로직을 끼웁니다.

class Entry:

def __init__(self, status):

self.status = status

@property \# getter — 속성처럼 읽기

def status(self):

return self._status

@status.setter \# setter — 대입 시 검증

def status(self, code):

if not (100 <= code <= 599):

raise ValueError(f"비정상 status: {code}")

self._status = code

> **💡 getter/setter · 계산 속성 · classmethod**
> **@property는 getter, @status.setter는 setter** (같은 이름 쌍). setter를 안 만들면 읽기 전용이 되어 대입 시 AttributeError. _status의 밑줄은 접근 차단이 아니라 '내부용' 관례 표시입니다.
> **계산 속성:** def is_failure(self): return self.status &gt;= 400 처럼 매번 계산하는 파생 속성은 저장 필드가 없습니다. 단 getter 안에서 **자기 자신(self.is_failure)을 다시 읽으면 RecursionError** — 다른 필드로 계산하세요.
> **@classmethod 대체 생성자:** from_line(cls, line)처럼 __init__과 다른 입력으로 객체를 만드는 방법. 첫 인자 **cls는 클래스 자신**이라 cls(...)는 Entry(...) 호출과 같습니다.

3.3 매직 메서드 (dunder)

len(obj)·obj[0]·== 같은 내장 문법은 __len__·__getitem__·__eq__ 같은 **dunder(이중밑줄) 메서드**에 대응합니다. 쓸 문법을 정하고 대응 메서드를 구현하면 파이썬이 실행 시 그 메서드를 대신 호출합니다.

| **그룹** | **내장 문법** | **대응 dunder** |
|----|----|----|
| 컨테이너 | len(obj) · obj[0] · for | __len__ · __getitem__ · __iter__ |
| 연산자 | a+b · a==b · a<b | __add__ · __eq__ · __lt__ |
| 표현 | print(obj) · repr(obj) | __str__ · __repr__ |
| 호출 | obj() | __call__ |

class LogBatch:

def __init__(self, entries): self.entries = entries

def __repr__(self): return f"LogBatch({len(self.entries)}건)"

def __len__(self): return len(self.entries) \# len(b)

def __getitem__(self, i): return self.entries[i] \# b[0], for, sorted

> **💡 __repr__ · __getitem__ 순회 · __lt__/__eq__**
> **__repr__** 를 정의 안 하면 print가 메모리 주소를 출력합니다. 정의하면 상태를 담은 문자열이 나오고, __str__이 없으면 출력 시 __repr__가 대신 쓰입니다.
> **__getitem__만 정의해도 for가 0부터 인덱스를 넣어 순회**하며, **IndexError가 나면 순회를 종료**합니다. sorted도 같은 방식으로 정렬합니다.
> **__lt__는 a&lt;b(정렬 기준), __eq__는 a==b(동등 비교)** 규칙을 정합니다. 두 메서드를 심으면 sorted가 객체를 정렬하고 ==가 객체를 비교합니다.

3.4 예외 처리

커스텀 예외 — 부모 상속으로 자식 전부 포착

class PipelineError(Exception): """공통 부모 예외"""

class ParseError(PipelineError): """형식이 다를 때"""

class FetchError(PipelineError): """못 받아올 때"""

try:

load(line)

except PipelineError as e: \# 부모 하나로 자식 둘 다 포착

print(f"{type(e).__name__}: {e}")

> **💡 공통 부모를 두면 except가 자식 전부를 잡는다**
> PipelineError를 공통 부모로 두고 ParseError·FetchError가 상속하면 **except PipelineError 한 줄로 두 자식 예외를 모두 포착**합니다. 자식 예외가 늘어도 except는 그대로 둡니다.

raise from — 원인 연결

try:

ip, status = line.split()

except ValueError as e:

raise ParseError("잘못된 로그 형식") from e \# 원인 보존

\# except에서 e.__cause__로 원래 ValueError 확인 가능

**from을 생략**하면 원인 예외가 암시적 문맥(__context__)으로만 남지만, **raise ... from e** 로 명시하면 __cause__로 원인을 직접 확인할 수 있습니다.

logging — print 대신

import logging, sys

logging.basicConfig(level=logging.INFO,

format="%(levelname)s:%(name)s:%(message)s", stream=sys.stdout)

log = logging.getLogger("sec") \# 로거 이름 = 출처 표시

log.debug("파싱 시작") \# INFO 미만 → 버려짐

log.warning("파싱 실패") \# INFO 이상 → 기록

> **💡 logging이 print보다 나은 점**
> print는 모든 메시지가 같은 형식이라 중요도 구분·출력 중지·출처 추적이 어렵습니다. logging은 **DEBUG·INFO·WARNING·ERROR 레벨**로 중요도를 표시하고, basicConfig의 **level로 상세도를 한 줄로 조절**하며(기준 미만은 버려짐), **getLogger(이름)**으로 출처를 표시합니다.

3.5 컨텍스트 매니저 (with)

with 블록이 끝나면 정리 작업이 **자동 실행**됩니다. 수동 close는 누락하기 쉽고 예외가 나면 도달하지 못하는데, 컨텍스트 매니저가 자원 획득·해제를 with 하나로 묶어 누수를 막습니다.

with open("log.txt", "r") as f:

data = f.read()

\# 블록을 벗어나면 자동 close (안에서 예외가 나도 닫힘은 보장)

__enter__ · __exit__ 로 직접 구현

import time

class Timer:

def __init__(self, name): self.name = name

def __enter__(self): \# 진입 시 — 자원 획득

self.t0 = time.perf_counter()

return self \# as 변수에 바인딩

def __exit__(self, exc_type, exc, tb): \# 종료 시 — 자원 해제

print(f"[{self.name}] {time.perf_counter()-self.t0:.2f}s")

with Timer("scan"):

print("스캔 중...")

@contextmanager 로 간단히

from contextlib import contextmanager

@contextmanager

def timer(name):

t0 = time.perf_counter() \# yield 앞 = __enter__

try:

yield

finally: \# yield 뒤 = __exit__

print(f"{name}: {time.perf_counter()-t0:.2f}s")

> **💡 __exit__ 반환값 = 예외의 운명 (핵심)**
> 예외가 나도 __exit__는 **항상 실행되어 자원을 정리**합니다. 그 반환값이 예외의 운명을 정합니다:
> **False 또는 None → 예외를 그대로 전파(기본, 바깥 except가 잡음)**, **True → 예외를 삼켜 억제(바깥에서 못 잡음)**. 치명적 오류도 조용히 사라지므로 **의도 없이 return True는 지양**하세요.

3.5 통합실습 — 예외에도 안전한 자원 처리

- __exit__에서 exc_type이 None이면 커밋, 예외면 롤백 후 False 반환(전파)

- @contextmanager로 enter→yield→finally exit 순서 보장

- with 안에서 except ValueError로 깨진 줄을 건너뛰고 errors 집계

- raise LogFormatError(line) from e 로 원인을 __cause__에 보존

- contextlib.suppress로 지정 예외를 억제할 수도 있음

> **💡 정상=커밋 / 예외=롤백, 그래도 정리는 항상**
> with가 정상 종료하면 커밋하고, 예외가 나면 __exit__에서 롤백한 뒤 **False를 반환해 예외를 전파**합니다. 어느 쪽이든 __exit__는 실행되어 **자원 정리는 항상 보장**됩니다. 이것이 'try/finally + 원인 보존(raise from)'을 with 한 흐름으로 묶은 안전한 처리 패턴입니다.
